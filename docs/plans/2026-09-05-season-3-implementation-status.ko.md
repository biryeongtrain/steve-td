# 시즌 3 구현·검증 기록

> 2026-09-06 · 시즌 3·Pet 커밋 분리와 해적 통합 검증 완료. 기존 기준선 27종은 부분 재현, 3종은 승인된 제외 대상이다. 해적의 기준선과 화면 검증 일부, 실제 밸런스 조정은 남아 있다. 운영에는 적용하지 않았다.

## 작업 범위

- 게임: `s3-release`. 웹: `semion-web`의 `codex/s3-release`.
- 시즌 3와 기존 Pet 변경을 별도 커밋으로 나누고 두 작업 브랜치에 푸시한다. 게임 `master`·웹 `main`에는 푸시하지 않는다. 운영 배포는 하지 않는다.
- 일반 증강 35종과 예비 보상 9종을 구현한다. `명예 퇴역`, `과밀 허가`는 제외한다.
- 전용 타워는 공격형 5종과 기존 지원형 4종이다. 증강용 빌더를 만들지 않고 `JOB | AUGMENT` 획득 구분을 사용한다. 해적은 별도의 창작 빌더로 편입한다.
- 라이브 설정, 운영 DB, 서버 재시작 후 경기 복구, 회복 감소 디버프는 범위 밖이다.

일반 후보 공개는 기본값에서 꺼져 있다. 내부 시험용 `augment force`도 마일스톤 희귀도, 후보 적격성, 안전한 선택지, 중복 선택 제한을 지킨다.

## 추가로 확정한 규칙

- 지뢰 위치: 고정 몬스터 경로에서 첫 번째 유효 수평 구간을 찾아 그 반대 방향으로 타워에서 2·4·6블록 떨어진 지점을 사용한다. 길이 0인 구간과 수직 구간은 건너뛴다.
- 저압 유닛: 새 증강 스택·조건·충전을 만들지 않는다. 이미 충전한 연승 탄환과 축전탄은 피해를 주고 소비된다. 유효 체력 피해가 없는 공격의 기존 충전 보존 규칙은 유지한다.
- 자연 승리 종료: 생존자의 미실현 예약도 최종 기록을 만들기 전에 취소한다. 결과를 다시 조회해도 취소를 중복 기록하지 않는다.

## 계측 해석

- `null`은 미측정 또는 구버전 누락이다. 실제 측정한 0·`false`·빈 배열과 구분한다.
- 후보 생성 이력과 실제 서버 화면 표시 이력을 분리한다. 화면 표시 기록만으로 실제 클릭이나 클라이언트 렌더링 성공을 입증하지 않는다.
- `augmentSpecialDamageDealt`는 별도 추가 피해 경로의 실제 적 체력 손실이다. 총 피해에 이미 포함되므로 다시 더하지 않는다.
- 편향 장갑의 피해 증감은 장갑 배율 계산 단계의 차이다. 이후 보호막·다른 배율·초과 피해를 거친 실제 체력 보호량이 아니다.
- `enemyHpDamage`는 적에게 받은 실제 체력 피해다. 적에게 준 피해가 아니다. `masteryEligibleHpDamage`는 그중 저압 유닛을 제외한 숙련 조건 피해다.
- 경제 이벤트는 실제 확정 거래의 증감량이다. 여러 카드가 관여한 한 거래를 카드마다 복제하거나 비용을 임의로 나누지 않는다.
- 전투·전용 타워 표본은 라운드 시작·종료·제거 시점의 상태다. 같은 타워·라운드의 중간 표본을 합산하지 않는다.
- 회복 비율은 유효 회복량 / 자연 웨이브 시작 체력이다. 누수한 적에게 준 회복도 포함하므로 추가 처치 부담과 같지 않다.

### 2026-09-06 커밋 분리와 해적 편입

게임의 시즌 3 구현·기획서·테스트 정리·색상·선택 30초 생산 중단은 `95352534`, Pet의 성체 효과·무리 밸런스·회귀 검사는 `0d8c6504`로 나눴다. Pet의 체력 계산 훅 이름 변경은 시즌 3 커밋에 넣어 공통 체력 API와의 의존 관계를 유지했다. 웹 카탈로그·기록·동기화는 `13c80104`로 커밋했다. 동기화 이미지에 필요한 `lib/augment.mjs` 복사도 포함했다.

해적 병합 대상은 `f87db7e04599499ce97bb376e8b54c11078b314a`로 고정했다. 기존 PR #87 이력을 보존해 게임 `s3-release`에 편입했다. ID는 `semion-td:pirate`, 분류는 `CREATIVE`다. 공식 14종·창작 17종이며, 증강 타워를 제외하는 `JOB` 필터 기준 스타터는 148종이다. 웹은 기존 `builderOrigin`을 사용한다.

- 뱃사공 라운드 수입은 시즌 3 정산 성공 뒤 한 번만 지급한다. 구형 호출도 같은 정산 경로를 사용하며, 중복 호출과 닫힌 증강 경제 상태에는 지급하지 않는다.
- 제독의 승급 소비는 승급권 정산 성공 뒤 실제 결제액만 집계한다. 할인·비용 부족·같은 타워의 티켓 재사용 거절·견적 무효화와 롤백을 검사했다.
- 칼잡이의 영구 체력·공격 성장, 일시 버프, 전시 경제의 중첩과 무쇠 칼잡이 승급 후 상태 유지를 실제 엔티티로 검사했다.
- 영구 성장 API에도 증강 타워의 외부 버프 금지를 적용했다. 기존 증강 타워 9종 검사에 회귀를 추가해 수정 전 실패를 확인했다. 해적 일반 타워의 성장과 PR #87의 직접 판매 순이익 절반 규칙은 유지한다.

웹은 독립 PostgreSQL 18.4에서 테스트 20/20(skip 0), lint·타입 검사·운영 DB에 연결하지 않는 빌드를 통과했다. 동기화 이미지의 파일 배치를 임시 디렉터리에서 재현해 모듈 import를 확인했다. 시험용 PostgreSQL과 임시 파일은 정리했으며 공유 Docker·운영 DB는 변경하지 않았다.

게임은 Java 21로 해적 경제·분류·웹 카탈로그 집중 단위 검사 30건과 해적 성장·승급 GameTest 1건을 통과했다. 최종 `rtk ./gradlew test runGameTest remapJar --console=plain --no-daemon` 결과는 GameTest 530/530, 단위 테스트 1,071건(실패 0·오류 0·skip 2)이다. JAR의 해적·시즌 3 클래스와 `publicPoolEnabled=false`도 확인했다.

첫 전체 실행에서 기존 `illusionCloneAttacksSharedSourceTargetInsteadOfScanningOwnTarget` 검사의 30틱 표적 일치 단언이 실패했다. 해당 검사와 게임 코드는 바꾸지 않았으며, 단독 1/1과 전체 재실행 530/530에서 통과했다. 원인은 이번에 확정하지 않았다. 시험 환경의 기존 코스메틱 키 누락과 외부 스킨 요청 오류도 로그에 남았다. 이번 검사로 최신 클라이언트 렌더링이나 외부 스킨 표시를 검증했다고 보지 않는다.

공개 문서·요약 JSON·합성 시험 PNG를 커밋했다. 실제 경기 입력·원본 결과 아카이브, 클라이언트 로그, 캐시와 빌드 산출물은 로컬에 보존하고 제외했다. 아래 빌더 기준선은 해적 편입 전 기록이며, 해적의 시즌 3 밸런스나 최신 화면을 새로 검증한 결과가 아니다. 운영 배포와 공개 증강 활성화는 하지 않았다.

### 2026-09-06 증강 선택 30초 추가

증강 제안이 있는 라운드는 `선택 30초 → 일반 준비 25초 → 전투` 순서로 진행한다. 추가 30초 동안만 전원의 에메랄드 자동 생산을 중단하며, 선택을 일찍 확정하거나 건너뛰어도 생산 재개 시점은 같다. 재접속해도 시간을 다시 주지 않는다. 선택 마감에는 미확정 제안만 `SKIPPED · TIMEOUT`으로 기록하고, 이후 25초 동안 일반 준비와 생산을 진행한다. 중단한 생산량은 보충하지 않는다.

생산 보너스와 R25 배율도 중단 대상이다. 일반 라운드의 25초 준비, 별도 보상·환불, 배치·구매 규칙은 유지한다. HUD에 생산 중단과 선택 시간, 이후 준비 25초를 표시한다. 기존 다이얼로그·경제 경로를 재사용했으며 새 라운드 단계는 추가하지 않았다.

기존 GameTest에서 R5·R15·R25의 600틱 무생산, 일반 준비 25초 보존, 다음 라운드 생산, 조기 확정·건너뛰기·재접속, 생산 보너스·R25 배율 재개를 확인했다. 전체 게이트를 통과했으며 실제 클라이언트 화면과 경제 기준선은 이번에 다시 측정하지 않았다. 아래 화면과 기준선 자료는 변경 전 규칙의 기록이다. 운영 설정과 공개 후보 풀은 변경하지 않았다.

### 2026-09-06 등급 색상·선택 개수 표시

원본은 25경기, 48명의 기록이며 카탈로그 버전은 20개다. 과거 성능 통계를 합산하지 않는다. 과거 기록에서는 행동 순서만 가져오고 시즌 3 설정으로 다시 측정한다. 원본 맵 식별자와 정확한 행동 틱은 공개 API에 없어 누락으로 표시했다.

수집 도구는 `tools/season3-baseline/fetch_records.py`, 입력은 로컬 보관 자료(커밋 제외)인 `build/season3-baseline/records.json`이다. 입력 SHA-256은 `146bceed70f515390dee289039a106d330ba46e6e7c0750d7286acdb33a65ec1`이다. 수집 도구 회귀 검사 5건을 통과했고, 캐시에서 다시 생성한 결과도 일치했다. 플레이어 이름과 UUID는 입력에 보관하지 않는다.

위 3종의 제외는 사용자가 승인했다. 전체 30종의 목록에서는 제외 사유를 유지한다. 기준선 수집 중에는 빌더, 증강, 웨이브 수치를 바꾸지 않는다. 실제 Dialog 확정 클릭과 전용 타워 화면 확인은 기준선 수집 다음 작업이다.

운영 트랙은 같은 구매 기록을 팀당 두 레인씩, 총 네 레인에 복제한다. 현재 게임의 소환 대상 배정과 보스 전투를 실행하지만 원본 경기의 다른 플레이어는 재현하지 않는다. 과거 경기의 승패 재생이 아니라 같은 행동 순서를 현재 규칙에서 실행하는 시험이다. 네 복제는 독립 플레이어 표본이 아니다.

재현 시 원본 좌표와 현재 지도에서 해석한 바닥 좌표를 함께 기록한다. 타워가 다른 엔티티로 변환되는 빌더는 변환 대상을 추적한다. 실제 엔티티 틱을 처리할 준비가 된 청크에서만 경기를 시작하며, 준비 대기는 전투 시간에 넣지 않는다.

실행 성공과 원본 일치는 별개다. 구매에 성공해도 가격, 환급, 인컴 증가량이 달라지면 최초 차이로 기록한다. 생산 업그레이드의 `incomeGain`은 에메랄드 생산 증가량이고 판매의 같은 필드는 다이아 환급액이다. 원본 생산 업그레이드의 지불 통화는 기록에 없어 미상으로 남긴다.

탈락 시 제거되는 성장 상태는 종료 직전 틱의 스냅샷으로 보존하고 `PRE_TERMINAL_TICK`을 표시한다. 타워·보스 처치와 환경 사망을 구분한다. 실제 피해원이 확인되지 않는 사망이나 사라진 엔티티는 시험 실패로 처리한다.

미래기관 요원의 정상 철수는 사망이 아니다. 철수 후 `survivingDefenseTowers`가 0이 될 수 있으므로 이 값으로 전멸을 판정하지 않는다. 사망 수는 명시적인 타워 사망 기록으로 집계한다.

### 우선 정밀 검토 대상

다음은 수치 변경 순서가 아니라 원인을 더 확인할 순서다.

1. **붉은 여왕: 장기 미해결 전투.** 운영 9개 중 4개가 한 웨이브의 6,000틱, 즉 게임 시간 300초 제한에 걸렸다. 해당 라운드는 R2·R4·R5·R7이다. 생존을 패배로 바꾸어 기록하지 않았으며, 재현 실패 이후의 편성과 실제 교착 원인을 먼저 확인해야 한다.
2. **마도사·벌레: 편성 재현 제한.** R16 전투의 평균 실제 투자액은 각각 220·235다이아로 공통 예산 1,740보다 작았다. 마도사의 첫 전투 재현 차이에는 `mage_prophecy_zombie_villager`의 `UNKNOWN_UPGRADE`, 벌레에는 6슬롯 제한이 있다. 낮은 전투 결과만 보고 상향하지 말고 현재 승급 경로·성장 조건·원본 편성 차이를 확인한다.
3. **식물·람쥐썬더: R16 완막 차이.** 두 빌더 모두 18개 레인 관측 중 12개를 완막했다. 공식 빌더별 완막률의 중앙값은 0%다. 평균 투자액은 각각 1,220·1,603.33다이아이고 일부 관측은 90초 시점에도 미해결이었다. 같은 투자·구매 성공 범위에서 지원 기여와 성장량을 비교한 다음 수치 변경을 판단한다.
4. **혹한: 초기 고정 편성 결과의 일반화 금지.** 앞선 고정 편성 시험과 달리 이번 기록 기반 R16 전투는 18개 중 완막 0개, 평균 투자액 1,155다이아였다. 운영 H0도 R16에 도달하지 못했다. 이번 표본에서 완전 가동 자동 발동은 0회였으므로 해당 능력의 성능은 미측정이다. 과거 한 편성의 결과로 일괄 하향하지 않는다.

이번 수집 중 수정한 것은 시험 환경과 계측이다. 숙적 훈련용 개체의 보상 없는 사망, 미래기관의 정상 철수, 실제 청크 준비, 혹한의 시험용 연결 초기화·동시 패킷 전송을 처리했다. 혹한 시험은 출력 패킷을 폐기하므로 전투·기존 사용 콜백의 검증이며, 실제 네트워크 전달이나 화면 검증이 아니다.

빌더·증강·웨이브의 수치와 기존 Pet 변경은 바꾸지 않았다. 운영 배포·DB 변경·공개 후보 활성화도 하지 않았다. 다음 작업은 실제 Dialog 확정과 전용 타워 화면 확인이며, 빌더 수치 조정은 이 기준선의 재현 차이를 검토한 뒤 한 종씩 진행한다.

측정 결과 묶음 `docs/plans/evidence/season3-builder-baseline-results.tar.gz`는 로컬 보관 자료(커밋 제외)다. `summary.json`, 웨이브 해시 동등성 증거, 최종 채택한 트랙별 로그 54개와 전체 게이트 로그를 보관한다. 실패·중단된 시험 로그는 로컬 `build/season3-baseline`에 따로 남겼으며 최종 측정 집계에 섞지 않았다.

## 재현 명령

게임 기본 게이트:

```sh
rtk ./gradlew test runGameTest remapJar --console=plain --no-daemon
```

30개 논리 참가자·180개 실제 타워의 독립 레인 부하 시험:

```sh
JAVA_TOOL_OPTIONS='-Dsemiontd.loadAcceptance=true -Dfabric-api.gametest.filter=semion-td-gametest:season_three_load_game_test_staged_waves' rtk ./gradlew runGameTest --console=plain --no-daemon
```

이 시험은 같은 R16에서 기본 → 회복만 → 회복·수량 증가를 순차 측정한다. 무증강·공격형·방어형 편성의 결과와 서버 틱 시간을 JSON으로 남긴다. 네트워크 클라이언트 30명, 경제 운영, 전체 경기·팀 최종 방어, 장기 성장 스택을 검증하는 시험은 아니다. 일반 게이트에서는 명시적인 옵트인 없이는 실행하지 않는다.

동일 예산 빌더 비교와 경제형 재투자 시험도 각각 단독 실행한다.

```sh
JAVA_TOOL_OPTIONS='-Dsemiontd.builderBalanceAcceptance=true -Dfabric-api.gametest.filter=semion-td-gametest:season_three_builder_balance_game_test_equal_budget_boards' rtk ./gradlew runGameTest --console=plain --no-daemon
JAVA_TOOL_OPTIONS='-Dsemiontd.economyBalance=true -Dfabric-api.gametest.filter=semion-td-gametest:season_three_economy_balance_game_test_cash_reinvestment_against_tactical_designation' rtk ./gradlew runGameTest --console=plain --no-daemon
```

아래 전체 빌더 기준선 명령은 로컬 보관 자료(커밋 제외)인 고정 입력 묶음을 가진 시험자용이다. 공개 저장소만 내려받아서는 당시 입력을 복원할 수 없다. 입력을 복원한 뒤 빌더별로 실행한다. 다음 예시는 주민 빌더다. `semiontd.baseline.builder`만 바꾸면 같은 조건으로 다른 빌더를 시험한다. 게임 서버는 한 번에 하나만 실행한다.

```sh
mkdir -p build/season3-baseline
tar -xzf docs/plans/evidence/season3-baseline-inputs.tar.gz -C build/season3-baseline
baseline_records_path="$PWD/build/season3-baseline/records.json"
JAVA_TOOL_OPTIONS="-Dsemiontd.builderBalanceAcceptance=true -Dfabric-api.gametest.filter=semion-td-gametest:season_three_builder_balance_game_test_equal_budget_boards -Dsemiontd.baseline.records=$baseline_records_path -Dsemiontd.baseline.builder=semion-td:villager_towers" rtk ./gradlew runGameTest --console=plain --no-daemon
JAVA_TOOL_OPTIONS="-Dsemiontd.baseline.operation=true -Dfabric-api.gametest.filter=semion-td-gametest:season_three_recorded_operation_game_test_recorded_operations -Dsemiontd.baseline.records=$baseline_records_path -Dsemiontd.baseline.builder=semion-td:villager_towers" rtk ./gradlew runGameTest --console=plain --no-daemon
python3 -B -m unittest discover -s tools/season3-baseline -p 'test_*.py'
```

프로젝트 루트에서 실행한다. `semiontd.baseline.records`에는 게임 시험 프로세스가 읽을 수 있는 절대 경로를 지정한다. 각 실행의 표준 출력을 별도 로그로 보관하고 다음 명령으로 집계한다. 같은 시나리오의 재실행 로그는 하나만 고른다.

```sh
python3 -B tools/season3-baseline/summarize_results.py build/season3-baseline/records.json COMBAT_LOG OPERATION_LOG --wave-hash-evidence build/season3-baseline/wave-config-order-evidence.json --output build/season3-baseline/summary.json
```

보관된 결과를 재집계하려면 로컬 보관 자료(커밋 제외)인 측정 결과 묶음도 `build/season3-baseline`에 푼다. 그 안의 54개 트랙 로그를 위 명령의 입력으로 지정한다. `regression-final.log`는 측정 로그가 아니다.

운영 트랙의 기본값은 무증강이다. 선택 속성 `semiontd.baseline.operation.group=ATTACK|DEFENSE|INCOME`은 R5 골드 한 장의 별도 시험용이다. R5·R15·R25의 증강 세 장 조합을 평가한 결과가 아니다.

공개 후보 풀 활성화, 수량 +40%·+50%, 운영 배포는 별도 판단이다. 내부 시험이 통과해도 라이브 밸런스가 입증된 것으로 취급하지 않는다.
