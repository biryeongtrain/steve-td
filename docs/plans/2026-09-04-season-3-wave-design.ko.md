# 세미온 TD 시즌 3 웨이브 명세

> 기준일: 2026-09-06 · 기준 브랜치: `s3-release` · 상태: 승인된 구현 기준. 기본 설정에 회복·수량 단계를 켜되, 증강 시스템과 공개 후보 풀이 모두 활성화된 `NORMAL` 경기에만 적용한다. 운영 설정과 공개 후보 풀은 이번 작업에서 바꾸지 않는다.

이 문서는 시즌 3의 웨이브 수량, 자연 웨이브 회복 유닛, 처치 보상과 검증 순서를 정의한다. 웨이브와 관련해서는 이 문서가 [시즌 3 출시 기획안](./2026-09-01-season-3-release-design.ko.md)의 관련 내용을 대체한다. 증강 자체의 규칙은 [시즌 3 증강 시스템 명세](./2026-09-03-season-3-augment-design.ko.md)를 따른다.

처음 작업하는 개발자는 1절의 적용 조건, 4절의 수량표와 5절의 회복 규칙을 확인한다. 7절은 코드·설정 경계, 8절은 검증 기준이다. 실제 검증 결과는 [시즌 3 구현 현황](./2026-09-05-season-3-implementation-status.ko.md)에서 구분해 기록한다.

이 문서에서 쓰는 말은 다음과 같다.

- `회복만 시험`: 기존 총수를 유지하고 지정한 일반 전투 유닛을 회복 유닛으로 교체하는 내부 비교 시험이다. 이전 문서의 공개 기술 카나리와 구분한다.
- `무한 웨이브 템플릿`: R20 이상에서 라운드마다 하나씩 뽑는 기본 편성 묶음이다.
- `보상 예산`: 플레이어 레인 한 곳에서 한 라운드의 자연 웨이브를 모두 처치했을 때 지급 가능한 기본 다이아 합계다. 직업 보정 등 기존 보정을 적용하기 전 값이다.
- `소환 출처`: 자연 웨이브, 유료·무료 인컴, 메아리와 빌더 프록시를 구분하는 식별값이다.
- `일반 전투 유닛`: 자연 웨이브의 회복 유닛과 보스를 제외한 공격 유닛이다.
- `회복 비율`: 회복 유닛의 실제 유효 회복량을 같은 표본의 웨이브 시작 최대 체력으로 나눈 값이다. 이 문서에서는 `h`로 쓴다. 방어력으로 환산한 EHP나 플레이어가 처치에 추가로 사용한 피해량을 뜻하지 않는다.
- `완막`: 개인 레인에 웨이브가 배정됐고 `cleared=true`, `leaked=false`, `laneDefenseBroken=false`이며 소속 팀이 다음 준비 단계에도 생존한 결과다. 분모는 해당 라운드 웨이브를 실제로 받은 참가자 수다.

## 1. 결정 사항

| 항목 | H0 결정 |
|---|---|
| 적용 조건 | `NORMAL`이며 샌드박스·튜토리얼이 아니고, 증강 시스템과 공개 후보 풀이 모두 활성화된 경기 |
| 웨이브 수량 | R5 이후 +10%, +20%, +30%로 나눈다. |
| R1~R4 | 변경하지 않는다. 첫 증강을 얻기 전 구간이다. |
| R15 | Warden 보스 4기를 유지한다. 일반 전투 유닛 배율을 적용하지 않는다. |
| R25 이상 | 30% 증량을 적용한다. 40%, 50%는 이번 범위에서 제외한다. |
| 회복 유닛 | R16 1기, R17 2기, R18 3기, R19 4기, R20 이후 5기. 일반 전투 유닛을 같은 수만큼 대체한다. |
| 회복량 | 개체당 대상 3기·성공 2회. 대상당 R16~19는 80, R20 이후는 160에 기존 라운드 체력 배율을 적용한다. |
| 회복 비율 | 실제 유효 회복량을 측정한다. 기존 6~10% 목표와 12% 이상 자동 롤백 규칙은 적용하지 않는다. |
| 처치 보상 | 유닛 수가 늘어도 라운드의 자연 웨이브 기본 처치 보상 총액은 늘리지 않는다. |
| 증강 상향 | 이번 작업에서 바꾸지 않는다. 시험 결과와 조정안을 보고한 뒤 사용자의 결정을 받는다. |

기본 `wave.json`과 Java 기본값은 수량·고정 회복 단계를 켜고 후반 템플릿 3종을 회복 대상으로 지정한다. 서버는 경기 시작 시 적용 조건을 검사한다. 조건을 충족하지 않으면 기존 수량과 회복 유닛이 없는 편성을 사용한다. 카드를 건너뛴 플레이어에게도 해당 경기의 같은 웨이브를 배정한다.

기존 서버의 설정 파일은 덮어쓰지 않는다. 적용용 설정안과 차이는 로컬에 보관하며, 운영 배포·설정 재적용과 공개 후보 풀 활성화는 별도 승인을 받는다.

회복을 포함한 체력 총량 증가율은 `시험 웨이브 시작 최대 체력 / 대조 웨이브 시작 최대 체력 × (1 + h) - 1`로 계산한다. 이는 체력 총량 비교다. 누수한 유닛의 회복도 포함하므로 난도 증가율이나 방어력 환산 EHP로 해석하지 않는다.

## 2. 왜 50%부터 시작하지 않는가

### 2.1 증강의 전투력은 선택에 따라 다르다

시즌 3 후보에는 전역 피해 증가 외에도 다음 카드가 섞여 있다.

- 인컴을 바꾸는 카드
- 받는 피해와 생존을 바꾸는 카드
- 타워 한 기만 강화하는 카드
- 배치나 전투 시간 조건을 만족해야 발동하는 카드
- 타워나 슬롯을 영구적으로 포기하는 카드

피해 증강을 연달아 고른 일부 플레이어의 보드는 50%보다 강해질 수 있다. 인컴이나 방어 카드를 고른 플레이어의 보드는 직접 피해가 거의 늘지 않을 수도 있다. 시즌 3 `NORMAL`은 기존 주특성·부특성도 비활성화하므로, 증강 세 장을 기존 특성 위에 더한 값으로 계산하면 안 된다.

### 2.2 수량과 화력은 같은 비율로 맞춰도 결과가 같지 않다

웨이브 수량 배율을 `m`, 플레이어의 실제 화력 배율을 `p`라고 두면 단일 대상 위주의 보드에서 전투 시간은 대략 `m / p`배가 된다.

예를 들어 실제 화력이 20% 늘었는데 수량을 50% 늘리면 전투 시간은 약 `1.50 / 1.20 = 1.25`, 즉 25% 길어진다. 회복 유닛이 더해지면 전투 시간은 더 늘어난다.

세미온 TD에는 긴 전투를 추가로 위험하게 만드는 규칙도 있다.

- 모든 현재 웨이브는 한 틱에 한 기씩 출현한다. 수량이 늘면 마지막 유닛의 출현도 늦어진다.
- 몬스터가 60초 동안 살아 있으면 2초마다 체력 5%, 공격력 6%가 증가한다.
- 90초에는 최종 방어가 강제로 시작된다.

따라서 수량 50%와 회복을 한 번에 적용하면 실제 난도는 50%보다 크게 오를 수 있다.

## 3. 비교 기준과 과거 자료

### 3.1 설정과 런타임

2026-09-06 작업 전 확인한 기존 서버 설정 파일과 번들 기본값은 서로 다르다. 파일 확인만으로 실행 중인 서버의 적용 상태를 입증하지 않는다.

- 기존 서버 파일: `/Users/qf/Desktop/semionTD/config/semion-td/wave.json`, SHA-256 `d1c98f…2548`. 시즌 3 활성화 필드가 없다.
- 작업 전 번들 기본값: `src/main/resources/semiontd/balance-defaults/wave.json`, SHA-256 `34e014…d3fe`. 수량·고정 회복 단계가 꺼져 있고 후반 회복 대상 목록이 비어 있다. 이번 구현에서 변경할 대상이다.
- 장기 전투 배율: `/Users/qf/Desktop/semionTD/config/semion-td/monster_scaling.json`

- R1~R19는 고정 웨이브다.
- R20부터는 세 개의 무한 웨이브 템플릿 중 하나를 라운드마다 뽑는다.
- 세 템플릿은 모두 기본 55기다.
- R20 이후 체력은 라운드마다 40%p, 공격력은 3%p씩 증가한다. 비교군은 수량 55기를 유지하며, H0는 4절의 수량 배율을 적용한다.
- 모든 라운드의 `spawnIntervalTicks`는 1이다.

이 문서의 초 단위는 20틱을 1초로 환산한 게임 시간이다. 전투 중 40 TPS를 사용하는 환경에서는 실제 경과 시간이 짧아질 수 있다. 전투 시간은 틱을 20으로 나눈 게임 시간으로 비교한다.

R17을 100기에서 150기로 바꾸면 자연 웨이브 큐를 비우는 게임 시간만 5초에서 7.5초로 늘어난다. R1~R19의 유닛별 보상을 그대로 두고 수량을 50% 올리면 누적 기본 처치 보상도 3,867다이아에서 5,813다이아로 50.3% 증가한다.

### 4.3 계산 규칙

1. 4.2절 표의 `증량 전` 열처럼 시즌 3 증량 전 전투 유닛 합계를 `B`로 둔다. 설정에 회복 유닛이 이미 있으면 대체한 종류에 그 수를 돌려놓고 계산한다.
2. 목표 총수는 `T = floor(B × 배율 + 0.5)`로 계산한다.
3. 종류 `i`의 증량 전 수를 `b_i`라고 두고 정확한 몫 `q_i = b_i × T / B`를 계산한다. 각 `q_i`를 내림한 뒤 소수 부분이 큰 순서로 남은 수를 한 기씩 준다. 동률이면 설정에 먼저 적힌 종류가 우선한다.
4. 회복 유닛이 `H`기인 웨이브는 지정한 전투 유닛 `H`기를 회복 유닛으로 바꾼다. 총수 `T`는 바뀌지 않는다.
5. 보스와 회복 유닛 수에는 배율을 적용하지 않는다.

종류마다 `ceil(기존 수 × 배율)`을 적용하지 않는다. 종류가 많은 웨이브일수록 올림 보너스를 여러 번 받아 목표 배율을 넘기기 때문이다.

배율은 시즌 3 증량 전 수량 `B`에 한 번 적용한다. 이미 늘린 수량이나 회복 유닛 수에 다시 곱하지 않는다.

### 4.4 처치 보상

H0의 라운드별 자연 웨이브 기본 처치 보상 총액은 현재 값과 같아야 한다. 추가된 유닛에 기존 `mineralReward`를 그대로 복사하지 않는다.

| 라운드 | 레인당 예산 | 라운드 | 레인당 예산 |
|---:|---:|---:|---:|
| R1 | 36 | R11 | 175 |
| R2 | 42 | R12 | 240 |
| R3 | 54 | R13 | 250 |
| R4 | 80 | R14 | 315 |
| R5 | 100 | R15 | 400 |
| R6 | 140 | R16 | 300 |
| R7 | 120 | R17 | 400 |
| R8 | 200 | R18 | 320 |
| R9 | 200 | R19 | 320 |
| R10 | 175 | R20 이상 | 템플릿당 55 |

R1~R19의 레인당 누적 예산은 3,867다이아다.

확장된 큐의 몬스터 수를 `N`, 보상 예산을 `D`, 1부터 시작하는 출현 순서를 `i`라고 두고 각 몬스터의 기본 보상을 다음처럼 정한다.

`reward(i) = floor(i × D / N) - floor((i - 1) × D / N)`

이 계산은 정수 보상을 큐 전체에 고르게 나누며 합계를 정확히 `D`로 유지한다. 직업 보정 등 기존 보정은 이 값을 만든 뒤 적용한다. 보상을 늘릴 필요가 있으면 웨이브 난도 실험과 분리한 카탈로그에서 조정한다.

### 4.5 처치·사망 발동

보상 예산을 고정해도 처치 기반 성장은 그대로 늘 수 있다. 현재 코드에는 다음 영향이 있다.

- Illager 게이지, Warlock 각성, Demon Lord 경험치와 Ancient City 진행도
- Undead, Fox와 Villager 고양이의 주변 사망 스택
- Atlantis Dolphin의 사망 폭발과 연쇄 처치

H0의 추가 유닛도 다른 자연 웨이브 유닛과 같은 `NATURAL_WAVE`다. 정상 처치·주변 사망 효과를 각각 한 번 발동한다. 일부 유닛의 보상이 0이더라도 자연 웨이브 처치 진행도는 발동해야 한다. 보상 유무에 따라 같은 자연 웨이브 유닛의 성장 적격이 달라지게 두지 않으며, 추가 유닛만 숨겨서 제외하는 `progressionEligible` 규칙도 만들지 않는다.

해적을 포함한 기존 빌더의 처치·사망 성장 규칙은 보존한다. 특정 빌더의 성장이 과도하면 비교 결과와 조정안을 보고하고 결정받는다. 이번 작업에서 진행도 배율이나 성장 상한을 바꾸지 않는다.

## 5. 자연 웨이브 회복 유닛

### 5.1 적용 구간

회복 유닛은 R16부터 1기씩 늘려 R20에 5기에 도달한다. 이후 라운드에서는 5기를 유지한다. R20 이상은 `animal_stampede`, `overworld_assault`, `zombified_legion` 중 어떤 템플릿을 골라도 회복 유닛 5기가 등장한다.

R1~R15에는 자연 웨이브 회복 유닛을 넣지 않는다. 기존 1기 제한과 템플릿별 순차 공개안은 이번 결정으로 교체한다. 운영 공개 순서는 이번 작업에서 실행하지 않는다.

### 5.2 R16~R19 고정 웨이브

R16은 두 번째 증강과 R15 보스전이 끝난 뒤 처음 만나는 일반 웨이브다. 초반 학습 구간을 건드리지 않으면서 새 지원 유닛을 분명한 전환점에 소개할 수 있다. 준비 단계 미리보기에서 회복 유닛을 먼저 알려 대응할 시간을 준다.

현재 자연 웨이브 스키마는 피해 유형을 받지 않고 모든 자연 웨이브 공격을 물리 피해로 만든다. H0의 회복 유닛도 물리 피해를 사용한다. 마법 피해가 필요하면 회복 검증과 분리해 `WaveMonsterEntry`에 피해 유형을 추가한다.

### 5.3 후반 회복 유닛

회복 유닛으로 바꿀 종류는 템플릿마다 고정한다. 자동으로 고르지 않는다.

### 5.4 회복 대상과 발동 규칙

회복 유닛은 다음 조건을 모두 만족하는 대상만 회복한다.

- 회복 유닛과 목표 팀 및 레인이 같다.
- 소환 출처가 `NATURAL_WAVE`다.
- 살아 있고 현재 체력이 최대 체력보다 낮다.
- 일반 전투 유닛이다.

자신, 다른 회복 유닛, 인컴 유닛, 보스, 사망한 유닛과 이미 누수한 유닛은 제외한다. 잃은 체력이 큰 유닛부터 고른다. 동률이면 가까운 거리, 런타임 엔티티 ID 순서로 정한다. 회복 유닛 자신도 논리 상태가 살아 있을 때만 시전한다. 초과 회복과 부활은 없다.

서버는 선택한 최대 3기의 `sum(min(amount, missingHealth))`를 계산한다. 이 값이 `0.5 × amount × maxTargets` 이상일 때만 시전한다. H0의 부상량 기준은 R16~19에서 120, 후반 기준값 240이며 후반에는 라운드 체력 배율을 함께 적용한다. 50%는 H0 고정 규칙으로 두고 설정 필드를 추가하지 않는다. 작은 부상 한 번에 제한된 시전 횟수를 쓰지 않기 위한 조건이다.

대상이 없으면 `NO_ELIGIBLE_TARGET`, 부상량이 기준에 미달하면 `INSUFFICIENT_INJURY`로 집계하고 20틱 뒤 재시도한다. 둘 다 성공 횟수를 쓰지 않는다. 서버가 실제로 회복한 체력 합계가 0보다 클 때만 성공 횟수를 1 올리고 160틱 재사용 대기시간을 시작한다. 향후 회복 감소를 넣어도 부상량 조건은 감소 적용 전 요청량으로 계산한다. 감소 적용 뒤 유효 회복이 0이면 실패로 집계하고 성공 횟수 없이 20틱 뒤 재시도한다.

서버는 회복 유닛마다 남은 재사용 대기시간과 성공 횟수를 보관한다. 기절·수면 중에도 재사용 대기시간은 흐르지만 회복은 시전하지 않는다. 해제 후 조건을 만족하면 한 번 시전하며, 밀린 횟수를 몰아서 쓰지 않는다. 같은 틱에 여러 회복 유닛이 같은 대상을 고르더라도 각 시전은 앞선 회복을 반영한 현재 체력을 기준으로 판정한다. 사망·제거·누수한 회복 유닛은 시전하지 않는다.

### 5.5 출현 위치

R16 이후 일반 유닛은 기존 `ROUND_ROBIN` 순서를 유지한다. 목표 총수를 `T`, 회복 유닛 수를 `H`, 일반 전투 유닛 수를 `C = T - H`로 둔다. 일반 큐를 확장한 뒤 다음 수만큼 일반 유닛이 출현한 직후 회복 유닛을 삽입한다.

- `H = 1`: `floor(C × 0.55)`.
- `H > 1`: 회복 유닛 `j = 0..H-1`마다 `floor(C × (0.55 + 0.30 × j / (H - 1)))`.

| H0 라운드 | 일반 유닛 수 | 회복 유닛 삽입 직전까지 출현할 일반 유닛 수 |
|---|---:|---|
| R16 | 71 | 39 |
| R17 | 118 | 64, 100 |
| R18 | 93 | 51, 65, 79 |
| R19 | 92 | 50, 59, 69, 78 |
| R20~24 | 61 | 33, 38, 42, 47, 51 |
| R25 이상 | 67 | 36, 41, 46, 51, 56 |

이미 삽입한 회복 유닛은 위치 계산에서 세지 않는다. 같은 위치가 나오면 설정 순서를 유지한다. 회복만 시험의 R16은 일반 유닛 59기 중 32기가 나온 뒤 회복 유닛을 넣는다. 최종 총수는 `T`이며 출현 간격은 1틱을 유지한다.

55~85%는 출현 순서다. 이동 속도·사거리·교전 위치가 달라 공간적 후열을 보장하지 않는다. 범용 웨이브 타임라인은 추가하지 않는다.

### 5.6 플레이어 피드백

준비 단계에는 이미 다음 웨이브 미리보기가 있다. `selectedRoundWave`와 `upcomingWaveEntries()`는 수량 배율과 회복 유닛을 모두 반영한 구성을 반환해야 한다. 상세·축약 미리보기와 `HeroPartyState.assignQuest`는 같은 총수와 총체력을 사용한다. 실제 삽입 위치는 `PlayerLane.expandWaveEntries`에서 정한다.

`SemionHudTextService`는 일반·축약 미리보기 헤더에 `회복 ×{회복 유닛 수}`를 표시한다. 종류 목록의 표시 제한과 관계없이 실제 회복 개체 수를 확인할 수 있어야 한다. 별도 지원 상세 줄이나 대상당 회복량 표시는 이번 범위에 넣지 않는다.

회복 유닛 이름표는 `회복 · 남은 시전 2회`처럼 역할과 개체별 남은 성공 시전 횟수를 보여 준다. 실패 재시도에는 숫자를 줄이지 않는다. 시전할 때는 기존 회복 애니메이션과 대상 연결 효과를 사용한다. 결과 지표는 같은 레인·라운드에 등장한 회복 유닛 전체의 유효 회복량을 합산한다. 새 전용 GUI는 만들지 않는다.

현재 기본 타워는 높은 타기팅 우선도부터 공격하므로 우선도 0인 회복 유닛을 직접 골라 공격한다고 안내하지 않는다. 공개 전에는 같은 빌더와 지출 예산으로 다음 두 대응이 기존 규칙에서 작동하는지 비교한다.

- 광역 타워의 교전 위치를 바꿔 회복 유닛에도 피해를 주고, 두 번째 회복 전에 처치한다.
- 단일 대상 중심 보드의 배치와 화력 집중 구간을 바꿔 부상한 전투 유닛을 회복 전에 처치한다.

두 방법은 검증할 가설이며 현재 성립을 보장하지 않는다. 무대응 보드와 비교해 회복량이나 성공 시전 횟수를 줄이고 완막률·전투 시간을 악화시키지 않는지 확인한다. 대응이 막히면 사거리·이동·등장 시점별 원인과 변경안을 보고한다. 승인 없이 회복 수치나 행동을 바꾸지 않으며, 새 수동 타깃 지정 시스템은 넣지 않는다.

## 6. 증강과 웨이브의 조정 관계

이번 시험에서는 증강·빌더·회복 수치를 고정한다. 관측 결과는 다음과 같이 해석하고, 조정이 필요하면 사용자에게 근거와 선택지를 제시한다.

| 관측 결과 | 검토할 내용 |
|---|---|
| 수량만 시험에서 전투 시간·누수·타워 사망이 늘어남 | 일반 유닛 증가, 출현 지연과 처치 기반 성장의 영향을 확인한다. |
| 회복만 시험에서 전투가 길어짐 | 회복 유닛 수, 성공 횟수, 대상의 부상량과 회복 전 처치 가능성을 확인한다. |
| 회복 비율이 낮음 | 대상 없음, 부상량 미달, 초과 회복, 조기 처치와 두 번째 시전 실패를 구분한다. 낮은 값만으로 회복량을 올리지 않는다. |
| 회복 비율이 12% 이상임 | 승인한 다중 회복 편성에서 가능한 값이다. 실효 회복량·전투 시간·대응 결과를 함께 보고하며 자동 롤백하지 않는다. |
| 특정 증강 조합에서만 실패함 | 공격·방어·인컴 조합의 보드와 투자액, 빌더·선택 라운드를 비교한다. |
| 광역·단일 대상 조합의 차이가 커짐 | 회복 유닛에 피해를 줄 기회와 부상 유닛을 회복 전에 처치할 기회를 구분한다. |

증강 비교는 같은 증강 설정, 빌더, 희귀도와 선택 라운드에서 시작한다. 웨이브 조건을 바꾸면 카탈로그 해시도 달라지므로 차이를 기록한다. 무작위 풀이 닫힌 동안의 내부 시험은 동작 오류와 조합별 차이를 찾는 데 사용하며 공개 선택률의 근거로 쓰지 않는다.

### 7.2 필요한 최소 변경

1. 기존 `WaveConfig`의 회복 유닛 수 제한을 1기에서 최대 5기로 늘린다. 한 웨이브의 회복 유닛 종류는 하나를 유지한다. 지정한 일반 유닛 수를 회복 유닛 수만큼 복구한 뒤 수량을 배분하고 다시 교체한다.
2. R17~19에 고정 회복 항목을 추가하고 후반 템플릿 3종의 회복 수량을 5로 맞춘다. Java 기본값과 번들 JSON에 같은 편성·활성화 기본값을 넣는다.
3. `PlayerLane.expandWaveEntries`에서 일반 큐를 먼저 확장한 뒤 5.5절의 위치에 회복 유닛을 분산한다. 기존 라운드 보상 예산과 큐별 정수 보상 분배를 유지한다.
4. 기존 `WaveHealingState`를 개체마다 유지한다. `NaturalWaveHealGoal`의 대상 조건·부상량 검사·기절 처리와 두 번의 성공 상한을 재사용한다. 엔티티를 다시 만들어도 성공 횟수와 대기시간을 초기화하지 않는다.
5. `SemionGame`은 시작 시 모드·샌드박스·튜토리얼·증강 활성화·공개 후보 풀을 검사하고 유효한 `WaveConfig`를 고정한다. 진행 중인 경기는 설정 재적용의 영향을 받지 않는다.
6. 일반·축약 웨이브 미리보기 헤더에 실제 회복 유닛 수를 표시한다. 개체별 이름표의 남은 성공 횟수를 유지하고, 회복 기여도는 같은 레인·라운드의 모든 회복 유닛 값을 합산한다.
7. `templateId`, `mineralRewardBudget`, `healing`을 무한 라운드 배율 처리 후에도 보존한다. 회복량에는 체력 배율을 한 번만 곱한다. 카탈로그 해시에 변경된 웨이브 설정을 반영한다.
8. 기존 소환 출처, 처치·주변 사망 진행도, 해적 수입과 성장 경로를 보존한다. 보상 0인 자연 웨이브도 진행도를 한 번 처리하며 중복 지급과 경기 종료 후 지급을 막는 기존 검사를 유지한다.

이미 구현한 소환 출처·회복 처리·지표 저장 경로를 사용한다. 이번 변경으로 DB·공개 API 스키마나 웹 전용 매핑을 추가하지 않는다. 인컴 Allay의 ID와 회복 Goal은 바꾸지 않는다.

소환 출처는 증강과 웨이브가 함께 쓰는 `Monster` 상태다. 자연 웨이브 회복 대상 필터와 텔레메트리는 `NATURAL_WAVE` 값을 사용한다. `BUILDER_PROXY`는 자연 웨이브 회복 대상, 자연 웨이브 보상 보정, 인컴 위협 지표와 유료 인컴 조건에서 제외하되 기존 라이벌 전투 규칙은 바꾸지 않는다. 자연 웨이브 ID를 인컴 `SummonRegistry`에 등록하지 않는다. 별도 이벤트 버스, 능력 스크립트 언어와 범용 웨이브 타임라인은 추가하지 않는다.

이번 H0에는 회복 감소 디버프를 구현하지 않는다. 이후 빌더에 회복 감소를 추가할 때는 기존 `TimedEffectSet`에 몬스터의 받는 회복 감소 효과 하나를 추가하고, `SemionMonsterEntity.receiveHealing`에서 한 번만 적용한다. 각 회복 Goal에 별도 감소 공식을 넣지 않는다. 처리 순서는 `요청 회복량 → 회복 감소 적용 → 잃은 체력 상한 적용`이다. 요청량과 감소 적용 뒤 회복량의 차이를 회복 감소량으로, 감소 적용 뒤 회복량과 실제 유효 회복량의 차이를 초과 회복량으로 기록한다.

### 7.3 설정 계약

`RoundWaveConfig`의 기존 선택 항목을 유지한다.

- `templateId`: 무한 웨이브 템플릿을 지표와 설정에서 구분하는 안정 ID다. 새 기본 설정의 무한 웨이브 세 템플릿에서는 서로 다른 값을 사용한다.
- `mineralRewardBudget`: 플레이어 레인당 기본 보상 예산이다. 값이 없으면 하위 호환성을 유지하기 위해 `count × mineralReward`의 합계를 사용한다.

`WaveConfig`의 `infiniteCountMultipliers`는 시작 라운드 문자열을 키로, 배율을 값으로 쓰는 맵이다. H0는 `{"20": 1.20, "25": 1.30}`을 사용한다. 값이 없으면 `1.00`을 사용한다.

활성화 필드의 JSON 이름은 바꾸지 않는다.

| 필드 | 새 기본값 | 제어 범위 |
|---|---|---|
| `season3CountsEnabled` | `true` | 4절의 구간별 수량 증가 |
| `round16HealingEnabled` | `true` | 이름은 유지하고 R16~R19 고정 회복 편성 전체를 제어 |
| `healingTemplates` | 템플릿 3종의 ID | 선택한 후반 템플릿의 회복 편성 |

경기 적용 조건을 만족해도 파일에서 끈 단계는 켜지지 않는다. 기존 파일에 필드가 없으면 기존 비활성 동작을 유지하고, 명시적인 `false`나 빈 대상 목록도 보존한다. 새 기본값을 기존 파일에 자동으로 병합하거나 저장하지 않는다. 운영용 설정안은 기존 파일의 복사본에서 편성·예산과 대체 ID를 확인해 만들고 차이와 함께 로컬에 보관한다. 알 수 없는 ID나 부족한 대체 수량은 임의로 고치지 않고 보고한다.

회복 수치는 `WaveMonsterEntry.healing`에 둔다. H0에 필요한 필드는 아래 여섯 개뿐이다.

```json
{
  "radius": 6.0,
  "amount": 80.0,
  "maxTargets": 3,
  "cooldownTicks": 160,
  "retryDelayTicks": 20,
  "maxSuccessfulCasts": 2
}
```

위 예시는 R16~19 값이다. R20 무한 웨이브의 기준 `amount`는 160이다. R20 이상에서는 `scaleInfiniteEntry`가 `amount`에도 기존 체력 배율을 한 번 적용한다. 대상 필터, 우선순위와 50% 부상량 조건은 설정으로 열지 않고 5.4절 규칙으로 고정한다.

`WaveConfig.validate()`에서 기존 보상·배율·회복 수치 검사를 유지한다. 회복 편성은 R16 이후, 웨이브당 한 종류·최대 5기, 유효한 일반 유닛 대체를 요구한다. 활성화한 후반 회복 템플릿은 안정적인 ID와 회복 항목을 가져야 한다. 구버전 비활성 설정을 새 회복 편성으로 추정하지 않는다.

서버 시작 때 설정을 읽지 못하면 번들 기본값을 사용한다. `/semiontd reload`에서는 기본값으로 대체하지 않는 웨이브 전용 후보 읽기를 한 뒤 `WaveConfig.validate()`를 호출한다. 성공한 설정은 관리자 기본값과 다음 경기부터 사용하고, 진행 중인 경기는 경기 시작 때 고정한 `WaveConfig`를 유지한다. 다른 설정 형식까지 바꾸는 범용 리로드 프레임워크는 만들지 않는다.

## 8. 검증과 완료 기준

### 8.1 자동 검증

- R1~R4 수량이 기존과 같은지 확인한다.
- R5~R14, R16~R24, R25 이상의 목표 총수와 구성비 반올림을 확인한다.
- R15가 Warden 4기인지 확인한다.
- 각 라운드의 기본 처치 보상 합계가 기존 예산과 같은지 확인한다.
- 보상 0인 자연 웨이브 유닛도 처치 진행도와 주변 사망 효과를 각각 한 번만 발동하는지 확인한다.
- 같은 시드가 같은 무한 웨이브 템플릿과 같은 순서를 만드는지 확인한다.
- R15~20·R24·R25 경계에서 총수·회복 수·대체 종류가 4절과 5절의 표와 같은지 확인한다. R1~15에는 회복 유닛이 없어야 한다.
- 회복만 시험의 R16은 일반 유닛 32기 뒤, H0는 39기 뒤에 회복 유닛이 들어가는지 확인한다.
- 여러 회복 유닛이 5.5절의 55~85% 위치에 들어가는지, 일반 큐 순서와 최종 총수를 유지하는지 확인한다.
- 회복 대상 우선순위와 인컴·보스·다른 회복 유닛·다른 레인·사망·누수 제외를 확인한다.
- 여러 회복 유닛이 같은 대상을 회복해도 초과 회복과 부활이 없어야 한다. 개체마다 성공 160틱·실패 20틱·성공 2회 상한을 지키고 지표가 합산되는지 확인한다.
- 기절·수면 중 대기시간은 흐르되 시전하지 않는지, 해제 후 조건을 만족해도 밀린 횟수를 몰아서 쓰지 않는지 확인한다. 사망·제거·누수 후에는 시전하지 않아야 한다.
- 선택한 대상의 회복 가능한 부상량 합계가 50% 기준 미만이면 시전 횟수를 쓰지 않고 `INSUFFICIENT_INJURY`를 기록하는지 확인한다. 기준과 같은 값에서는 시전한다.
- 유효 회복 합계가 0인 시전은 실패인지 확인한다. 향후 회복 감소를 적용해도 부상량 조건은 감소 전 요청량으로 계산하고, 회복 결과가 0이면 성공 횟수를 쓰지 않아야 한다.
- 재접속이나 엔티티 재생성으로 시전 횟수와 재사용 대기시간이 초기화되지 않는지 확인한다.
- 자연 웨이브 큐는 `NATURAL_WAVE`, 라이벌 프록시는 `BUILDER_PROXY`를 받는지 확인한다. 프록시가 회복 대상이나 자연 웨이브 보상·인컴 위협 지표에 들어가지 않아야 한다.
- 무한 웨이브 능력치 배율을 적용한 뒤에도 `templateId`, `mineralRewardBudget`과 `healing`이 남는지 확인한다.
- 잘못된 웨이브 설정은 관리자 기본값과 진행 중인 경기 모두에 적용되지 않는지 확인한다. 유효한 설정도 진행 중인 경기에는 적용되지 않고 다음 경기부터 쓰이는지 확인한다.
- 증강 시스템·공개 후보 풀의 네 가지 활성화 조합과 `NORMAL`·테스트·튜토리얼·샌드박스를 검사한다. 1절의 조건을 모두 만족한 경기만 강화 웨이브를 사용해야 한다.
- 구버전 설정의 누락 필드, 명시적인 비활성 값과 빈 회복 대상 목록을 보존하는지 확인한다. 설정을 반복 적용해도 수량·회복량에 배율을 중복 적용하지 않아야 한다.

기존 단위 테스트와 GameTest를 확장한다. Java 21로 다음 회귀 검증을 실행하고 성공·실패·건너뜀 수와 실행 시간을 기록한다.

```sh
rtk ./gradlew test runGameTest remapJar --console=plain --no-daemon
```

### 8.2 측정 항목

기존 경기 지표와 내부 시험 결과를 사용한다. 이번 작업에서는 운영 계측이나 DB·API 스키마를 늘리지 않는다. 수집하지 못한 값은 `미측정`으로 적는다.

- `catalog_version`, 라운드, 선택된 웨이브 `templateId`
- 설정 수량, 실제 출현 수량과 출현 완료 시각
- 라운드 시작 총체력과 물리·마법 구성
- 회복 유닛 ID·수, 전체 개체의 총 시도 횟수, 성공 시전 횟수, 실패 사유별 횟수(`NO_ELIGIBLE_TARGET`, `INSUFFICIENT_INJURY`, 유효 회복 0), 적격 대상 수와 선택한 대상의 회복 가능한 부상량 합계, 요청 회복량, 회복 감소량, 초과 회복량, 실제 유효 회복량
- 전투 시간, `cleared`, 누수, 타워 사망, 60초 진입, 90초 최종 방어 진입
- 빌더, 선택한 증강, `area_damage_dealt`, `total_damage_dealt`
- 소환 출처별 처치 수와 `natural_wave_kill_count`
- 처치 성장 상태의 웨이브당 증가량과 상한 도달 라운드·틱
- 사망·피격 발동이 만든 추가 피해량과 추가 처치 수
- 자연 웨이브 기본 처치 보상 예산과 실제 지급 합계

### 8.3 결과 해석

시험 카탈로그를 직전 대조 카탈로그와 비교한다. 두 카탈로그는 `NORMAL` 모드와 `augment_version`을 포함한 증강 규칙이 같아야 하며, 이번에 시험하는 웨이브 항목만 달라야 한다. 같은 라운드와 템플릿부터 비교하고 빌더 구성도 함께 확인한다. 후반 도달 라운드가 다른 표본을 합쳐 난도 변화로 해석하지 않는다.

지표는 다음 단위로 계산한다.

- 완막률: 이 문서에서 정의한 완막 조건을 만족한 참가자-라운드 수를 해당 웨이브를 실제로 받은 참가자-라운드 수로 나눈다.
- P95 전투 시간: `(match_id, player_id, round_number)`로 중복을 제거한 `combat_seconds`의 95백분위수다.
- 60초 이상 전투 비율: `combat_seconds ≥ 60`인 참가자-라운드 수를 전체 참가자-라운드 수로 나눈다.
- 90초 최종 방어 진입률: `(match_id, round_number)`로 중복을 제거한 뒤 `wave_duration_seconds ≥ 90`인 경기-라운드 수를 해당 웨이브가 열린 경기-라운드 수로 나눈다. 공용 라운드 시간이므로 참가자 수로 가중하지 않는다.
- 타워 사망률: `tower_death_count` 합계를 `tower_count_start` 합계로 나눈다. 시작 타워 수가 0인 행은 제외한다.
- 회복 비율 `h`: 회복 유닛이 나온 레인·라운드의 실제 유효 회복량 합계를 같은 표본의 웨이브 시작 최대 체력 합계로 나눈다. 누수한 유닛에 준 회복도 포함하므로 플레이어의 추가 처치 부담이나 방어력 환산 EHP로 해석하지 않는다. 회복 유닛 교체만 시험할 때는 시작 최대 체력과 방어력 분포가 같지만 공격·이동 규칙의 차이는 남는다.
- 광역·단일 대상 완막률 격차: `total_damage_dealt > 0`인 표본에서 `area_damage_dealt / total_damage_dealt`가 50% 이상인 참가자-라운드를 광역, 20% 이하를 단일 대상으로 분류한다. 중간 표본은 제외한다. `gap = abs(광역 완막률 - 단일 대상 완막률)`, `Δ = 시험 카탈로그의 gap - 대조 카탈로그의 gap`으로 계산한다. 두 집단 중 하나라도 참가자-라운드 20건 미만이면 이 지표는 보류다.
- 처치 성장률: 해당 빌더의 웨이브당 진행도 증가량을 자연 웨이브 시작 총체력으로 나누고 10,000을 곱한다. 시험값과 대조값의 상대 변화율을 비교한다. 대조값이 0이면 비율을 만들지 않고 양쪽 증가량을 보고한다. 상한이 있는 상태는 두 표본 모두 상한에 도달했을 때 최초 도달 라운드도 비교하고, 그렇지 않으면 성장량을 비교한다.
- 사망·피격 발동 피해 비율: 해당 발동이 만든 추가 피해를 `total_damage_dealt`로 나눈다. 시험 비율에서 대조 비율을 빼 변화 `Δ`를 구한다.

다음 값은 이전 1기 편성안에서 사용한 비회복 지표의 검토선이다. 이번 시험에서도 차이를 찾는 참고값으로 남기되, 자동 통과·수치 변경·운영 롤백 명령으로 사용하지 않는다.

| 지표 | 우선 검토할 변화 |
|---|---:|
| 완막률 | 8%p 이상 하락 |
| P95 전투 시간 | 25% 이상 증가 |
| 60초 이상 전투 비율·90초 최종 방어 진입률 | 각각 10%p 이상 증가 |
| 타워 사망률 | 5%p 이상 증가 |
| 광역·단일 대상 완막률 격차 | 10%p 이상 증가 |
| 처치 성장률·상한 도달 시점 | 상대 변화 20% 이상 또는 상한 도달 3라운드 이상 앞당김 |
| 사망·피격 발동 피해 비율 | 8%p 이상 증가 |

회복 비율에는 기존 `6~10%` 목표와 `12% 이상 자동 롤백`을 적용하지 않는다. R17 이후 다중 회복 편성의 이론 상한은 이를 넘을 수 있다. 실제 회복량과 성공 횟수, 전투 시간·누수·대응 기회를 함께 해석한다.

회복 유닛이 없는 시험의 회복 비율은 `N/A`로 적는다. 부족한 표본이나 수집하지 못한 지표는 `표본 부족/미측정`으로 남긴다. 같은 보드를 반복 실행한 결과는 독립 플레이어 표본으로 세지 않는다. 내부 무증강 비교군에 정상 공략을 보장할 필요는 없다.

복제·무한 회복·보상 중복 같은 기능 결함은 수정하고 회귀 검증한다. 수량·회복량·증강 효과·타워 행동·시각 효과를 바꿔야 하면 작업을 멈추고 사용자의 결정을 받는다. 운영 배포나 공개 테스트로 넘어가지 않는다.

### 8.4 내부 비교 시험

기존 전투 시험에 아래 네 조건을 추가한다. 같은 빌더·보드·예산·증강 조합과 후반 템플릿을 유지하며 조건별 설정 해시를 기록한다.

| 조건 | 수량 | 회복 편성 |
|---|---|---|
| 기본 | 증량 전 | 없음 |
| 회복만 | 증량 전 | R16부터 1~5기 |
| 수량만 | H0 | 없음 |
| 회복·수량 | H0 | R16부터 1~5기 |

주요 측정 라운드는 R16·R19·R20·R25다. 무증강, 공격 중심, 방어 중심, 인컴 중심 조합을 나누어 전투 시간·누수·타워 사망·실효 회복량과 회복 비율을 보고한다. 고정 보드 시험에서 인컴 증강의 경제 이력을 재현하지 못하면 그 한계를 표시한다. 결과를 맞추려고 자원을 보충하거나 증강 효과를 바꾸지 않는다.

격리된 시험 설정에서만 증강 시스템과 후보 풀을 켠다. 30명 접속 테스트는 사용자 확인에 따른 기존 라이브 검증 완료로 제외한다. 전체 빌더 기록 재현이나 새 리플레이 프레임워크를 추가하지 않는다.

### 8.5 재미와 이해도 확인

5.6절의 두 대응을 실제 클라이언트 전투에서 확인한다. 테스트 진행자는 첫 R16 전에 설명을 덧붙이지 않고 미리보기와 이름표만 보여 준 뒤 다음을 관찰한다.

- 플레이어가 회복 유닛과 남은 시전 횟수를 알아보는가?
- 다음 시도에서 배치나 투자 판단을 바꾸고, 줄어든 회복 또는 막아 낸 두 번째 시전을 확인하는가?
- 플레이어가 실패 이유를 설명하는가, 아니면 적 체력이 이유 없이 되차거나 전투만 길어졌다고 느끼는가?

플레이어가 대응을 바꾸지 못하거나 변화의 결과를 알아보지 못하면 원인과 변경안을 보고한다. 자동 테스트 통과와 실제 클라이언트 화면 검증을 구분한다. 화면을 확인하지 않았다면 `미확인`으로 남기며 운영 밸런스까지 입증했다고 표현하지 않는다.
