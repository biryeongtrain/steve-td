# 세미온 TD 시즌 3 웨이브 명세

> 기준일: 2026-09-05 · 기준 브랜치: `s3-release` · 적용 모드: `NORMAL` · 상태: 로컬 구현·검증 중. 회복·수량 단계는 기본 비활성이며 운영 적용하지 않았다.

이 문서는 시즌 3의 웨이브 수량, 자연 웨이브 회복 유닛, 처치 보상과 검증 순서를 정의한다. 웨이브와 관련해서는 이 문서가 [시즌 3 출시 기획안](./2026-09-01-season-3-release-design.ko.md)의 관련 내용을 대체한다. 증강 자체의 규칙은 [시즌 3 증강 시스템 명세](./2026-09-03-season-3-augment-design.ko.md)를 따른다.

처음 작업하는 개발자는 1절에서 결론을 확인하고, 4절의 수량표와 5절의 회복 유닛 규칙을 구현 기준으로 사용한다. 7절은 필요한 코드 경계, 8절은 테스트와 라이브 판정 기준이다.

이 문서에서 쓰는 말은 다음과 같다.

- `기술 카나리`: 수량을 바꾸지 않고 회복 로직과 지표만 먼저 검증하는 작은 공개 단계다.
- `무한 웨이브 템플릿`: R20 이상에서 라운드마다 하나씩 뽑는 기본 편성 묶음이다.
- `보상 예산`: 플레이어 레인 한 곳에서 한 라운드의 자연 웨이브를 모두 처치했을 때 지급 가능한 기본 다이아 합계다. 직업 보정 등 기존 보정을 적용하기 전 값이다.
- `소환 출처`: 자연 웨이브, 유료·무료 인컴, 메아리와 빌더 프록시를 구분하는 식별값이다.
- `일반 전투 유닛`: 자연 웨이브의 회복 유닛과 보스를 제외한 공격 유닛이다.
- `회복 비율`: 회복 유닛의 실제 유효 회복량을 같은 표본의 웨이브 시작 최대 체력으로 나눈 값이다. 이 문서에서는 `h`로 쓴다. 방어력으로 환산한 EHP나 플레이어가 처치에 추가로 사용한 피해량을 뜻하지 않는다.
- `완막`: 개인 레인에 웨이브가 배정됐고 `cleared=true`, `leaked=false`, `laneDefenseBroken=false`이며 소속 팀이 다음 준비 단계에도 생존한 결과다. 분모는 해당 라운드 웨이브를 실제로 받은 참가자 수다.

## 1. 결정 사항

| 항목 | H0 결정 |
|---|---|
| 웨이브 수량 | 전 구간 50% 증량부터 시작하지 않는다. R5 이후 10%, 20%, 30%로 나눈다. |
| R1~R4 | 변경하지 않는다. 첫 증강을 얻기 전 구간이다. |
| R15 | Warden 보스 4기를 유지한다. 일반 전투 유닛 배율을 적용하지 않는다. |
| R25 이상 | 30% 증량으로 시작한다. 40%, 50%는 검증을 통과한 뒤 별도 카탈로그에서 시험한다. |
| 회복 유닛 | R16에 처음 등장한다. 웨이브당 최대 1기이며 기존 전투 유닛 한 자리를 대체한다. |
| 회복 비율 | 회복 유닛을 방치한 내부 시험에서 6~10%를 목표로 한다. 플레이어가 대응해 회복을 줄인 결과는 실패로 보지 않는다. |
| 처치 보상 | 유닛 수가 늘어도 라운드의 자연 웨이브 기본 처치 보상 총액은 늘리지 않는다. |
| 증강 상향 | 웨이브와 동시에 조정하지 않는다. 특정 피해 증강만 약하다는 데이터가 있을 때 한 단계씩 올린다. |

`×1.50`은 검증 가능한 수량 상한이다. 현재 증강은 모든 플레이어에게 최소 50% 화력을 주지 않으므로 H0는 더 낮은 배율에서 시작한다. 대응할 선택이 늘지 않고 전투만 길어지면 수량을 더 올리지 않는다.

R16 회복 유닛은 두 단계로 본다. 먼저 총수 60기의 기술 카나리로 회복 동작과 유닛 교체의 영향을 본다. 그 다음 수량 H0를 열면 총수 72기 규칙 위에 같은 회복 계약을 유지한다. R1~R15에는 자연 웨이브 회복 유닛을 넣지 않는다.

회복을 포함한 체력 총량 증가율은 `시험 웨이브 시작 최대 체력 / 대조 웨이브 시작 최대 체력 × (1 + h) - 1`로 계산한다. 이는 체력 총량 비교이며 난도 증가율은 아니다. 구성비와 정수 반올림의 영향을 생략하면 아래처럼 수량 배율로 근사할 수 있다. 표는 `h=6~10%`를 가정한 예시이며, 설정상 회복 상한은 5.3절에서 따로 확인한다.

| 단계 | 수량 배율 | 기존 웨이브 대비 체력 총량 증가 근사치 |
|---|---:|---:|
| R16 기술 카나리 | `×1.00` | 6~10% |
| R16 및 R20~R24 중 회복 유닛 적용 웨이브 | `×1.20` | 27.2~32.0% |
| R25 이상 수량 H0 | `×1.30` | 37.8~43.0% |
| R25 이상 승격 1 | `×1.40` | 48.4~54.0% |
| R25 이상 승격 2 | `×1.50` | 59.0~65.0% |

이 표는 회복 유닛이 적용된 웨이브만 설명한다. 회복 상한이 10%보다 낮은 편성은 표의 상단 값에 도달하지 못한다. `×1.50`은 회복까지 합치면 50%를 넘을 수 있으므로 자동 승격하지 않는다.

## 2. 왜 50%부터 시작하지 않는가

### 2.1 증강의 전투력은 선택에 따라 다르다

시즌 3 후보에는 전역 피해 증가 외에도 다음 카드가 섞여 있다.

- 인컴을 바꾸는 카드
- 받는 피해와 생존을 바꾸는 카드
- 타워 한 기만 강화하는 카드
- 배치나 전투 시간 조건을 만족해야 발동하는 카드
- 타워나 슬롯을 영구적으로 포기하는 카드

피해 증강을 연달아 고른 일부 플레이어의 보드는 50%보다 강해질 수 있다. 인컴이나 방어 카드를 고른 플레이어의 보드는 직접 피해가 거의 늘지 않을 수도 있다. 시즌 3 `NORMAL`은 기존 주특성·부특성도 비활성화하므로, 증강 세 장을 기존 특성 위에 더한 값으로 계산하면 안 된다.

### 2.2 수량과 화력은 같은 비율로 맞춰도 결과가 같지 않다

웨이브 수량 배율을 `m`, 플레이어의 실제 화력 배율을 `p`라고 두면 단일 대상 위주의 보드에서 전투 시간은 대략 `m / p`배가 된다.

예를 들어 실제 화력이 20% 늘었는데 수량을 50% 늘리면 전투 시간은 약 `1.50 / 1.20 = 1.25`, 즉 25% 길어진다. 회복 유닛이 더해지면 전투 시간은 더 늘어난다.

세미온 TD에는 긴 전투를 추가로 위험하게 만드는 규칙도 있다.

- 모든 현재 웨이브는 한 틱에 한 기씩 출현한다. 수량이 늘면 마지막 유닛의 출현도 늦어진다.
- 몬스터가 60초 동안 살아 있으면 2초마다 체력 5%, 공격력 6%가 증가한다.
- 90초에는 최종 방어가 강제로 시작된다.

따라서 수량 50%와 회복을 한 번에 적용하면 실제 난도는 50%보다 크게 오를 수 있다.

### 4.3 계산 규칙

1. 4.2절 표의 `현재` 열처럼 시즌 3 증량 전 전투 유닛 합계를 `B`로 둔다.
2. 목표 총수는 `T = floor(B × 배율 + 0.5)`로 계산한다.
3. 종류 `i`의 증량 전 수를 `b_i`라고 두고 정확한 몫 `q_i = b_i × T / B`를 계산한다. 각 `q_i`를 내림한 뒤 소수 부분이 큰 순서로 남은 수를 한 기씩 준다. 동률이면 설정에 먼저 적힌 종류가 우선한다.
4. 회복 유닛이 있는 웨이브는 템플릿에 지정한 전투 유닛 한 기를 회복 유닛으로 바꾼다. 총수 `T`는 바뀌지 않는다.
5. 보스와 회복 유닛 수에는 배율을 적용하지 않는다.

종류마다 `ceil(기존 수 × 배율)`을 적용하지 않는다. 종류가 많은 웨이브일수록 올림 보너스를 여러 번 받아 목표 배율을 넘기기 때문이다.

승격 배율도 항상 시즌 3 증량 전 수량 `B`에 적용한다. 예를 들어 R25의 `×1.40`은 H0의 72기에 다시 곱하지 않고 기존 55기에서 77기를 계산한다.

### 4.4 처치 보상

H0의 라운드별 자연 웨이브 기본 처치 보상 총액은 현재 값과 같아야 한다. 추가된 유닛에 기존 `mineralReward`를 그대로 복사하지 않는다.

R1~R19의 레인당 누적 예산은 3,867다이아다.

확장된 큐의 몬스터 수를 `N`, 보상 예산을 `D`, 1부터 시작하는 출현 순서를 `i`라고 두고 각 몬스터의 기본 보상을 다음처럼 정한다.

`reward(i) = floor(i × D / N) - floor((i - 1) × D / N)`

이 계산은 정수 보상을 큐 전체에 고르게 나누며 합계를 정확히 `D`로 유지한다. 직업 보정 등 기존 보정은 이 값을 만든 뒤 적용한다. 보상을 늘릴 필요가 있으면 웨이브 난도 실험과 분리한 카탈로그에서 조정한다.

### 4.5 처치·사망 발동

보상 예산을 고정해도 처치 기반 성장은 그대로 늘 수 있다. 현재 코드에는 다음 영향이 있다.

- Illager 게이지, Warlock 각성, Demon Lord 경험치와 Ancient City 진행도
- Undead, Fox와 Villager 고양이의 주변 사망 스택
- Atlantis Dolphin의 사망 폭발과 연쇄 처치

H0의 추가 유닛도 다른 자연 웨이브 유닛과 같은 `NATURAL_WAVE`다. 정상 처치·주변 사망 효과를 각각 한 번 발동한다. 일부 유닛의 보상이 0이더라도 자연 웨이브 처치 진행도는 발동해야 한다. 보상 유무에 따라 같은 자연 웨이브 유닛의 성장 적격이 달라지게 두지 않으며, 추가 유닛만 숨겨서 제외하는 `progressionEligible` 규칙도 만들지 않는다.

이 정책이 특정 빌더를 과도하게 키우면 수량 승격을 보류하고 해당 빌더의 진행도 배율이나 웨이브당 상한을 별도 카탈로그에서 조정한다.

## 5. 자연 웨이브 회복 유닛

### 5.1 공개 순서

회복 유닛은 다음 순서로 연다.

1. 공개 증강 기준선을 수집한 뒤 수량을 바꾸지 않은 R16에서 동작과 지표를 검증한다.
2. R16 카나리가 통과하면 같은 회복 유닛을 유지한 채 수량 H0를 연다.
3. 수량 H0가 안정되면 R20 이상 템플릿 하나에 회복 유닛을 넣는다.
4. `overworld_assault`가 기준을 통과하면 `animal_stampede`, `zombified_legion` 순서로 한 카탈로그에 하나씩 넓힌다.

R1~R19 고정 웨이브 중 회복 유닛은 R16에만 나온다. R15 Warden 보스도 회복하지 않는다. H0에서는 한 웨이브에 회복 유닛을 두 기 이상 넣지 않는다.

### 5.2 R16 기술 카나리

R16은 두 번째 증강과 R15 보스전이 끝난 뒤 처음 만나는 일반 웨이브다. 초반 학습 구간을 건드리지 않으면서 새 지원 유닛을 분명한 전환점에 소개할 수 있다. 준비 단계 미리보기에서 회복 유닛을 먼저 알려 대응할 시간을 준다.

| 항목 | 값 |
|---|---|
| 구성 | 호글린 19기, 돌진 좀비화 피글린 20기, 원거리 피글린 20기, 회복 유닛 1기 |
| 총수 | 60기. 현재와 동일 |
| ID | `wave_healer_allay_16` |
| 체력 / 방어력 | 120 / 10 |
| 기본 공격 | 2, 원거리 물리 피해 |
| 사거리 / 공격 간격 | 6블록 / 13틱 |
| 이동 속도 배율 | 0.85 |
| 타기팅 우선도 | 0 |
| 기본 처치 보상 | R16의 레인당 보상 예산 300다이아에 포함 |
| 회복 | 반경 6블록, 대상당 80, 최대 3기 |
| 첫 시전 | 5.4절의 부상량 조건을 만족하면 즉시 |
| 재사용 대기시간 | 성공 160틱, 대상 없음·부상량 미달·유효 회복 0이면 20틱 뒤 재시도 |
| 성공 시전 상한 | 웨이브당 2회 |

회복 유닛은 `hoglin_tank_16` 한 기를 대체한다. 최대 체력과 방어력은 대체 전과 같으므로 웨이브 시작 최대 체력 4,500은 바뀌지 않는다. 한 번에 최대 240, 한 웨이브에 최대 480을 회복한다. 설정상 회복량 상한 비율은 `480 / 4,500 = 10.67%`다.

수량 H0에서는 호글린 23기, 돌진 좀비화 피글린 24기, 원거리 피글린 24기와 회복 유닛 1기로 총 72기를 구성한다. 웨이브 시작 최대 체력은 5,400이며 설정상 회복량 상한 비율은 `480 / 5,400 = 8.89%`다. 기술 카나리는 수량과 웨이브 시작 최대 체력·방어력 분포를 유지한다. 공격, 이동, 사거리와 타기팅 우선도는 달라지므로 회복만의 효과가 아닌 유닛 교체의 종합 효과를 측정한다.

현재 자연 웨이브 스키마는 피해 유형을 받지 않고 모든 자연 웨이브 공격을 물리 피해로 만든다. H0의 회복 유닛도 물리 피해를 사용한다. 마법 피해가 필요하면 회복 검증과 분리해 `WaveMonsterEntry`에 피해 유형을 추가한다.

### 5.3 후반 회복 유닛

첫 후반 카나리는 R20 이상 무한 웨이브 템플릿 세 개 중 `overworld_assault`에만 적용한다. 라운드마다 템플릿 하나를 무작위로 고르므로 회복 유닛 출현 확률은 약 1/3이다.

| 구간 | `overworld_assault` H0 구성 |
|---|---|
| R20~R24 | 허스크 24기, 거미 23기, 약탈자 18기, 회복 유닛 1기. 총 66기 |
| R25 이상 | 허스크 26기, 거미 25기, 약탈자 20기, 회복 유닛 1기. 총 72기 |

회복 유닛으로 바꿀 종류는 템플릿마다 고정한다. 자동으로 고르지 않는다.

| 대상 웨이브·템플릿 | 대체할 `WaveMonsterEntry.id` |
|---|---|
| R16 고정 웨이브 | `hoglin_tank_16` |
| `animal_stampede` | `infinite_llama_ranged` |
| `overworld_assault` | `infinite_spider_rush` |
| `zombified_legion` | `infinite_zombified_piglin_rush` |

H0에서는 `overworld_assault`만 사용한다. 나머지 두 ID는 5.1절 4단계에서 회복 유닛을 넓힐 때 사용한다.

후반 회복 유닛의 H0 수치는 다음과 같다.

| 항목 | 값 |
|---|---|
| ID | `wave_healer_allay_infinite` |
| R20 기준 체력 / 방어력 | 150 / 7 |
| 기본 공격 | 2, 원거리 물리 피해 |
| 사거리 / 공격 간격 | 6블록 / 13틱 |
| 이동 속도 배율 | 0.85 |
| 타기팅 우선도 | 0 |
| 기본 처치 보상 | 해당 라운드 총보상 예산에 포함 |
| 회복 | 반경 6블록, 대상당 160, 최대 3기 |
| 첫 시전 | 5.4절의 부상량 조건을 만족하면 즉시 |
| 재사용 대기시간 | 성공 160틱, 대상 없음·부상량 미달·유효 회복 0이면 20틱 뒤 재시도 |
| 성공 시전 상한 | 웨이브당 2회 |

회복 유닛은 대체하는 `infinite_spider_rush`와 같은 최대 체력과 방어력을 사용한다. 다른 템플릿으로 넓힐 때도 회복 유닛의 최대 체력과 방어력은 그 템플릿에서 대체하는 항목과 같게 둔다. 후반 회복 유닛의 체력과 회복량에는 기존 무한 웨이브 체력 배율을 적용하고, 기본 공격에는 공격력 배율을 적용한다. R20 `overworld_assault` H0의 웨이브 시작 최대 체력은 약 12,540이고 두 번의 최대 회복은 960이다. 설정상 회복량 상한 비율은 약 7.66%다.

아래 값은 회복량 상한이다. 실제 회복 비율은 대상의 잃은 체력, 회복 유닛의 생존과 두 번째 시전 성공 여부에 따라 낮아진다.

| 시험 | 웨이브 시작 최대 체력 | 최대 회복 | 설정상 회복량 상한 비율 | 회복 감소 30% 적용 뒤 상한 |
|---|---:|---:|---:|---:|
| R16 기술 카나리 | 4,500 | 480 | 10.67% | 7.47% |
| R16 수량 H0 | 5,400 | 480 | 8.89% | 6.22% |
| R20 `overworld_assault` H0 | 약 12,540 | 960 | 7.66% | 5.36% |
| R25 이상 `overworld_assault` H0 `×1.30` | 약 13,633 | 960 | 7.04% | 4.93% |
| R25 이상 `overworld_assault` 시험 `×1.40` | 약 14,630 | 960 | 6.56% | 4.59% |
| R25 이상 `overworld_assault` 시험 `×1.50` | 약 15,723 | 960 | 6.11% | 4.27% |

R25 이상 행은 라운드 체력 배율을 적용하기 전 값이다. 실제 체력과 회복량에 같은 배율을 곱하므로 상한 비율은 같다. `×1.50`에서 회복 비율 6%를 얻으려면 최대 회복량의 98.27%를 써야 한다. 따라서 6~10%를 모든 수량 단계의 필수 합격선으로 쓰지 않는다.

회복 감소 30%는 향후 빌더 디버프를 가정한 내성 점검값이며 이번 H0의 확정 수치가 아니다. 회복 유닛을 방치하고 디버프도 없는 내부 시험에서 회복 비율 6~10%를 목표로 한다. 공개 경기에서는 조기 처치와 부상 대상 제거로 회복이 줄어든 결과도 대응 성공으로 본다. 회복 감소가 한 번이라도 적용된 레인·라운드는 기본 회복량 비교에서 제외하고 요청량·감소량·실제 유효 회복량을 별도로 보고한다.

### 5.4 회복 대상과 발동 규칙

회복 유닛은 다음 조건을 모두 만족하는 대상만 회복한다.

- 회복 유닛과 목표 팀 및 레인이 같다.
- 소환 출처가 `NATURAL_WAVE`다.
- 살아 있고 현재 체력이 최대 체력보다 낮다.
- 일반 전투 유닛이다.

자신, 다른 회복 유닛, 인컴 유닛, 보스, 사망한 유닛과 이미 누수한 유닛은 제외한다. 잃은 체력이 큰 유닛부터 고른다. 동률이면 가까운 거리, 런타임 엔티티 ID 순서로 정한다. 회복 유닛 자신도 논리 상태가 살아 있을 때만 시전한다. 초과 회복과 부활은 없다.

서버는 선택한 최대 3기의 `sum(min(amount, missingHealth))`를 계산한다. 이 값이 `0.5 × amount × maxTargets` 이상일 때만 시전한다. H0의 부상량 기준은 R16 120, 후반 기준값 240이며 후반에는 라운드 체력 배율을 함께 적용한다. 50%는 H0 고정 규칙으로 두고 설정 필드를 추가하지 않는다. 작은 부상 한 번에 제한된 시전 횟수를 쓰지 않기 위한 조건이다.

대상이 없으면 `NO_ELIGIBLE_TARGET`, 부상량이 기준에 미달하면 `INSUFFICIENT_INJURY`로 집계하고 20틱 뒤 재시도한다. 둘 다 성공 횟수를 쓰지 않는다. 서버가 실제로 회복한 체력 합계가 0보다 클 때만 성공 횟수를 1 올리고 160틱 재사용 대기시간을 시작한다. 향후 회복 감소를 넣어도 부상량 조건은 감소 적용 전 요청량으로 계산한다. 감소 적용 뒤 유효 회복이 0이면 실패로 집계하고 성공 횟수 없이 20틱 뒤 재시도한다.

### 5.5 출현 위치

R16과 R20 이상 템플릿은 `ROUND_ROBIN`이다. 현재 목록에 수량 1인 회복 유닛을 추가하면 첫 순환에 바로 나오므로 별도 삽입 규칙을 사용한다. 먼저 4.3절에 따라 일반 전투 유닛을 `T`기까지 배분하고, 지정한 종류에서 한 기를 빼 `T - 1`기 큐를 만든다. 이 큐를 확장한 뒤 `floor((T - 1) × 0.55)`기가 출현한 직후 회복 유닛 한 기를 삽입한다. 최종 총수는 `T`다.

- R16 기술 카나리: 전투 유닛 59기 중 32기가 나온 뒤 삽입한다.
- R16 수량 H0: 전투 유닛 71기 중 39기가 나온 뒤 삽입한다.
- R20~R24: 전투 유닛 65기 중 35기가 나온 뒤 삽입한다.
- R25 이상: 전투 유닛 71기 중 39기가 나온 뒤 삽입한다.

이 기능은 회복 유닛의 한 번 삽입만 지원한다. 범용 웨이브 스크립트 엔진은 만들지 않는다.

55%는 출현 순서다. 이동 속도, 사거리와 교전 위치가 다르므로 공간적 후열을 보장하지 않는다.

### 5.6 플레이어 피드백

준비 단계에는 이미 다음 웨이브 미리보기가 있다. `selectedRoundWave`와 `upcomingWaveEntries()`는 수량 배율과 회복 유닛을 모두 반영한 구성을 반환해야 한다. 그래야 상세·축약 미리보기와 `HeroPartyState.assignQuest`가 같은 총수와 총체력을 사용한다. 실제 55% 삽입 위치만 `PlayerLane.expandWaveEntries`에서 정한다.

`SemionHudTextService.appendNextWavePreview`는 최대 세 종류만 보여 주므로, `healing`이 있는 유닛은 세 종류 제한과 별도로 다음 한 줄을 표시한다.

`지원: 회복 알레이 ×1 · 대상당 {현재 회복량} 회복 · 최대 3기 · 성공 시전 최대 2회`

R16의 `{현재 회복량}`은 80이다. R20 이상에서는 현재 라운드 배율을 적용한 값을 표시한다. 회복 유닛 이름표는 `회복 · 남은 시전 2회`처럼 역할과 남은 성공 시전 횟수를 보여 준다. 실패 재시도에는 숫자를 줄이지 않는다. 시전할 때는 기존 회복 애니메이션과 대상 연결 효과를 사용한다. 웨이브 결과는 `총 324 회복 · 시작 체력의 7.2%`처럼 표시한다. 새 전용 GUI는 만들지 않는다.

현재 기본 타워는 높은 타기팅 우선도부터 공격하므로 우선도 0인 회복 유닛을 직접 골라 공격한다고 안내하지 않는다. 공개 전에는 같은 빌더와 지출 예산으로 다음 두 대응이 기존 규칙에서 작동하는지 비교한다.

- 광역 타워의 교전 위치를 바꿔 회복 유닛에도 피해를 주고, 두 번째 회복 전에 처치한다.
- 단일 대상 중심 보드의 배치와 화력 집중 구간을 바꿔 부상한 전투 유닛을 회복 전에 처치한다.

두 방법은 검증할 가설이며 현재 성립을 보장하지 않는다. 무대응 보드와 비교해 회복량이나 성공 시전 횟수를 줄이고 완막률·전투 시간을 악화시키지 않는지 확인한다. 두 대응을 재현하기 전에는 회복량 상향을 보류한다. 대응이 막힌 원인은 사거리, 이동 또는 등장 시점 중 하나씩 시험한다. H0에 새 수동 타깃 지정 시스템은 넣지 않는다.

## 6. 증강과 웨이브의 조정 관계

웨이브가 어려워졌다는 이유만으로 증강 피해를 먼저 올리지 않는다. 원인을 다음 순서로 구분한다.

| 관측 결과 | 다음 카탈로그의 변경 |
|---|---|
| 공개 수량 H0 표본이 8.3절의 즉시 롤백 구간에 들어감 | 시험값을 직전 대조 카탈로그 값으로 되돌린다. |
| 공개 수량 H0의 적용 지표가 통과하고 같은 라운드의 P95 전투 시간이 대조군보다 10% 이상 짧음 | 증량 필요성을 검토한다. 5.6절 대응 시험에서 선택이 늘어난 경우에만 다음 수량 단계를 시험한다. |
| 무대응 내부 시험의 회복 비율이 6% 미만임 | 대상 없음, 부상량 미달, 초과 회복, 조기 처치와 두 번째 시전 실패를 구분한다. 회복량 부족이 원인일 때만 수치 변경 가설 하나를 시험한다. |
| 공개 경기에서 회복 비율이 6% 미만임 | 대응 성공 여부를 먼저 확인한다. 낮은 값만으로 회복량을 올리지 않는다. |
| 회복 비율이 10% 초과 12% 미만임 | 긴 전투와 대응 실패를 함께 확인한다. 필요하면 회복량·사거리·시점 중 원인 하나를 별도 시험한다. |
| 회복 비율이 12% 이상이거나 회복 카나리 표본이 즉시 롤백 구간에 들어감 | 안전 경보로 취급하고 해당 회복 유닛 단계를 직전 대조 카탈로그 값으로 되돌린다. |
| 특정 피해 증강 선택자의 이후 3웨이브 완막률이 같은 조건의 비교군보다 낮음 | 선택 직전 보드와 누수 상태, 빌더, 희귀도, 선택 라운드를 확인한다. 카드 자체가 약하다는 가설을 검증한 뒤 수치를 바꾼다. |
| 광역·단일 대상 완막률 격차가 5%p 넘게 벌어짐 | 수량을 더 올리지 않고 웨이브 구성이나 체력 분배를 별도 시험한다. |

증강 비교는 같은 `catalog_version`, 빌더, 희귀도와 선택 라운드에서 시작한다. 제시 횟수만으로 상향을 결정하지 않는다. 불리한 보드가 해당 카드를 더 자주 고르는 선택 편향도 확인한다. 수치 시험에서는 카드 하나 또는 같은 계보 하나만 바꾸고 웨이브는 유지한다. 무작위 풀이 닫힌 동안의 관리자 강제 제안 테스트는 동작 오류와 지배 조합을 찾는 데 사용하며 공개 선택률의 근거로 쓰지 않는다.

### 7.2 필요한 최소 변경

1. `Monster.fromWaveEntry`가 소환 출처를 필수 인자로 받게 한다. `PlayerLane.enqueueWaveMonster`와 `enqueueWave`만 `NATURAL_WAVE`를 넘기고, `AdversaryRivalTower`의 라이벌 개체는 `BUILDER_PROXY`를 넘긴다. `Monster.fromWaveEntry` 호출만으로 자연 웨이브라고 간주하지 않는다.
2. 고정 웨이브의 H0 수량을 `wave.json`에 명시한다.
3. 무한 웨이브 세 템플릿에 안정적인 `templateId`를 붙인다. 첫 후반 카나리 ID는 `overworld_assault`다.
4. 무한 웨이브 설정에 `infiniteCountMultipliers={"20": 1.20, "25": 1.30}`을 추가한다. 현재 라운드 이하에서 가장 큰 키의 배율을 사용한다.
5. `RoundWaveConfig`에 선택 항목 `mineralRewardBudget`을 추가한다. 값이 없으면 기존처럼 `count × mineralReward`의 합계를 사용한다.
6. 확장된 큐에 4.4절 공식으로 정수 보상을 배분한다. `lateJoinCatchUpDiamond`도 유닛별 합계가 아니라 같은 예산을 사용한다.
7. `WaveMonsterEntry`의 선택 항목 `healing`을 논리 `Monster`까지 복사한다. `SemionMonsterEntity.installWaveAbilityGoals`를 별도로 만들고, `configureFrom()`이 소환·복원 때 이를 호출하게 한다. `NATURAL_WAVE`이면서 `healing`이 있는 개체에만 자연 웨이브 회복 Goal을 설치한다.
8. 지정한 일반 전투 유닛 수를 한 기 줄여 `T - 1`기 `ROUND_ROBIN` 큐를 확장한 뒤 회복 유닛 한 기를 지정 비율에 삽입한다.
9. 회복 유닛의 남은 재사용 대기시간과 성공 횟수를 논리 `Monster`에 저장한다. 전용 회복 Goal은 로컬 필드가 아니라 이 값을 읽고 쓴다. 실제 엔티티를 다시 만들어도 초기화하지 않는다.
10. 레인·라운드마다 총 시도 횟수, 성공 시전 횟수, 적격 대상 수, 선택한 대상의 회복 가능한 부상량 합계, 요청 회복량, 회복 감소량, 초과 회복량과 실제 유효 회복량을 집계한다. 실패 사유는 `NO_ELIGIBLE_TARGET`, `INSUFFICIENT_INJURY`, 시전했지만 유효 회복이 0인 경우로 나누어 기록한다. 성공 횟수는 유효 회복이 0보다 큰 시전에서만 늘린다.
11. `WaveConfig.scaleInfiniteRound`는 `RoundWaveConfig`의 `templateId`와 `mineralRewardBudget`을 보존한다. `scaleInfiniteEntry`는 `WaveMonsterEntry.healing`을 복사하고 `amount`에 체력 배율을 한 번만 적용한다.
12. 소환 출처를 판정할 때 `ownerPlayer()` 유무를 쓰던 `EconomyService`의 자연 웨이브 보상 보정과 `PlayerLane`의 인컴 위협·누수 지표를 명시적인 소환 출처 판정으로 바꾼다.
13. `SemionPolymerEntityDataWarmup`이 시작 시 `rounds()`와 `infiniteTemplates()`의 엔티티 종류와 BIL 모델을 모두 준비하게 한다. `SemionGameManager.reloadConfigs`도 새 설정을 적용하기 전에 같은 준비 과정을 실행한다.
14. `PlayerRoundMetricsSnapshot`과 DB·공개 API 스키마에 8.2절의 라운드 집계값을 추가한다. 시전별 이벤트 테이블은 만들지 않고 횟수·합계만 저장한다.
15. `SemionGame`은 경기 시작 시 `WaveConfig`를 스냅샷으로 고정한다. `SemionGameManager.reloadConfigs`가 성공해도 진행 중인 경기의 웨이브 설정은 바꾸지 않고 다음 경기부터 사용한다.
16. `EconomyService.awardMonsterKillReward`의 첫 조건에서 보상 0인 `NATURAL_WAVE`만 조기 반환하지 않게 한다. 이후 기존 단일 경로가 0다이아 지급, 현재 처치자의 처치 통계, `SemionJob.onMonsterKilled`와 `rewardGranted`를 각각 한 번 처리한다. 다른 보상 0 출처는 계속 제외하고, 주변 사망 알림은 현재 `PlayerLane`의 단일 호출을 유지한다.

인컴 Allay의 ID나 회복 Goal은 바꾸지 않는다. 현재 공용 회복 Goal은 같은 팀·레인이면 자연 웨이브와 인컴 유닛을 구분하지 않으며, 잃은 체력이 큰 순서로 고르지도 않는다. 그대로 재사용하면 후반 웨이브 계약을 지킬 수 없다.

소환 출처는 증강과 웨이브가 함께 쓰는 `Monster` 상태다. 자연 웨이브 회복 대상 필터와 텔레메트리는 `NATURAL_WAVE` 값을 사용한다. `BUILDER_PROXY`는 자연 웨이브 회복 대상, 자연 웨이브 보상 보정, 인컴 위협 지표와 유료 인컴 조건에서 제외하되 기존 라이벌 전투 규칙은 바꾸지 않는다. 자연 웨이브 ID를 인컴 `SummonRegistry`에 등록하지 않는다. 별도 이벤트 버스, 능력 스크립트 언어와 범용 웨이브 타임라인은 추가하지 않는다.

이번 H0에는 회복 감소 디버프를 구현하지 않는다. 이후 빌더에 회복 감소를 추가할 때는 기존 `TimedEffectSet`에 몬스터의 받는 회복 감소 효과 하나를 추가하고, `SemionMonsterEntity.receiveHealing`에서 한 번만 적용한다. 각 회복 Goal에 별도 감소 공식을 넣지 않는다. 처리 순서는 `요청 회복량 → 회복 감소 적용 → 잃은 체력 상한 적용`이다. 요청량과 감소 적용 뒤 회복량의 차이를 회복 감소량으로, 감소 적용 뒤 회복량과 실제 유효 회복량의 차이를 초과 회복량으로 기록한다.

### 7.3 설정 계약

`RoundWaveConfig`에는 다음 두 선택 항목을 추가한다.

- `templateId`: 무한 웨이브 템플릿을 로그와 카나리 대상으로 구분하는 안정 ID다. 무한 웨이브 세 템플릿에서는 필수이며 서로 달라야 한다.
- `mineralRewardBudget`: 플레이어 레인당 기본 보상 예산이다. 값이 없으면 하위 호환성을 유지하기 위해 `count × mineralReward`의 합계를 사용한다.

`WaveConfig`의 `infiniteCountMultipliers`는 시작 라운드 문자열을 키로, 배율을 값으로 쓰는 맵이다. H0는 `{"20": 1.20, "25": 1.30}`을 사용한다. 값이 없으면 `1.00`을 사용한다.

회복 수치는 `WaveMonsterEntry.healing`에 둔다. H0에 필요한 필드는 아래 여섯 개뿐이다.

```json
{
  "radius": 6.0,
  "amount": 80.0,
  "maxTargets": 3,
  "cooldownTicks": 160,
  "retryDelayTicks": 20,
  "maxSuccessfulCasts": 2
}
```

위 예시는 R16 값이다. R20 무한 웨이브의 기준 `amount`는 160이다. R20 이상에서는 `scaleInfiniteEntry`가 `amount`에도 기존 체력 배율을 한 번 적용한다. 대상 필터, 우선순위와 50% 부상량 조건은 설정으로 열지 않고 5.4절 규칙으로 고정한다.

`WaveConfig.validate()` 한 곳에서 `infiniteTemplates()`의 빈 `templateId`와 중복 `templateId`, 음수 보상 예산, 1.00 미만이거나 1.50을 넘는 수량 배율, 유한하지 않거나 양수가 아닌 회복 수치와 0 이하 정수 필드를 거절한다. 수량 배율의 키는 양의 정수 라운드로 변환할 수 있고 `infiniteFromRound` 이상이어야 한다.

서버 시작 때 설정을 읽지 못하면 번들 기본값을 사용한다. `/semiontd reload`에서는 기본값으로 대체하지 않는 웨이브 전용 후보 읽기를 한 뒤 `WaveConfig.validate()`를 호출한다. 성공한 설정은 관리자 기본값과 다음 경기부터 사용하고, 진행 중인 경기는 경기 시작 때 고정한 `WaveConfig`를 유지한다. 다른 설정 형식까지 바꾸는 범용 리로드 프레임워크는 만들지 않는다.

## 8. 검증과 출시

### 8.1 자동 검증

- R1~R4 수량이 기존과 같은지 확인한다.
- R5~R14, R16~R24, R25 이상의 목표 총수와 구성비 반올림을 확인한다.
- R15가 Warden 4기인지 확인한다.
- 각 라운드의 기본 처치 보상 합계가 기존 예산과 같은지 확인한다.
- 보상 0인 자연 웨이브 유닛도 처치 진행도와 주변 사망 효과를 각각 한 번만 발동하는지 확인한다.
- 같은 시드가 같은 무한 웨이브 템플릿과 같은 순서를 만드는지 확인한다.
- R1~R19 고정 웨이브 중 R16에만 회복 유닛이 정확히 한 기 있는지 확인한다.
- R16 기술 카나리에서 전투 유닛 32기 뒤, 수량 H0에서 39기 뒤에 회복 유닛이 들어가는지 확인한다.
- 후반 회복 유닛이 확장 큐의 55% 지점에 한 번만 들어가는지 확인한다.
- 회복 대상 우선순위와 인컴·보스·다른 회복 유닛·다른 레인·사망·누수 제외를 확인한다.
- 초과 회복과 부활이 없고, 성공 160틱·실패 20틱·성공 2회 상한을 지키는지 확인한다.
- 선택한 대상의 회복 가능한 부상량 합계가 50% 기준 미만이면 시전 횟수를 쓰지 않고 `INSUFFICIENT_INJURY`를 기록하는지 확인한다. 기준과 같은 값에서는 시전한다.
- 유효 회복 합계가 0인 시전은 실패인지 확인한다. 향후 회복 감소를 적용해도 부상량 조건은 감소 전 요청량으로 계산하고, 회복 결과가 0이면 성공 횟수를 쓰지 않아야 한다.
- 재접속이나 엔티티 재생성으로 시전 횟수와 재사용 대기시간이 초기화되지 않는지 확인한다.
- 자연 웨이브 큐는 `NATURAL_WAVE`, 라이벌 프록시는 `BUILDER_PROXY`를 받는지 확인한다. 프록시가 회복 대상이나 자연 웨이브 보상·인컴 위협 지표에 들어가지 않아야 한다.
- 무한 웨이브 능력치 배율을 적용한 뒤에도 `templateId`, `mineralRewardBudget`과 `healing`이 남는지 확인한다.
- 잘못된 웨이브 설정은 관리자 기본값과 진행 중인 경기 모두에 적용되지 않는지 확인한다. 유효한 설정도 진행 중인 경기에는 적용되지 않고 다음 경기부터 쓰이는지 확인한다.

### 8.2 필수 텔레메트리

- `catalog_version`, 라운드, 선택된 웨이브 `templateId`
- 설정 수량, 실제 출현 수량과 출현 완료 시각
- 라운드 시작 총체력과 물리·마법 구성
- 회복 유닛 ID, 총 시도 횟수, 성공 시전 횟수, 실패 사유별 횟수(`NO_ELIGIBLE_TARGET`, `INSUFFICIENT_INJURY`, 유효 회복 0), 적격 대상 수와 선택한 대상의 회복 가능한 부상량 합계, 요청 회복량, 회복 감소량, 초과 회복량, 실제 유효 회복량
- 전투 시간, `cleared`, 누수, 타워 사망, 60초 진입, 90초 최종 방어 진입

- 소환 출처별 처치 수와 `natural_wave_kill_count`
- 처치 성장 상태의 웨이브당 증가량과 상한 도달 라운드·틱
- 사망·피격 발동이 만든 추가 피해량과 추가 처치 수
- 자연 웨이브 기본 처치 보상 예산과 실제 지급 합계

### 8.3 통과선과 롤백선

시험 카탈로그를 직전 대조 카탈로그와 비교한다. 두 카탈로그는 `NORMAL` 모드와 `augment_version`을 포함한 증강 규칙이 같아야 하며, 이번에 시험하는 웨이브 항목만 달라야 한다. 같은 라운드와 템플릿부터 비교하고 빌더 구성도 함께 확인한다. 후반 도달 라운드가 다른 표본을 합쳐 난도 변화로 해석하지 않는다.

지표는 다음 단위로 계산한다.

- 완막률: 이 문서에서 정의한 완막 조건을 만족한 참가자-라운드 수를 해당 웨이브를 실제로 받은 참가자-라운드 수로 나눈다.
- P95 전투 시간: `(match_id, player_id, round_number)`로 중복을 제거한 `combat_seconds`의 95백분위수다.
- 60초 이상 전투 비율: `combat_seconds ≥ 60`인 참가자-라운드 수를 전체 참가자-라운드 수로 나눈다.
- 90초 최종 방어 진입률: `(match_id, round_number)`로 중복을 제거한 뒤 `wave_duration_seconds ≥ 90`인 경기-라운드 수를 해당 웨이브가 열린 경기-라운드 수로 나눈다. 공용 라운드 시간이므로 참가자 수로 가중하지 않는다.
- 타워 사망률: `tower_death_count` 합계를 `tower_count_start` 합계로 나눈다. 시작 타워 수가 0인 행은 제외한다.
- 회복 비율 `h`: 회복 유닛이 나온 레인·라운드의 실제 유효 회복량 합계를 같은 표본의 웨이브 시작 최대 체력 합계로 나눈다. 누수한 유닛에 준 회복도 포함하므로 플레이어의 추가 처치 부담이나 방어력 환산 EHP로 해석하지 않는다. 회복 유닛 교체만 시험할 때는 시작 최대 체력과 방어력 분포가 같지만 공격·이동 규칙의 차이는 남는다.
- 광역·단일 대상 완막률 격차: `total_damage_dealt > 0`인 표본에서 `area_damage_dealt / total_damage_dealt`가 50% 이상인 참가자-라운드를 광역, 20% 이하를 단일 대상으로 분류한다. 중간 표본은 제외한다. `gap = abs(광역 완막률 - 단일 대상 완막률)`, `Δ = 시험 카탈로그의 gap - 대조 카탈로그의 gap`으로 계산한다. 두 집단 중 하나라도 참가자-라운드 20건 미만이면 이 지표는 보류다.
- 처치 성장률: 해당 빌더의 웨이브당 진행도 증가량을 자연 웨이브 시작 총체력으로 나누고 10,000을 곱한다. 시험값과 대조값의 상대 변화율을 비교한다. 대조값이 0인데 시험값이 양수면 즉시 롤백한다. 상한이 있는 상태는 두 표본 모두 상한에 도달했을 때 최초 도달 라운드도 비교하고, 그렇지 않으면 성장률만 판정한다.
- 사망·피격 발동 피해 비율: 해당 발동이 만든 추가 피해를 `total_damage_dealt`로 나눈다. 시험 비율에서 대조 비율을 빼 변화 `Δ`를 구한다.

| 지표 | 통과 | 보류 | 즉시 롤백 |
|---|---:|---:|---:|
| 완막률 변화 `Δ` | `-5%p < Δ < +5%p` | `-8%p < Δ ≤ -5%p` 또는 `Δ ≥ +5%p` | `Δ ≤ -8%p` |
| P95 전투 시간 증가율 `Δ` | `Δ ≤ 15%`이고 P95 55초 미만 | `15% < Δ < 25%` 또는 `Δ ≤ 15%`이고 P95 55초 이상 | `Δ ≥ 25%` |
| 60초 이상 전투 비율 변화 `Δ` | `Δ ≤ +3%p` | `+3%p < Δ < +10%p` | `Δ ≥ +10%p` |
| 90초 최종 방어 진입률 변화 `Δ` | `Δ ≤ +3%p` | `+3%p < Δ < +10%p` | `Δ ≥ +10%p` |
| 타워 사망률 변화 `Δ` | `Δ ≤ +3%p` | `+3%p < Δ < +5%p` | `Δ ≥ +5%p` |
| 회복 비율 `h` | 무대응 내부 목표 `6% ≤ h ≤ 10%`. 공개 경기의 낮은 값은 대응 성공 여부로 판정 | 무대응 내부 시험 `h < 6%` 또는 `10% < h < 12%` | `h ≥ 12%` 안전 경보 |
| 광역·단일 대상 완막률 격차 변화 `Δ` | `Δ ≤ +5%p` | `+5%p < Δ < +10%p` | `Δ ≥ +10%p` |
| 처치 성장률 상대 변화 `Δ` | `abs(Δ) ≤ 10%`이고 상한 도달 시점이 대조와 같거나 늦거나, 최대 1라운드 빠름 | `10% < abs(Δ) < 20%` 또는 2라운드 빠름 | `abs(Δ) ≥ 20%` 또는 3라운드 이상 빠름 |
| 사망·피격 발동 피해 비율 변화 `Δ` | `Δ ≤ +3%p` | `+3%p < Δ < +8%p` | `Δ ≥ +8%p` |

표의 경계는 H0 운영 기준이며 통계적으로 확정한 밸런스 법칙은 아니다. 해당 시험에 적용되는 지표가 통과하고 5.6절의 대응을 재현한 뒤 다음 단계로 간다. 회복 유닛이 없는 시험의 `h`처럼 적용 대상이 아닌 지표는 `N/A`로 적는다. 적용 지표를 수집하지 못했거나 비교할 표본이 부족하면 `미측정/표본 부족`으로 보류한다. 누락된 값을 0이나 통과로 바꾸지 않는다.

낮은 `h`만으로 회복량을 올리지 않는다. 6절에 따라 원인을 구분하고 한 번에 가설 하나를 시험한다. 회복 감소가 한 번이라도 적용된 레인·라운드는 기본 회복량 판정에서 제외한다. 즉시 롤백 경계에 들어가면 해당 단계를 되돌리고 측정 오류 여부를 확인한다. 여러 지표가 다른 구간에 걸리면 가장 강한 조치를 따른다.

시험 카탈로그와 대조 카탈로그의 모집 목표는 각각 `NORMAL` 10경기와 해당 참가자-라운드 100건이다. 같은 경기의 참가자는 조건을 공유하므로 100건을 독립 표본 100개로 취급하지 않는다. 이 목표를 채워도 통계적 유의성을 보장하지 않으며, 같은 라운드·템플릿·빌더 비교에 필요한 표본이 없으면 다음 단계를 보류한다. 복제, 무한 회복, 보상 중복 등 안전 결함은 모집 완료를 기다리지 않고 즉시 중단한다.

| 시험 | 표본에 넣는 라운드 |
|---|---|
| R16 기술 카나리 | R16만 |
| 수량 H0 | R5~R14, R16~R24, R25 이상을 각각 판정 |
| 후반 회복 유닛 | 해당 카탈로그에서 회복 유닛을 새로 적용한 템플릿이 선택되고 회복 유닛이 나온 라운드만. `templateId`별로 각각 판정 |
| R25 이상 `×1.40`, `×1.50` | R25 이상만 |

빌더별 판정에는 표본이 부족하므로 사용 가능한 모든 빌더를 관리자 강제 조합 테스트로 먼저 확인한다.

처치 성장이나 사망 발동이 있는 빌더는 공개 수량 승격 전에 빌더별 참가자-라운드 20건을 확보한다. 표본이 모이지 않으면 해당 수량 단계는 보류한다.

### 8.4 카탈로그 순서

1. 소환 출처와 회복·긴 전투 텔레메트리를 배포한다.
2. 관리자 강제 제안으로 무증강, 피해 중심, 방어 중심, 인컴 중심 증강 조합의 내부 기준선을 각각 수집한다. 공개 무작위 풀의 선행조건을 충족하기 전에는 선택률 밸런스를 판정하지 않는다.
3. 증강 명세의 `SAFE`와 희귀도별 카드 수 조건을 충족한 뒤 공개 무작위 증강을 열고, 기존 웨이브에서 공개 기준선을 수집한다.
4. 수량을 유지한 R16 회복 유닛을 기술 카나리로 공개한다.
5. 같은 네 조합에 수량 H0를 강제 적용해 기능과 명백한 실패만 내부 검증한다.
6. 수량 H0만 공개 적용한다.
7. `overworld_assault` 후반 회복 유닛을 연다.
8. 별도 카탈로그에서 `animal_stampede` 회복 유닛을 연다.
9. 다시 별도 카탈로그에서 `zombified_legion` 회복 유닛을 연다.
10. 추가 난도가 필요한 경우에만 R25 이상 수량 `×1.40`, 이후 `×1.50`을 한 단계씩 검증한다. 전투만 길어지면 이전 단계에서 멈춘다.

수량, 회복 유닛과 증강 피해 수치는 같은 카탈로그에서 함께 바꾸지 않는다. 한 단계가 롤백선을 넘으면 해당 단계만 되돌린다.

### 8.5 재미와 이해도 확인

5.6절의 두 대응을 실제 클라이언트 전투에서 확인한다. 테스트 진행자는 첫 R16 전에 설명을 덧붙이지 않고 미리보기와 이름표만 보여 준 뒤 다음을 관찰한다.

- 플레이어가 회복 유닛과 남은 시전 횟수를 알아보는가?
- 다음 시도에서 배치나 투자 판단을 바꾸고, 줄어든 회복 또는 막아 낸 두 번째 시전을 확인하는가?
- 플레이어가 실패 이유를 설명하는가, 아니면 적 체력이 이유 없이 되차거나 전투만 길어졌다고 느끼는가?

플레이어가 대응을 바꾸지 못하거나 변화의 결과를 알아보지 못하면 수치 승격을 보류한다. 자동 테스트와 `h` 목표 달성만으로 이 검증을 대체하지 않는다.
