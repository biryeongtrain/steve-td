# 세미온 TD 시즌 3 증강 시스템 명세

> 기준일: 2026-09-05 · 기준 브랜치: `s3-release` · 적용 모드: `NORMAL` · 상태: 로컬 구현·통합 검증 중. 운영 배포와 공개 풀 활성화는 미승인이다.

이 문서는 시즌 3의 증강 선택, 카드 효과, 구현과 검증 규칙을 정의한다. 증강 화면과 입력은 [시즌 3 증강 GUI 상세 명세](./2026-09-04-season-3-augment-gui-design.ko.md)를 따른다. 증강과 관련해서는 이 문서가 [시즌 3 출시 기획안](./2026-09-01-season-3-release-design.ko.md)의 관련 내용을 모두 대체한다. 웨이브 수량과 자연 웨이브 회복 유닛은 [시즌 3 웨이브 명세](./2026-09-04-season-3-wave-design.ko.md)를 따르고, 공성 인컴과 빌더 밸런스는 출시 기획안을 따른다.

신규 개발자는 1~5절에서 시스템 전체 규칙을 먼저 확인한다. 카드 구현자는 6~10절을 읽고 11절에서 검증 절차를, 12절과 부록에서 설계 근거를 확인한다.

구현 범위는 기존 22장과 [2차 증강 10장](./2026-09-05-season-3-augment-candidates-2.ko.md), [타워형 증강 5장](./2026-09-05-season-3-tower-augment-design.ko.md)에서 `명예 퇴역`과 `과밀 허가`를 뺀 일반 후보 35장이다. 두 제외 카드는 설계 이력으로만 남기며 관리자 강제 제안으로도 구현하지 않는다.

공격형 전용 타워는 거인 사냥꾼, 축전 초소, 매복 작업장, 별빛 고치, 군수공장 5종을 승인했다. 비공격형 4종을 합쳐 전용 타워는 9종이다. 후보 부족용 예비 보상 9장을 더해 구현 카탈로그는 총 44장이다. 예비 보상은 일반 추첨 풀에 넣지 않는다.

## 1. 시스템 한눈에 보기

증강은 한 경기 동안 플레이어의 타워 운용이나 인컴 구매 규칙을 바꾸는 선택 효과다. 생존 플레이어는 R5, R15, R25의 준비 단계에서 각각 한 장씩, 최대 세 장을 고른다.

기존 `TraitLoadout` 코드와 과거 기록은 보존한다. 시즌 3 `NORMAL`에서는 경기 전 특성을 선택하거나 적용하지 않고, 경기 도중 증강만 최대 세 장 고른다. 증강 상태를 `TraitLoadout`에 넣지 않으며 효과 적용 경계만 재사용한다.

### 현재 결정된 범위

| 항목 | 결정 |
|---|---|
| 선택 횟수 | R5, R15, R25에 한 번씩, 최대 3회 |
| 한 번에 보는 카드 | 같은 희귀도의 개인별 카드 3장 |
| 리롤 | 경기당 1회. 선택한 카드 칸 한 장만 교체 |
| 건너뛰기 | 허용. 시간 초과도 `SKIPPED`로 처리 |
| 희귀도 | 실버, 골드, 프리즘 |
| 일반 후보 | 실버 10장, 골드 15장, 프리즘 10장, 총 35장 |
| 예비 보상 | 등급별 3계열, 총 9장. 후보 부족 때만 사용 |
| 공개 상태 | `enabled=false`, `publicPoolEnabled=false`가 기본값. 내부 시험과 공개 활성화는 별도 |

7절의 기본 18장과 8절의 확장 4장은 초안 작성 당시의 묶음 이름이다. 현재 구현 수는 위 표를 기준으로 센다. 수치는 내부 비교 시험의 시작값이며, 구현 승인은 운영 밸런스나 공개 승인이 아니다.

`SAFE` 후보가 부족하면 즉시 다이아를 보장한다. 같은 희귀도가 세 번 나오거나 이전 선택의 계보·충돌 때문에 후보가 줄어도 아래 예비 보상 규칙으로 세 칸을 채운다.

### 한 경기의 처리 흐름

| 시점 | 서버 처리 | 플레이어가 보는 것 |
|---|---|---|
| 경기 시작 | 희귀도 세 개의 조합과 순서를 한 번 뽑아 경기 상태에 저장 | 이번 경기의 희귀도 순서 |
| R5 준비 단계 | 생존 플레이어마다 해당 희귀도의 적격 카드 3장을 생성하고 먼저 저장 | 카드 3장, 리롤, 건너뛰기 |
| 카드 선택 | 대상과 비용을 다시 검사한 뒤 선택과 부가 상태를 한 번만 저장 | 효과, 대가, 적용 대상 확인 화면 |
| 웨이브 시작 | 배치와 대상 조건을 스냅샷하고 전투 효과 적용 | 이름표, 연결선, 진행도 |
| R15, R25 | 같은 절차 반복 | 누적 선택 최대 3장 |
| R5 중도 참여 | `requestedRound=5`이면 놓친 R5 선택을 예약하고 첫 준비 단계에 제안 | R5 카드 3장, 리롤, 건너뛰기 |
| 재접속 | 같은 서버 프로세스의 경기 상태에서 제안과 선택을 복원 | 닫기 전과 같은 선택 화면 또는 현재 효과 |

기존 준비 25초 앞에 에메랄드 자동 생산이 멈추는 증강 선택 30초를 추가한다. 선택 시간 안에 확정하지 않으면 서버가 해당 선택을 `SKIPPED`로 기록한다. 이후 일반 준비 25초 동안 생산을 재개한다. 최소 지원 범위는 같은 서버 프로세스에서 진행 중인 경기의 재접속이다. 서버 재시작 뒤 경기 복구는 경기 영속화를 추가할 때 별도로 설계한다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 빌더 | 플레이어가 고른 직업 또는 타워 계열. 설치 가능한 타워와 고유 규칙을 결정한다. |
| 보드 | 한 플레이어 레인에 배치한 영구 타워 구성과 위치다. |
| 준비 단계 | 타워를 배치·승급·판매하고 인컴을 구매하는 `PREPARE_AND_SUMMON` 단계다. |
| 전투 단계 구매 | 웨이브 도중 다음 라운드 소환을 예약하는 `LANE_WAVE` 거래다. 증강의 준비 단계 구매로 세지 않는다. |
| 다이아 | 타워 배치와 승급에 쓰는 자원이다. 정기 인컴으로 반복 지급된다. |
| 에메랄드 | 상대 팀에 인컴 유닛을 보낼 때 쓰는 자원이다. |
| 인컴 | 에메랄드를 내고 상대에게 유닛을 보내며 자신의 정기 다이아 지급량을 올리는 거래다. |
| 공격형 인컴 | 상대 타워를 직접 공격해 압박하는 유닛이다. |
| 유틸 인컴 | 같은 목표 팀·레인의 자연 웨이브와 인컴 유닛을 회복하거나 보호막·강화 효과를 주는 지원 유닛이다. |
| 표준 공격형 인컴 | 최대 체력과 기본 공격만으로 싸우며 별도 전투 능력이 없는 공격형 인컴이다. 적용 가능한 유닛 목록은 카드 화면에 표시한다. |
| 일반 영구 타워 | 프로덕션 카탈로그에서 배치돼 라운드 사이에도 남고, 소유자의 `PlayerLane.towers()`에 등록되며, 판매 가능하고 실제 타워 슬롯을 쓰는 타워다. 직업 핵심, 임시·복제, 합성 재료, 스킬 제단과 슬롯 가중치 0인 부속물은 제외한다. |
| 파괴 | 전투 중 타워 체력이 0이 된 상태다. 일반 타워는 다음 라운드에 복구된다. |
| 제거 | 판매, 퇴역, 교체처럼 타워가 보드에서 빠지는 처리다. 다음 라운드에 돌아오지 않는다. |
| 전용 타워 설계도 | 카드를 고른 뒤 타워 설치 목록에 유료 증강 타워를 추가하는 보상이다. |
| 호출 | 무료 배치권 한 장을 지급하는 보상이다. 배치에 성공할 때만 배치권을 소비한다. |
| 패키지 | 여러 보상을 한 번에 지급하는 묶음이다. 현재 카드 풀에는 무작위 패키지가 없다. 결과를 뽑은 뒤 플레이어가 할 판단이 적어서 제외했다. |
| 기본 후보 | 첫 구현 대상으로 남긴 18장이다. 출시 확정 카드라는 뜻은 아니다. |
| 확장 후보 | 추가 검토 대상으로 남긴 4장이다. 기본 후보와 분리해 단독 검증한다. |
| 재설계 보류 | 보상과 대가가 의도한 재미를 만들기 어렵다고 판단한 카드다. 무작위 풀에서는 제외하고 반례 비교에만 쓴다. |
| H0 | 첫 플레이테스트에서 반증할 시작 수치다. 라이브 확정값이 아니다. |
| 안정 ID | 저장, 충돌과 텔레메트리에 쓰는 변경하지 않는 카드 식별자다. 화면 이름은 바꿔도 안정 ID는 유지한다. |
| 적격 | 현재 빌더, 보드, 라운드와 이전 선택을 기준으로 카드를 제시하거나 효과를 적용할 수 있는 상태다. |
| `familyKey` | 같은 계보에 속한 카드를 묶는 키다. 같은 키의 카드는 한 경기에서 하나만 선택한다. |
| 하드 충돌 | 두 카드를 같은 경기에서 선택하지 못하게 하는 규칙이다. |
| `SAFE` | 제안에서 가장 이해하기 쉬운 선택지로 쓰는 카탈로그 플래그다. 즉시 사용할 수 있고 선택만으로 영구 손실이 없는 카드 중 일부를 지정하며, 제안 세 장에 최소 한 장을 넣는다. |
| `SKIPPED` | 플레이어가 건너뛰었거나 제한 시간 안에 고르지 않은 선택 결과다. 카드 효과는 없다. 내부 사유는 `EXPLICIT`과 `TIMEOUT`으로 나눠 기록한다. |
| `offerRevision` | 서버가 제안을 만들거나 바꿀 때 올리는 버전 번호다. 오래된 화면에서 보낸 선택 요청을 거절하는 데 쓴다. |
| 요청 식별자 | 서버가 일회성 버튼을 만들 때 발급해 명령에 넣는 `requestId`다. 같은 요청을 두 번 처리하지 않는 데 쓴다. |
| `NORMAL_PAID` | 에메랄드를 실제로 지불한 정상 인컴 소환이다. |
| `FREE_AUGMENT` | 증강이 만든 무료 소환이다. 비용, 인컴, 처치 보상과 판매가를 만들지 않는다. |
| `ECHO` | 다른 소환을 본떠 만든 무보상 메아리다. 비용, 인컴, 처치 보상과 다른 증강 발동을 만들지 않는다. |
| `NATURAL_WAVE` | `wave.json`에서 생성한 자연 웨이브다. 발신자와 구매 거래가 없으며 유료 인컴 조건을 만족하지 않는다. |
| `BUILDER_PROXY` | 빌더가 전투 규칙을 계산하거나 별도 적 개체를 만들 때 쓰는 비구매 개체다. 자연 웨이브와 유료 인컴 조건을 만족하지 않는다. |
| 출처 기반 효과 | 효과를 카드 ID 같은 출처 키로 저장하는 방식이다. 여러 출처는 함께 적용되고 한 출처를 지워도 나머지는 유지된다. |
| 타워 누적 실결제 다이아 | 해당 타워의 배치와 승급에 실제로 차감한 다이아의 누계다. 무료·할인 금액은 제외하고 정상 승급 시 이어받는다. |
| 인컴 실결제 에메랄드 | 한 번의 정상 소환 거래에서 실제로 차감한 에메랄드다. |
| `augment_version` | 카드 ID, 희귀도·카테고리·상태, 효과·수치, 적격·충돌 규칙 또는 제안 확률·알고리즘이 바뀌면 갱신하는 증강 규칙 버전이다. |
| `catalog_version` | 타워, 인컴, 웨이브, 경제와 `augment_version`을 함께 식별하는 전체 게임 카탈로그 버전이다. 단계별 공개 때마다 새 값을 사용한다. |
| 같은 종류·티어 | `(towerTypeId, catalogTier)` 두 값이 모두 같은 타워다. |
| 유효 지원 | 잃은 체력을 1 이상 회복하거나 새 보호막·강화 효과를 처음 적용한 사건이다. 초과 회복과 지속 시간 갱신은 세지 않는다. |

카드 이름 `금지된 설계도`는 고유명사다. 위 표의 `전용 타워 설계도`와 달리 타워를 해금하지 않는다.

## 3. 희귀도와 카테고리

### 희귀도가 뜻하는 것

| 희귀도 | 설계 기준 | 대표 판단 |
|---|---|---|
| 실버 | 작고 이해하기 쉬운 이득을 준다. | 대상이나 진형 선택 |
| 골드 | 실버보다 큰 이득이나 새로운 조합 기회를 준다. | 타이밍, 역할, 성장 관리 |
| 프리즘 | 핵심 타워나 편성 전체에서 강한 변화를 체감하게 한다. | 강한 계보 효과 또는 운영 전환 |

희귀도는 영향력의 등급이지 조작 난도의 등급이 아니다. 계보형은 같은 규칙을 더 강하게 만들고, 등급 고유형은 새로운 운영을 연다. 프리즘에도 간단하고 강한 카드가 있을 수 있다. 대가형은 같은 등급의 무대가 카드보다 유리해지는 상황이 분명해야 한다.

### 다섯 카테고리

모든 카드는 주 카테고리 하나를 갖는다. 충돌 태그는 별도로 관리한다.

| 카테고리 | 카드가 바꾸는 것 | 피해야 할 결과 |
|---|---|---|
| 범용 | 별도 숙제 없이 쓰는 강화, 지킬 타워, 진형, 전투 계획 | 모든 보드에서 다른 선택을 압도하는 수치 |
| 대가형 | 큰 보상과 영구 손실의 교환 | 판매나 후방 배치로 없앨 수 있는 가짜 손실 |
| 전용 타워 | 기존 타워를 보조할 새 위치와 슬롯 | 빌더 대신 공격을 맡는 만능 타워 |
| 게임 체인저 | 타워 역할이나 보드 규모 | 빌더별 예외가 카드 효과보다 긴 규칙 |
| 인컴 | 구매 비용, 지원, 출현 시점, 압박 강도 | 무료 소환 재귀와 일방적인 경제 이득 |

## 4. 카드 선택 규칙

### 4.1 희귀도 추첨

경기 시작 시 아래 조합 하나를 뽑는다. 모든 플레이어가 같은 희귀도 조합과 R5·R15·R25 배치 순서를 공유한다. 실제 카드 3장은 플레이어별로 다르게 뽑는다.

| 희귀도 조합 | 확률 |
|---|---:|
| 실버·실버·실버 | 3% |
| 실버·실버·골드 | 14% |
| 실버·골드·골드 | 23% |
| 골드·골드·골드 | 18% |
| 실버·골드·프리즘 | 22% |
| 골드·골드·프리즘 | 11% |
| 골드·프리즘·프리즘 | 7% |
| 프리즘·프리즘·프리즘 | 2% |

확률 합계는 100%다. 혼합 조합은 세 희귀도를 마일스톤에 무작위로 배치한다.

### 4.2 제안 카드 3장 생성

제안 대상은 마일스톤 준비 단계에 살아 있는 플레이어다. 서버는 아래 순서로 후보를 줄인다.

1. 해당 마일스톤의 희귀도와 출현 라운드가 맞는 카드를 고른다.
2. 현재 빌더와 보드에서 대상이 없는 카드를 제외한다.
3. 이미 선택한 카드와 `familyKey`가 같거나 하드 충돌 관계인 카드를 제외한다. 제안 내 카드 ID와 같은 계보는 중복하지 않는다. 세 장 중 한 장만 고르므로 제안끼리는 하드 충돌해도 된다.
4. 가능하면 서로 다른 카테고리에서 한 장씩 고른다.
5. 선택 즉시 영구 손실이 없는 `SAFE` 카드 한 장을 포함한다.
6. 대가형과 불가역 게임 체인저는 합쳐서 한 제안에 최대 한 장만 넣는다.
7. 카드 ID를 정렬한 뒤 저장된 경기 시드, 플레이어 UUID, 마일스톤, 리롤 횟수와 카드 칸으로 섞는다.
8. 최종 카드 3장을 서버 상태에 저장한 뒤 UI를 연다.

대상이 필요한 카드는 현재 적격 대상이 하나 이상일 때만 제시한다. `SAFE` 여부는 카드 카탈로그의 고정 메타데이터로 관리한다.

유효 후보가 세 장보다 적거나 안전한 후보가 없을 때만 같은 등급의 예비 보상을 사용한다.

| 예비 보상 | 실버 | 골드 | 프리즘 |
|---|---:|---:|---:|
| 즉시 다이아 | 60 | 120 | 240 |
| 정기 인컴 증가 | +10 | +20 | +40 |
| 기본 에메랄드 생산 증가 | +1 | +2 | +3 |

한 제안 안에서는 예비 보상도 중복하지 않는다. 다른 마일스톤의 반복 선택은 예비 보상만 허용한다. 안전한 후보가 없으면 즉시 다이아 한 칸을 보장한다. 정기 인컴은 기존 지급 감소와 부채 정산을 거친다. 생산 보너스는 업그레이드 횟수·가격·상한과 분리하고 기존 R25 생산 배율을 받는다.

### 4.3 선택, 리롤, 건너뛰기

- 플레이어는 경기당 한 번, 선택한 카드 칸 한 장만 리롤할 수 있다. 다른 두 칸의 카드와 희귀도는 유지한다.
- 교체 카드는 이번 마일스톤에서 이미 본 카드, 현재 부적격 카드와 이전 선택에 충돌하는 카드를 제외한다. 보존한 두 카드와는 ID·계보 중복만 막고 하드 충돌은 허용한다. 교체 뒤에도 `SAFE` 최소 한 장과 대가형·불가역 게임 체인저 합계 최대 한 장을 지킨다. 저장된 시드와 같은 입력값에서 항상 같은 카드가 나오도록 남은 후보 한 장을 골라 같은 칸에 넣는다.
- 고른 칸이 제안의 유일한 `SAFE` 카드이고 이를 대신할 유효한 `SAFE` 카드가 없으면 해당 칸을 리롤할 수 없다.
- 유효한 교체 카드가 없으면 리롤을 소비하지 않는다. 성공하면 같은 칸을 교체하고 `offerRevision`을 올리며 미확정 대상·모드 초안을 지운다.
- 플레이어는 카드를 고르지 않고 건너뛸 수 있다.
- 준비 단계가 끝나면 미확정 선택을 `SKIPPED`로 기록한다. 대가형, 전용 타워, 게임 체인저를 자동 선택하지 않는다.
- 전용 타워 카드는 한 플레이어가 경기당 한 장만 선택할 수 있다.
- 중도 참여자의 마일스톤 적격은 실제 합류가 끝난 라운드가 아니라 `requestedRound`로 판정한다. `requestedRound=5`인데 R5 제안을 받지 못했다면 `addLateParticipant`에서 R5 선택을 예약하고, 합류 뒤 처음 맞는 준비 단계에 같은 경기 희귀도로 제안한다. 전투 중에는 선택창을 열지 않는다.

### 4.4 공개 풀 하한

- 희귀도별 등록 카드가 8장 미만이면 무작위 제안을 열지 않는다.
- 빌더 적격성과 충돌을 적용한 뒤 현재 플레이어에게 유효한 카드가 최소 3장이어야 한다.
- 카드 칸별 리롤을 제공하려면 현재 제안 밖에 유효한 교체 카드가 한 장 이상 있어야 한다. 후보가 없는 칸은 리롤 버튼을 표시하지 않고 이유를 본문에 적는다.
- 카드가 부족해도 충돌을 풀거나 부적격 카드를 노출하지 않는다.
- 등록 수 8장은 충분조건이 아니다. 공개 전에는 같은 등급이 세 번 나온 경기, 이전 선택의 계보·충돌, 빌더별 대상 유무를 적용해 적격 세 장과 `SAFE`를 계속 제안할 수 있는지 검사한다.
- 내부 테스트에서는 관리자가 현재 경기의 해당 마일스톤 희귀도에 맞는 카드 세 장을 강제로 제시할 수 있다. 경기 공통 희귀도 순서는 바꾸지 않는다. 제외한 두 카드는 등록하지 않는다.

### 4.5 확정의 원자성

카드 확정 요청에는 `offerRevision`을 포함한다. 서버는 한 메서드 안에서 현재 단계와 라운드, `offerRevision`, 미선택 상태, 충돌, 대상과 가격을 다시 검사한다. 검사에 실패하면 카드, 자원, 이용권과 토글을 소비하지 않는다.

난수 결과와 예약 소환은 UI보다 먼저 서버 상태에 기록한다. 같은 거래 ID와 같은 라운드 정산을 두 번 적용하지 않는다.

## 5. 모든 카드에 적용하는 공통 규칙

### 5.1 효과 계산 순서

- 별도 `×배율`을 쓰지 않은 최종 피해 증가는 출처별 증가율을 더한 뒤 한 번 곱한다.
- 최대 체력 보너스가 바뀌면 현재 체력 비율을 유지한다.
- 받는 피해 감소는 모든 증강을 합쳐 50%에서 경보를 내고 60%에서 제한한다.
- `편향 장갑`은 기존 피해 감소 뒤에 적용한다. `전열 분업` 포대의 받는 피해 `×1.25`는 감소 상한 처리 뒤에 적용한다.
- `방벽 핵심`의 피해 전가는 최종 피격량을 계산한 뒤 처리한다. 방벽 핵심으로 전가된 피해는 다시 피해 전가를 발동하지 않는다.

### 5.2 카드 충돌

| 태그 또는 관계 | 함께 선택할 수 없는 카드 | 이유 |
|---|---|---|
| `TACTICAL_DESIGNATION` | 전술 지명 I, II, III | 상위 계보 중 하나만 사용 |
| `BOARD_CAPACITY` | 명예 퇴역 ↔ 과밀 허가 | 타워 한도 감소와 증가의 상쇄 방지 |
| `UPGRADE_CONTRACT` | 금지된 설계도 ↔ 다른 무료·할인 승급 카드 | 무료 승급 중복 방지 |
| `FUTURE_DIAMOND` | 비상 융자 ↔ 금지된 설계도 ↔ 현금 결제 | 미래 다이아를 여러 번 당기는 조합 방지 |
| `INCOME_BODY_CONTRACT` | 예고 공세 ↔ 저압 고수익 | 같은 인컴 몸체를 두 계약이 동시에 변경하는 문제 방지 |
| `FOCUS_OVERDRIVE` | 전술 지명 계보 ↔ 과열 코어 | 한 타워에 순간 화력 집중 방지 |

`현금 결제`는 `예고 공세` 또는 `저압 고수익`과 같은 경기에서 선택할 수 있다. 한 인컴 구매에는 계약 하나만 적용한다. `현금 결제` 토글을 켜면 `예고 공세` 토글을 끄고, 반대로도 동일하다. `저압 고수익`을 가진 상태에서 `현금 결제` 토글을 켜면 해당 구매의 저압 계약 선택을 잠근다. 저압 계약을 쓰려면 먼저 `현금 결제` 토글을 꺼야 한다. 구매 버튼에는 현재 적용될 계약 하나를 표시한다. `추가 적재`와 `지원 실적`은 인컴의 가치 계약을 바꾸지 않으므로 함께 적용할 수 있다.

`전열 분업`의 선봉과 포대는 전술 지명 대상이 될 수 없고 `삼각 진형` 효과도 받지 않는다. `쌍둥이 편대`와 `삼각 진형`은 함께 적용하며 출처 기반 합산 규칙을 따른다.

### 5.3 무료 효과, 판매, 파괴

- `FREE_AUGMENT`, `ECHO`, `NATURAL_WAVE`와 `BUILDER_PROXY`는 유료 인컴을 요구하는 증강의 구매 조건을 만들지 않는다. `FREE_AUGMENT`와 `ECHO`는 비용, 인컴, 처치 보상과 판매가도 만들지 않는다.
- 인컴은 생성할 때부터 소환 출처, 거래 ID, 인컴 실결제 에메랄드와 정상 다이아 인컴 증가량을 보존한다.
- 판매, 승급 교체와 임시 소멸은 긍정적인 타워 사망 효과를 발동하지 않는다.
- 증강 전용 타워가 파괴돼도 긍정적인 타워 사망 효과를 발동하지 않는다.
- `명예 퇴역`은 사망 경로가 아니라 정상 판매 경로를 사용한다.

### 5.4 상태 소유권과 재접속

| 소유자 | 저장할 상태 |
|---|---|
| `SemionGame` | 희귀도 순서, 경기 증강 시드, `augment_version`, `catalog_version`, 경기 시작 때 확정한 증강 설정 스냅샷 |
| `SemionPlayer` | 제안 카드, `offerRevision`, `deadlineTickExclusive`, 리롤, 선택 카드, 제안·설정 초안, `draftRevision`, `configurationRevision`, 카드별 `lastConfiguredRound`, 충돌 태그와 카드별 플레이어 상태 |
| `TowerDataKey` 기반 타워 상태 | 논리 타워 ID, 열화, 숙련 대상·스택·마지막 정산 라운드처럼 타워에 귀속되는 상태 |
| 인컴 개체 | 소환 출처, 거래 ID, 발신자, 인컴 실결제 에메랄드, 정상 다이아 인컴 증가량, 예약 라운드 |
| 웨이브 스냅샷 | 삼각 진형 대상, 쌍둥이 편대의 활성 라운드·타워 UUID, 중계기 연결과 편향 선택·잠금 라운드처럼 해당 웨이브에 고정할 상태 |

최소 지원 범위는 같은 서버 프로세스에서 진행 중인 경기의 재접속이다. 서버는 전술 지명 대상과 모드, 교전 계획, 융자 부채, 인컴 토글·소수 잔액·처리한 거래 ID, 예약 소환, 이용권, 역할 지정과 전용 타워 해금을 복원한다. 쌍둥이 편대는 활성 라운드와 타워 UUID, 전장 숙련은 대상·스택·마지막 정산 라운드, 편향 장갑은 현재 선택·잠금 라운드, 현금 결제는 토글·처리한 거래 ID를 복원한다. 미확정 카드와 제안 초안은 같은 `offerRevision`으로, 확정 카드의 설정 초안은 같은 `configurationRevision`으로 다시 연다.

## 7. 기본 후보 18장 상세

별도 출현 제한이 없는 카드는 해당 희귀도가 배정된 R5, R15, R25에 제시할 수 있다. 대상이 필요한 카드에 적격 대상이 없으면 후보에서 제외한다.

### 7.1 상위 계보: 전술 지명 I·II·III

- 희귀도·카테고리: 실버 I, 골드 II, 프리즘 III / 범용
- 제시 조건: 일반 영구 타워가 한 기 이상 있어야 한다.
- 효과: 준비 단계에서 타워 한 기와 `돌격` 또는 `엄호`를 고른다. 준비 단계마다 한 번 바꿀 수 있다.

| 카드 | 돌격 | 엄호 |
|---|---:|---:|
| 전술 지명 I | 최종 피해 +15% | 받는 피해 12% 감소 |
| 전술 지명 II | 최종 피해 +25% | 받는 피해 20% 감소 |
| 전술 지명 III | 최종 피해 +40% | 받는 피해 30% 감소 |

- 대가: 직접 비용은 없다. 한 타워에 돌격과 엄호를 함께 적용할 수 없다.
- 판정: 세 카드는 `familyKey=TACTICAL_DESIGNATION`을 공유한다. 증강 전용, 임시, 복제, 무적 타워는 대상이 아니다. 승급은 지명과 모드를 이어받는다. 대상이 제거되면 지명이 해제되며 다음 준비 단계에 새 대상을 골라야 한다. 전투 중 파괴는 지명을 지우지 않는다.
- 플레이: 이번 웨이브의 핵심 화력이나 가장 먼저 지켜야 할 타워를 정한다.
- UI: 카드와 타워 상세에 대상, 모드, 실제 증가·감소율을 표시한다. 부적격 대상을 누르면 제외 이유를 보여 준다.

### 7.2 실버: 삼각 진형

- 희귀도·카테고리: 실버 / 범용
- 제시 조건: 별도 조건 없음.
- 효과: 웨이브 시작 시 각 타워의 현재 위치를 스냅샷한다. 같은 플레이어 레인에서 반경 4블록 안에 다른 일반 영구 타워가 두 기 이상 있는 타워는 해당 웨이브 동안 최종 피해가 8% 증가하고 받는 피해가 8% 감소한다.
- 대가: 직접 비용은 없다. 밀집 배치는 적 광역 공격에 여러 타워를 노출한다.
- 판정: 웨이브 시작 시 한 번 계산한다. 증강 전용 타워와 슬롯 가중치 0인 부속물은 이웃 수에서 제외한다. 시작 뒤 이웃이 파괴돼도 효과는 웨이브 끝까지 유지한다.
- 플레이: 밀집 화력과 광역 피해 위험을 함께 계산한다.
- UI: 제안 화면에 현재 적격 타워 수를 표시한다. 웨이브 시작 시 적격 타워 사이에 짧은 연결선을 그리고 상세 화면에 적용 수치를 표시한다.

### 7.3 실버: 교전 계획

- 희귀도·카테고리: 실버 / 범용
- 제시 조건: 별도 조건 없음.
- 효과: 준비 단계마다 `속전` 또는 `지구전`을 고른다. 속전은 웨이브 시작 후 160틱 동안 일반 영구 타워의 최종 피해를 18% 높인다. 지구전은 160틱째부터 웨이브 끝까지 최종 피해를 10% 높이고 받는 피해를 10% 줄인다.
- 대가: 직접 비용은 없다. 고른 시간대 밖에서는 보너스를 받지 못한다.
- 판정: 증강 전용, 임시, 복제, 무적 타워는 제외한다. 모드를 바꾸지 않으면 직전 선택을 유지한다. 두 효과는 웨이브 종료 시 해제한다.
- 플레이: 직전 전투 시간과 다음 적 구성을 보고 초반 처치와 장기전 중 하나를 고른다.
- UI: 직전 웨이브 전투 시간과 각 모드의 발동 구간을 보여 준다. 기본 화력이 일정하고 두 구간 모두 계속 공격한다는 단순 모델에서는 22.4초가 피해량 손익분기점이다. 실제 공격 시작, 광역 피해와 적 회복에 따라 달라지므로 이를 추천 모드나 확정 피해 기댓값으로 표시하지 않는다.

### 7.4 실버: 비상 융자

- 희귀도·카테고리: 실버 / 대가형
- 제시 조건: R5와 R15에만 제시한다. 무한 웨이브에는 확정된 종료 라운드가 없으므로 앞으로 네 번 생존하거나 지급받을지를 적격 조건으로 검사하지 않는다.
- 효과: 선택 시점의 실제 정기 다이아 지급액을 `I`로 저장한다. `A = min(3I, 300)`다이아를 즉시 지급한다.
- 대가: 부채 `D = ceil(4A / 3)`를 만든다. 다음 네 번의 정기 지급에서 `ceil(남은 부채 / 남은 차감 횟수)`를 뺀다. 총 금융 비용은 수령액의 약 33%다.
- 판정: `I`는 현재 모드에서 허용하는 직업 보정을 적용하고 증강 부채를 빼기 전의 개인 지급액이다. 실제 정기 지급이 일어날 때만 차감 횟수를 줄인다. 차감 예정액이 지급액보다 크면 지급액까지만 차감하고 부족분은 남은 부채로 이월한다. 다섯 번째 이후에는 `min(남은 부채, 이번 지급액)`을 차감한다. 보유 다이아를 음수로 만들지 않는다. 탈락·경기 종료 시 미상환 부채는 경기 상태와 함께 닫으며 다른 경기로 넘기거나 별도 회수하지 않는다.
- 플레이: 핵심 배치나 승급을 앞당기는 대신 이후 운영 자금을 줄인다. 통상 네 번에 상환하지만 지급액이 부족하면 더 오래 걸린다.
- UI: `즉시 +240 / 총부채 320 / 예정 4회, 지급 부족 시 연장 / 다음 차감 80`처럼 실제 금액을 확정 전에 보여 준다.

### 7.5 실버: 접이식 방벽 설계도

- 희귀도·카테고리: 실버 / 전용 타워
- 제시 조건: 별도 조건 없음.
- 효과: 비용 160다이아, 최대 체력 180, 슬롯 1칸, 동시 설치 한도 1기인 비공격 방벽을 설치 목록에 추가한다. 같은 거리에서 공격 가능한 타워가 여럿이면 몬스터는 방벽을 먼저 노린다.
- 대가: 배치할 때 160다이아와 슬롯 1칸을 사용한다.
- 판정: 기존 타워 배치 조건과 정상 판매 환급 규칙을 따른다. 다음 웨이브에 체력을 모두 회복한다. 증강·특성 전투 버프, 무료 승급과 복제를 받지 않는다. 판매와 파괴는 긍정적인 타워 사망 효과를 발동하지 않는다.
- 플레이: 어느 공격 경로를 늦출지 보고 방벽 위치를 고른다.
- UI: 설치 전 비용, 슬롯, 체력과 현재 설치 수를 보여 준다. 타워 상세에 `비공격 / 우선 공격 대상 / 사망 효과 없음`을 표시한다.

### 7.6 실버: 추가 적재

- 희귀도·카테고리: 실버 / 인컴
- 제시 조건: 구매 가능한 유틸 인컴이 있어야 한다.
- 효과: 준비 단계마다 한 번 토글을 켤 수 있다. 다음 `NORMAL_PAID` 유틸 인컴의 최대 체력과 실제 회복·보호막 수치가 각각 35% 증가한다.
- 대가: 해당 유닛의 에메랄드 비용이 25% 증가한다. 소수 비용은 올림 처리하며 정상 다이아 인컴 증가량은 바뀌지 않는다.
- 판정: 성공한 구매만 토글을 소비한다. 실패한 구매 뒤에는 유지하고 준비 단계가 끝나면 해제한다. 무료 소환, 메아리와 보스에는 적용하지 않는다. `현금 결제`와 함께 적용할 수 있다.
- 플레이: 지원 유닛 수와 한 기의 생존·지원력 중 하나를 고른다.
- UI: 구매 버튼에 `비용 240 → 300 / 체력·지원 +35%`와 토글 만료 시점을 표시한다.

### 7.7 골드: 과열 코어

- 희귀도·카테고리: 골드 / 대가형
- 제시 조건: R5와 R15에만 제시한다. 과열 가능한 일반 영구 타워가 한 기 이상 있어야 한다.
- 효과: 각 준비 단계는 `이번 웨이브 미사용`으로 시작한다. 플레이어가 이번 준비 단계에 과열할 타워 한 기를 확정하고, 웨이브 시작 시 대상이 적격하면 해당 웨이브의 최종 피해가 40% 증가한다. 처음 카드를 고르면서 대상을 확정한 경우도 이번 웨이브 사용으로 센다.
- 대가: 효과를 받은 타워는 웨이브 종료 시 영구 `열화` 1스택을 얻는다. 열화 1스택마다 최종 피해가 6% 감소하며 최대 5스택까지 쌓인다.
- 판정: 이전 웨이브의 예약은 자동 유지하지 않는다. 미예약이면 보너스와 열화를 모두 적용하지 않는다. 예약 확정은 이번 준비 단계의 설정 기회를 소비한다. 열화 5스택 타워는 다시 과열할 수 없다. 승급은 열화를 이어받고, 제거되면 타워와 열화가 함께 사라진다. 자동 전역·순환·소멸 타워와 판매 보상 타워는 대상이 아니다. 웨이브 시작 전에 대상이 제거되면 효과와 열화를 적용하지 않는다.
- 플레이: 지금 막아야 할 웨이브를 위해 어느 타워의 미래 화력을 쓸지 정한다.
- UI: `다음 웨이브 +40% / 종료 후 영구 -6% / 현재 열화 2/5`를 대상 확정 전에 표시한다.

### 7.8 골드: 박동 중계기 설계도

- 희귀도·카테고리: 골드 / 전용 타워
- 제시 조건: 별도 조건 없음.
- 효과: 비용 220다이아, 최대 체력 160, 사거리 6, 슬롯 1칸, 동시 설치 한도 1기인 비공격 중계기를 해금한다. 웨이브 시작 시 범위 안에서 `towerTypeId`가 다른 가장 가까운 일반 영구 공격 타워 두 기를 연결한다.
- 대가: 배치할 때 220다이아와 슬롯 1칸을 사용한다.
- 판정: 두 연결 타워는 공격 횟수를 따로 센다. 한쪽 연결 타워가 실제 기본 공격을 5회 해결하면 반대편 연결 타워가 충전 1개를 얻고, 공격한 타워의 카운터는 0으로 돌아간다. 충전은 한 개만 보관하며 추가 충전은 버린다. 충전을 가진 타워의 다음 기본 공격은 그 공격의 대상에게 해당 타워 기본 공격 피해의 50%를 추가로 준다. 추가 피해는 공격 횟수나 다른 증강을 발동하지 않는다. 카운터와 충전은 웨이브 시작 시 초기화한다. 중계기나 연결 타워가 파괴되면 해당 웨이브의 연결을 끊는다.
- 플레이: 빠른 공격 타워와 강한 한 발을 가진 타워를 중계기 양쪽에 배치한다.
- UI: 연결 후보가 두 기 미만이면 이유를 표시한다. 준비 단계에는 연결 예정 타워를 강조하고 전투 중에는 연결선, `3/5`, `충전됨`을 표시한다.

### 7.9 골드: 전열 분업

- 희귀도·카테고리: 골드 / 게임 체인저
- 제시 조건: 피해를 줄 수 있는 서로 다른 일반 영구 타워가 두 기 이상 있어야 한다.
- 효과: 준비 단계에서 두 타워를 `선봉`과 `포대`로 지정한다. 선봉은 최종 피해가 25% 줄고 받는 피해가 30% 감소하며 같은 거리의 다른 타워보다 먼저 공격받는다. 포대는 최종 피해가 30% 늘고 받는 피해에 `×1.25`를 적용한다.
- 대가: 선봉의 화력을 포기하고 포대의 생존 위험을 높인다.
- 판정: 준비 단계마다 대상을 한 번 바꿀 수 있다. 승급은 역할을 이어받는다. 둘 중 하나가 파괴되거나 제거되면 그 웨이브에는 두 효과를 함께 끈다. 제거된 역할 대상은 다음 준비 단계에 다시 지정한다. 역할 타워에는 전술 지명과 삼각 진형을 적용하지 않는다.
- 플레이: 오래 버틸 선봉과 보호할 포대를 한 쌍으로 배치한다.
- UI: 두 역할의 실제 증감값과 연결선을 표시한다. 같은 타워를 두 역할에 지정하면 확정하지 않고 오류를 보여 준다.

### 7.10 골드: 예고 공세

- 희귀도·카테고리: 골드 / 인컴
- 제시 조건: 구매 가능한 유료 공격형 인컴이 있어야 한다.
- 효과: 준비 단계마다 한 번 토글을 켠다. 다음 `NORMAL_PAID` 공격형 인컴은 비용을 즉시 지불하지만 이번 웨이브에 출현하지 않는다. 다음 웨이브에 원본과 원본 최대 체력·기본 공격 피해의 30%를 가진 `ECHO`가 같은 레인에 연이어 출현한다.
- 대가: 원본의 정상 다이아 인컴 증가량은 다음 웨이브 출현 시 반영하므로 정기 지급 한 번을 놓친다. 원본이 나오기 전에 경기가 끝나면 환불받지 못하고 다이아 인컴도 증가하지 않는다.
- 판정: 준비 단계마다 예약 한 개만 만든다. 실패한 구매는 토글을 소비하지 않으며 준비 단계 종료 시 미사용 토글을 해제한다. 유틸 인컴과 보스는 예약할 수 없다. 메아리는 비용, 인컴, 처치 보상, 고유 능력과 다른 증강 발동이 없다. 구매 ID, 인컴 실결제 에메랄드, 정상 다이아 인컴 증가량, 대상 팀·레인과 예약 라운드를 저장한다.
- 플레이: 현재 웨이브의 압박을 포기하고 다음 웨이브의 합동 공격을 준비한다.
- UI: 토글 상태와 `R16: 좀비 +30% 메아리` 같은 예약 내용을 표시한다.

### 7.11 골드: 지원 실적

- 희귀도·카테고리: 골드 / 인컴
- 제시 조건: 구매 가능한 유틸 인컴이 있어야 한다.
- 효과: 같은 준비 단계에 구매한 각 `NORMAL_PAID` 유틸 인컴을 추적한다. 한 기가 같은 라운드·레인의 서로 다른 일반 전투 유닛 세 기를 유효 지원하면 구매자의 다이아 인컴이 2 증가한다. 지원 대상은 자연 웨이브와 `NORMAL_PAID` 공격형 인컴이며 발신자가 달라도 된다. 해당 준비 단계에 산 유틸 중 먼저 성공한 한 기에 대해서만 +2를 지급한다.
- 대가: 별도 추가 비용은 없다. 유틸을 실제로 구매해야 하며, 해당 레인에서 공격 유닛 세 기에 지원이 적용되기 전에 유틸이 죽으면 보상이 없다.
- 판정: 대상은 논리 몬스터 ID로 구분해 엔티티 재생성으로 다시 세지 않는다. 자신, 회복 유닛, 보스, 무료 소환, 메아리와 저압 계약으로 약화된 인컴은 제외한다. 같은 유닛을 세 번 회복해도 1기로 센다. 준비 단계당 한 번, 경기당 최대 +8을 지급한다. 보상은 지원 대상의 소유자가 아니라 유틸 구매자에게 돌아간다. 처리한 라운드와 지원 대상 ID를 저장해 중복 정산을 막는다.
- 플레이: 자연 웨이브 구성과 상대의 압박을 보고 회복·보호막 유틸 중 무엇을 보낼지 고른다. 목표 레인은 현재 서버가 자동 배정하므로 직접 레인을 고르는 조작을 전제하지 않는다. 이 조건이 사실상 자동 +8에 그치는지, 불필요한 유틸 구매 숙제가 되는지는 별도로 검증한다.
- UI: 유틸 이름표에 `지원 2/3`, HUD에 `누적 +4/+8`을 표시한다. 실패하면 부족한 대상 수나 실제 적용량 0을 이유로 보여 준다.

### 7.12 프리즘: 금지된 설계도

- 희귀도·카테고리: 프리즘 / 대가형
- 제시 조건: R5와 R15에만 제시한다. 현재 보드에 이용권과 보유 다이아로 완료할 수 있는 적격 유료 승급이 한 개 이상 있어야 한다.
- 효과: 유료 승급 비용을 장당 최대 300다이아까지 대신 내는 이용권 두 장을 받는다. 초과 비용은 플레이어가 낸다.
- 대가: 이용권을 한 장 쓸 때마다 남은 경기의 정기 다이아 지급액에 `×0.90`을 적용한다. 두 장을 쓰면 `×0.81`이 된다.
- 판정: 비용이 300 미만이어도 이용권 한 장을 전부 소비한다. 같은 타워에는 한 장만 쓸 수 있다. 이용권은 카드를 고른 준비 단계가 끝나면 사라진다. 직업과 특성 보정을 마친 정기 지급액에 이용권 사용 장수에 따른 배율 `0.9^n`(`n`은 사용한 이용권 수)을 한 번 적용하고 마지막에 내림한다. 직업 핵심, 임시, 복제, 무적, 증강 전용 타워에는 쓸 수 없다. 무료분은 타워 누적 실결제 다이아와 판매가에 넣지 않는다.
- 플레이: 비싼 승급을 지금 끝낼지 이후 정기 수입을 지킬지 고른다.
- UI: `무료 300 / 이후 정기 지급 ×0.90 / 이번 준비 종료 시 만료 / 남은 이용권 1`을 승급 확정 전에 표시한다.

### 7.13 프리즘: 명예 퇴역

> 재설계 보류. 아래 +20%는 비교 시험값이다. 스택을 버릴 만한 보상이 확인되기 전에는 공개하지 않는다.

- 희귀도·카테고리: 프리즘 / 대가형
- 제시 조건: R15와 R25에 한 플레이어당 한 번만 제시한다. T3, 타워 누적 실결제 다이아 350 이상, 전투 5웨이브 이상인 일반 영구 타워가 있어야 한다.
- 효과: 적격 타워 중 타워 누적 실결제 다이아가 가장 큰 타워를 정상 판매로 제거한다. 동률이면 그중 하나를 고른다. 현재 남아 있거나 이후 배치하는 일반 영구 타워의 최종 피해와 최대 체력이 각각 20% 증가한다.
- 대가: 정상 판매 환급만 받는다. 선택한 타워의 처치, 결속, 흡수, 진화 등 귀속 상태를 모두 잃고 남은 경기의 개인 타워 한도가 1 줄어든다.
- 판정: 타워 누적 실결제 다이아와 전투 웨이브 수는 승급 뒤에도 이어받는다. 판매 보상이 있는 군대 타워, 연결 복제체가 있는 미래기관 요원, 직업 핵심, 임시, 무적, 증강 전용, 슬롯 가중치 0 타워는 대상에서 제외한다. 제거에 성공한 뒤에만 카드를 소비한다.
- 플레이: 성장한 핵심 한 기와 빈 슬롯을 편성 전체 강화로 바꿀지 결정한다.
- UI: 타워 이름, 잃는 귀속 상태, 정상 환급, 변경 전후 한도와 +20% 효과를 한 화면에 표시한다. 직전 웨이브의 대상 피해 기여도는 참고값으로 표시하되 미래 손익을 보장하지 않는다.
- 보상 검토: 제거할 타워의 기존 총피해 비중을 `s`라 하면, 같은 공격 시간·재투자 없음·다른 증강 없음의 단순 모델에서 남은 총피해는 `1.2 × (1-s)`다. `s=30%`인 주력을 퇴역시키면 84%로 줄어든다. 정상 환급의 재투자와 생존 이득까지 비교해도 전환의 이점이 없다면 보상을 재설계한다. 스택 손실을 경고하는 것만으로 카드가 재미있어지지는 않는다.

### 7.14 프리즘: 방벽 핵심 호출

- 희귀도·카테고리: 프리즘 / 전용 타워
- 제시 조건: 별도 조건 없음.
- 효과: 최대 체력 700, 사거리 6, 슬롯 2칸인 비공격 방벽 핵심의 무료 배치권 한 장을 받는다. 웨이브 시작 시 방벽 핵심의 현재 위치와 거리를 기준으로 가장 가까운 일반 영구 타워를 최대 세 기 연결한다. 거리 동률은 그리드 좌표 순으로 결정한다.
- 대가: 슬롯 2칸과 한 번뿐인 배치 위치를 사용한다.
- 판정: 연결 타워가 받을 최종 피격량의 25%를 줄이고, 줄인 양을 방벽 핵심에 방어 무시 피해로 전가한다. 방벽 핵심으로 전가할 피해가 남은 체력을 초과해도 초과분을 연결 타워로 되돌리지 않는다. 전가된 피해는 다시 피해 전가를 발동하지 않는다. 핵심이 파괴되면 해당 웨이브의 연결을 끊는다. 전투 중 회복 효과를 받지 못하고 다음 웨이브에는 체력을 모두 회복한다. 판매, 재배치, 승급과 복제를 허용하지 않으며 다른 전투 버프를 받지 않는다.
- 플레이: 핵심 타워 세 기를 연결하면서 핵심이 오래 버틸 위치를 고른다.
- UI: 배치 전에 연결 예상 대상과 슬롯을 보여 준다. 전투 중에는 연결선, 남은 체력과 대신 받은 누적 피해를 표시한다.

### 7.15 프리즘: 과밀 허가

> 재설계 보류. 피해·체력 동시 상쇄가 프리즘 보상을 지우는지 먼저 비교한다.

- 희귀도·카테고리: 프리즘 / 게임 체인저
- 제시 조건: 별도 조건 없음.
- 효과: 개인 타워 한도가 2 늘어난다. 증강 보정 전 개인 한도 `N`에 따라 현재와 이후 일반 영구 타워의 최종 피해와 최대 체력에 각각 `N / (N + 2)`를 곱한다.
- 대가: 기존 타워가 모두 약해지고 추가 두 자리의 배치 비용도 직접 내야 한다.
- 판정: `N`은 라운드 기본 한도, 구매한 한도와 특성 보너스의 합이며 증강의 한도 증감은 넣지 않는다. 이 값이 바뀌면 배율을 다시 계산하고 현재 체력 비율을 유지한다. 증강 전용, 임시, 복제, 무적, 슬롯 가중치 0 타워에는 능력치 배율을 적용하지 않는다.
- 플레이: 두 자리를 지원·오라 타워로 채워 개별 능력치 손실을 회수한다.
- UI: `기존 한도 N=8 / 새 한도 10 / 피해·최대 체력 각각 ×0.80`처럼 실제 값을 표시한다.
- 보상 검토: 같은 성능의 타워로 만석을 채우면 `(N+2) × N/(N+2) = N`이므로 기본 피해·체력 합은 그대로인데 배치비만 늘어난다. 고정 효과나 오라가 있는 빌더만 이익을 얻는다면 범용 프리즘으로 공개하지 않는다. 피해·체력 중 한쪽 대가만 남기는 안을 비교 후보로 두되, 검증 전 이 문서의 수치를 자동 상향하지 않는다.

### 7.16 프리즘: 저압 고수익

- 희귀도·카테고리: 프리즘 / 인컴
- 제시 조건: 고유 전투 능력이 없는 표준 공격형 인컴을 구매할 수 있어야 한다.
- 효과: 표준 공격형 인컴을 구매할 때 `저압 계약` 적용 여부를 고른다. 정상 다이아 인컴 증가량 `G`의 25%를 보너스 계산에 사용한다.
- 대가: 계약을 적용한 유닛은 최대 체력과 기본 공격 피해가 각각 30% 감소한다.
- 판정: 준비 단계 시작 시 지급 누계를 0으로 둔다. `raw = 이전 소수 잔액 + 0.25G`, `지급 = min(floor(raw), 12 - 이번 준비 지급 누계)`로 계산한다. 지급 뒤에는 `raw - floor(raw)`인 소수만 다음 구매와 다음 준비 단계로 넘기며 상한을 넘은 정수는 버린다. 고유 전투 능력이 있는 공격형 인컴, 유틸 인컴, 무료 소환, 메아리와 보스에는 적용하지 않는다. 약화 표식은 제거할 수 없고 다른 증강 조건을 채우지 않는다.
- 저압 유닛과의 상호작용으로 새 증강 스택이나 발동 조건을 채우지 않는다. 연승 탄환 획득, 전장 숙련의 조건 피해 누적, 마무리 사격 조건, 중계기 적중 누적, 도미노·포격·지뢰의 새 발동을 제외한다. 이미 충전한 연승 탄환과 축전 초소의 강화 기본 공격은 저압 유닛에게도 피해를 주고 기존 규칙대로 소모한다. 유효 체력 피해가 없는 공격에는 기존 보존 규칙을 적용한다. 실제 피해 통계와 일반 처치 보상은 그대로 기록한다.
- 플레이: 구매마다 상대 압박과 영구 인컴 중 하나를 고른다.
- UI: `체력·기본 공격 -30% / 인컴 +3 / 이번 준비 +8/+12 / 잔액 0.5`를 구매 버튼에 표시한다.

| 밸런스·구현 심사 | 6 | 정상 판매와 순비용이 같은 `시제품 계약`, 빌더별 T2·T3 가치를 뒤집는 `미완성의 미학` 삭제 |
| 재미·중복·UX 심사 | 4 | 기존 방벽·중계기와 겹치는 `경보탑` 삭제, 공용 보호막 체계가 필요한 `차폐 변환기` 보류 |

프리즘 후보는 심사를 통과하지 못했다. 희귀도별 카드 수를 맞추기 위해 탈락 카드를 되살리지 않는다.

### 8.1 실버: 쌍둥이 편대

- 희귀도·카테고리: 실버 / 범용
- 제시 조건: 같은 종류의 공격 타워를 동시에 두 기 이상 설치할 수 있는 빌더에게만 제시한다.
- 효과: 웨이브 시작 시 같은 종류·티어인 일반 영구 공격 타워가 정확히 두 기이면 두 타워의 최종 피해가 해당 웨이브 동안 10% 증가한다. 조건을 만족하는 조합이 여러 개면 모두 적용한다.
- 대가: 직접 비용은 없다. 같은 종류·티어인 타워가 한 기이거나 세 기 이상이면 효과가 꺼진다.
- 판정: 웨이브 시작 시 한 번 계산한다. 직업 핵심, 임시, 복제, 증강 전용 타워와 슬롯 가중치 0인 부속물은 세지 않는다. 시작 뒤 한 기가 파괴돼도 스냅샷 효과는 웨이브 끝까지 유지한다.
- 플레이: 같은 타워 두 기를 유지하면서 두 기의 승급 시점을 함께 맞춘다.
- UI: `궁수 1/2`, `2/2 활성`, `3/2 초과`를 표시하고 적용 타워 상세에 `최종 피해 +10%`를 보여 준다.
- H0 경보: 선택 후 3웨이브의 적용 슬롯 비율이 평균 80%를 넘고 같은 빌더·라운드의 다른 범용 카드보다 반복해서 우세하면 지배 선택 여부를 조사한다. 총피해는 생존 시간·상대 인컴·적 회복량에도 늘어나므로 차이만 보고 10%를 8%로 내리지 않는다. 같은 시작 보드와 웨이브에서 전투 시간·누수·생존을 비교하고, 두 기를 맞추는 과정이 편성 판단인지 승급을 미루는 숙제인지 확인한다.

### 8.2 골드: 전장 숙련

- 희귀도·카테고리: 골드 / 범용
- 제시 조건: 직전 웨이브에 적 몬스터에게서 웨이브 시작 시점 최대 체력의 40% 이상에 해당하는 실제 체력 피해를 받고 생존한 일반 영구 공격 타워가 현재 보드에 있어야 한다.
- 효과: 카드를 확정할 때 타워 한 기를 베테랑으로 지정한다. 지정 타워가 한 웨이브 동안 적 몬스터에게서 웨이브 시작 시점 최대 체력의 40% 이상에 해당하는 실제 체력 피해를 받고 생존할 때마다 `숙련` 1스택을 얻는다. 스택마다 출처 기반 최종 피해와 최대 체력 보너스가 4%씩 증가하며 최대 4스택, 총 16%까지 쌓인다.
- 대가: 직접 비용은 없다. 조건을 달성하려면 대상이 큰 피해를 받고도 살아남아야 한다.
- 판정: 대상은 바꿀 수 없다. 자해, 환경 피해, 방벽 핵심으로 전가된 피해와 보호막 흡수량은 조건에 넣지 않는다. 승급은 대상과 스택을 이어받고, 제거 시 지정과 스택을 모두 잃는다. 마지막 정산 라운드를 저장해 한 웨이브를 두 번 정산하지 않는다.
- 플레이: 지정 타워의 어그로와 보호를 조절해 생존 과제를 반복한다.
- UI: 확정 전에 대상과 판매·퇴역 등 제거 시 손실을 보여 준다. 이름표에는 `숙련 2/4 · 조건 피해 31/80`을 표시하고 실패하면 부족한 피해량 또는 파괴를 이유로 보여 준다.
- 보상 검토: 위험을 감수해 네 번 성공한 보상이 같은 등급의 즉시 강화보다 매력적인지 비교한다. 후반에 완성하지 못하고 끝난 경기도 실패 표본으로 남긴다. 승리한 완성 사례만으로 성장의 재미를 판정하지 않는다.

### 8.3 골드: 편향 장갑

- 희귀도·카테고리: 골드 / 대가형
- 제시 조건: 별도 조건 없음.
- 효과: 카드 확정 시 `물리 편향` 또는 `마법 편향`을 고른다. 물리 편향은 일반 영구 타워가 받는 물리 직접 피해에 `×0.75`, 마법 직접 피해에 `×1.35`를 적용한다. 마법 편향은 반대로 적용한다. 준비 단계마다 한 번 바꿀 수 있다.
- 대가: 반대 유형의 직접 피해가 35% 증가한다.
- 판정: 공격자가 `SemionMonsterEntity`인 직접 공격만 몬스터의 런타임 피해 유형으로 분류한다. 방어 무시, 환경, 지속, 간접 능력 피해에는 적용하지 않는다. 증강 전용, 임시, 복제, 무적 타워도 제외한다. 원래 피해를 `D0`, 기존 감소 뒤 피해를 `D1`이라 하면 선택 유형 피해는 `max(0.40D0, 0.75D1)`, 반대 유형 피해는 `1.35D1`이다.
- 플레이: 자연 웨이브와 예약된 상대 인컴의 피해 유형을 읽고 다음 웨이브의 편향을 정한다.
- UI: 준비 중인 편향은 본인과 팀원에게만 표시한다. 상대와 관전자에게는 웨이브 시작에 잠근 편향을 동시에 공개한다. 선택 화면에는 다음 웨이브에 출현할 적의 기본 공격력과 공격 주기로 계산한 물리·마법 직접 DPS 비중을 표시한다. 전투 뒤에는 `물리 -24 / 마법 +6 / 순감소 18`처럼 실제 증감량을 보여 준다.
- 균형점: 다른 피해 감소가 없을 때 물리와 마법이 50:50이면 총 직접 피해가 5% 늘어난다. 선택 유형 비중이 약 58.3%를 넘어야 총피해가 줄어든다.

### 8.4 골드: 현금 결제

- 희귀도·카테고리: 골드 / 인컴
- 제시 조건: 정상 다이아 인컴 증가량이 양수인 유료 인컴을 구매할 수 있어야 한다.
- 효과: 준비 단계마다 한 번 토글을 켠다. 이후 처음 성공한 `NORMAL_PAID` 구매의 정상 다이아 인컴 증가량을 `G`라고 할 때 영구 인컴 `G`를 얻지 않고 즉시 `3G`다이아를 받는다.
- 대가: 정기 지급 3회분과 같은 다이아를 미리 받지만 네 번째 지급부터 누적 손해가 생긴다.
- 판정: `G`는 직업 보정을 마친 뒤 다른 증강을 적용하기 전의 정상 다이아 인컴 증가량이며, 0보다 커야 한다. 에메랄드 비용, 유닛 능력치, 목표 레인, 처치 보상과 출현 시점은 바꾸지 않는다. `PREPARE_AND_SUMMON`에서 성공한 거래만 토글을 소비한다. 무료 소환, 메아리, 실패·환불 거래와 `LANE_WAVE` 예약 소환은 제외한다. 성공 거래 ID를 저장해 중복 지급을 막는다.
- 충돌: `현금 결제`는 `비상 융자`, `금지된 설계도`와 함께 선택할 수 없다. `예고 공세` 또는 `저압 고수익`과는 같은 경기에서 선택할 수 있지만 5.2절의 토글 잠금으로 한 구매에 계약 하나만 적용한다.
- 플레이: 당장 필요한 승급과 장기 인컴 중 하나를 고른다.
- UI: `영구 인컴 +15 포기 / 즉시 +45다이아 / 4번째 지급부터 손해`를 구매 버튼에 표시한다. 실패 구매 뒤에는 토글을 유지하고 준비 단계가 끝나면 해제한다.
- 계측: 해당 거래의 `income_generated=0`, `augment_income_forgone=G`, `augment_diamond_granted=3G`를 기록한다.

## 9. UI 명세

상세 화면과 입력 계약은 [시즌 3 증강 GUI 상세 명세](./2026-09-04-season-3-augment-gui-design.ko.md)를 따른다. 새 인벤토리형 GUI를 만들지 않는다. 기존 서버 전송형 `MultiActionDialog`, 타워 관리 화면, `runtimeDetailLines`, 출처 기반 효과와 공용 VFX를 재사용한다.

### 9.1 카드 선택 화면

주 화면은 카드명·분류, 행동·핵심 보상, 대가·현재 적용 가능 수의 세 줄로 요약한다. 영구 손실은 숨기지 않는다. 검토·결과 확인 화면에서 아래 정보를 풀어 보여 준다.

- 카드명, 희귀도, 카테고리
- 플레이어가 할 행동을 설명하는 한 문장
- 효과 수치와 지속 시간
- 대가, 실패 조건과 남은 사용 횟수
- 현재 보드로 계산한 금액, 체력, 슬롯과 적격 대상
- 선택 시 함께 제외되는 계보와 충돌 카드

`비상 융자`, `금지된 설계도`, `명예 퇴역`, `과밀 허가`, `전장 숙련`은 보상과 손실을 한 화면에 계산해 보여 준 뒤 한 번 더 확인한다. 대상이나 모드를 정해야 하는 카드도 마지막 결과를 확인한다. 최종 확인 전에는 자원, 대상, 이용권과 난수 결과를 바꾸지 않는다.

### 9.2 선택 이후 화면

- Dialog를 닫아도 제안 상태를 유지한다.
- `/semiontd augment ui` 명령은 현재 제안이나 선택한 증강 목록을 다시 연다.
- 이름표와 타워 상세에는 현재 대상, 스택, 충전과 실제 적용 수치를 표시한다.
- 실패 시 `대상 없음`, `정확히 2기 필요`, `조건 피해 부족`, `다른 계약 적용 중`처럼 수정할 수 있는 이유를 보여 준다.
- 관전자는 제안과 리롤을 볼 수 없다. 확정된 증강과 전투 효과만 볼 수 있다.

## 10. 구현 명세

### 10.1 현재 코드 상태

현재 `augment` 패키지, 기존 전투·경제·Dialog 경계와 테스트에 구현을 추가했다. 자동 검증, 실제 클라이언트 표시, 내부 밸런스와 운영 검증은 각각 구분한다.

`SemionPlayer`는 경기별 증강 선택과 경제 상태를 소유한다. `ProductionTowerCatalog.CatalogEntry`는 `JOB | AUGMENT`와 필요한 증강 ID를 구분한다. `SemionGame.summonMonster`는 실제 비용과 대상 확인 뒤 결제·큐 등록·경제 확정을 처리하며 소환 출처와 거래 ID를 논리 몬스터에 보존한다.

### 10.2 최소 신규 구조

| 구성 | 책임 |
|---|---|
| `AugmentCatalog` | 카드 ID, 이름, 희귀도, 카테고리, `SAFE`, `familyKey`, 충돌 태그, 출현 라운드와 UI 문구 등록 |
| `PlayerAugmentState` | `SemionPlayer`가 소유하는 경기 단위 제안, 선택, 리롤, 대상, 토글, 진행도와 중복 방지 상태 |
| `AugmentSnapshot` | 플레이어의 확정된 전투 효과만 담아 `PlayerLane`과 소유 타워에 전달하는 불변 값 |
| `AugmentService` | 제안 생성, 리롤, 건너뛰기, 미리보기, 확정과 UI 재개 처리 |
| 증강 밸런스 설정 | H0 수치 저장. `augment_version`과 웹 카탈로그 해시에 포함 |

카드마다 클래스를 만들지 않는다. 카드별 상태는 필요한 타입만 `PlayerAugmentState` 또는 기존 `TowerDataKey` 맵에 추가한다. 범용 `Map<String, Object>`, 새 이벤트 버스와 스크립트 엔진은 만들지 않는다.

카드의 안정 ID와 구조 메타데이터는 `AugmentCatalog` 코드에 둔다. 조정 가능한 H0 수치는 번들 기본값 `src/main/resources/semiontd/balance-defaults/augment_balance.json`과 서버 파일 `config/semion-td/augment_balance.json`에 둔다. 서버 파일에서 빠진 값은 번들 기본값으로 채우고, 알 수 없는 카드 ID, 유한하지 않은 수, 허용 범위 밖의 값이나 합계가 100%가 아닌 희귀도 확률은 검증 실패로 처리한다. 리로드가 실패하면 기존의 유효한 설정을 계속 사용한다.

시즌 3 `NORMAL`은 `config/semion-td/traits.json`의 `enabled`를 `false`로 둔다. 증강과 특성이 동시에 켜진 `NORMAL` 설정은 경기 시작 검증에서 거절한다. `SemionGameManager.scheduleStart`는 `TraitSelectionSession`을 만들지 않고 빈 `TraitSelectionSnapshot`을 넘기며, 참가자와 레인에는 `TraitLoadout.none()`을 적용한다. 기존 특성 기록과 다른 모드의 동작은 지우지 않는다.

### 10.3 기존 코드에 연결할 위치

| 사건 | 기존 경계 | 처리할 카드 |
|---|---|---|
| 준비 단계 시작 | `SemionGame.startPreparePhase` | 마일스톤 제안, 전술 지명, 교전 계획, 토글 초기화 |
| 제안 만료 | `SemionGame.startWavePhase`가 단계를 바꾸기 직전 | 미확정 제안을 `SKIPPED`로 정산 |
| 웨이브 시작 | `SemionGame.startWavePhase`에서 플레이어별 스냅샷 생성 후 `PlayerLane.markWaveStarted`에 전달 | 삼각 진형, 쌍둥이 편대, 중계기 연결, 편향 잠금 |
| 웨이브 종료 | `SemionGame.tickPayout`에서 `notifyRoundEnded(currentRound)` 뒤, 정기 지급과 `currentRound++` 전 | 과열 코어 열화, 전장 숙련 정산 |
| 정기 다이아 지급 | `SemionGame.tickPayout`이 호출하는 `EconomyService.payRoundIncome(currentRound, ...)` | 비상 융자, 금지된 설계도 |
| 타워 거래 | `ProductionTowerService`의 배치·승급·판매 검증과 성공 반환점 | 전용 타워 권한, 이용권, 퇴역, 상태 승계·소멸 |
| 기본 공격 해결 | `TowerAttackMonsterGoal`의 쿨다운을 소비하는 주 대상 공격 성공 지점 | 박동 중계기 |
| 최종 피격 | `SemionTowerEntity.actuallyHurt`에서 `modifyFinalIncomingDamage` 뒤, `applyDamage` 전 | 전열 분업, 편향 장갑, 방벽 핵심 |
| 웨이브 타워 지표 | `TowerRoundMetricsTracker` | 전장 숙련 |
| 인컴 구매 | `SemionGame.summonMonster`의 검증·계산과 성공 반환점 | 추가 적재, 예고 공세, 지원 실적, 저압 고수익, 현금 결제 |
| 유틸 적용 성공 | 공용 회복·보호막·강화 효과 성공 지점 | 지원 실적 |
| 타워 파괴 알림 | `PlayerLane`의 사망 알림 한 곳 | 증강 전용 타워의 긍정 사망 효과 차단 |
| 재접속 | `SemionGameManager.handlePlayerJoin`에서 `restorePlayerPlacement` 뒤 | 5.4절의 제안·대상·카드 상태와 Dialog 복원 |
| 중도 참여 | `SemionGame.addLateParticipant`에서 참가자 활성화와 따라잡기 경제 지급 뒤 | `requestedRound=5`이면 누락된 R5 마일스톤 예약 |

### 10.4 공통 경계에 필요한 변경

- 최대 체력과 어그로는 빌더별 계산 뒤 증강 보정을 적용하는 공통 후처리 경계를 만든다. `currentMaxHealth()`의 8개 구현과 `aggroPriority()`의 4개 구현 중 일부가 부모 구현을 호출하지 않으므로, 한 구현만 고치는 방식은 쓰지 않는다. 공통 후처리는 재정의할 수 없게 두고 기존 빌더 계산을 내부 훅으로 옮긴다.
- `SemionPlayer`의 확정 상태에서 불변 `AugmentSnapshot`을 만들고 `PlayerLane`과 모든 소유 타워에 동기화한다. 카드 확정, 배치와 승급 뒤에 다시 동기화한다. 최대 체력 배율이 바뀌면 기존 엔티티 능력치와 현재 체력 비율도 즉시 갱신한다.
- 개인 타워 한도는 `SemionGame.towerLimitForPlayer()`의 최종 결과에 증강 증감을 한 번만 적용한다.
- 타워 귀속 증강 상태는 문자열 맵이 아니라 기존 `TowerDataKey` 타입 맵에 저장한다. 최초 지정 때 논리 타워 UUID를 만들고 `Tower.copyFrom`이 승급 타워에 복사한다. 얕은 복사 뒤 두 타워가 상태를 공유하지 않도록 값은 UUID, 숫자나 불변 record만 사용한다.
- 최종 피격 증강은 `SemionTowerEntity.actuallyHurt`의 한 비가상 후처리에서 실행한다. 방벽 핵심으로 전가된 피해는 같은 후처리에 다시 들어가지 않는 내부 경로를 사용한다.
- 증강 전용 타워는 `triggersNearbyDeathEffects=false`로 표시하고 `PlayerLane`의 사망 알림에서 제외한다.
- `TowerRoundMetricsTracker`에는 라운드 증강·특성 적용 뒤의 웨이브 시작 시점 최대 체력을 저장한다. `SemionTowerEntity.applyDamage`에서 공격자가 `SemionMonsterEntity`인 실제 체력 피해만 별도 값으로 전달한다.
- 회복·보호막·강화 효과 성공 지점은 시전자, 대상, 종류와 실제 적용량을 지원 실적에 보고한다.
- 박동 중계기는 `TowerAttackMonsterGoal`이 해결한 주 대상 기본 공격만 센다. Frost 즉시 추가 공격, Body 추가 대상 공격과 증강 추가 피해는 기존 `recordAttack`을 호출해도 카운터에 넣지 않는다. 주 대상 공격 성공 지점에서 증강용 콜백을 한 번만 호출한다.
- 논리 `Monster`에는 재생성 뒤에도 유지되는 개체 ID와 `NORMAL_PAID`, `FREE_AUGMENT`, `ECHO`, `NATURAL_WAVE`, `BUILDER_PROXY`, 서버 거래 ID, 인컴 실결제 에메랄드, 정상 다이아 인컴 증가량과 예약 라운드를 보존한다. `SemionMonsterEntity`가 다시 만들어져도 이 값이 남아야 한다.
- 예약 소환과 메아리는 정상 구매 함수를 다시 호출하지 않는다.
- 경기 시작 때 증강 설정을 값으로 복사해 `SemionGame`에 둔다. `/semiontd reload` 뒤에도 진행 중인 경기는 이 스냅샷만 읽고 새 경기는 새 `augment_version`과 설정을 사용한다.

### 10.5 전용 타워 카탈로그

전용 타워를 열기 전에 아래 두 경계를 만든다.

1. 정적 카탈로그 항목에 `availability`와 선택적인 `augmentId`, `builderOrigin`을 추가한다.
2. 상점 표시와 실제 배치가 함께 쓰는 권한 판정에서 `직업 허용 또는 증강 해금`을 검사한다.

`availability=JOB`인 기존 타워는 지금처럼 카탈로그의 직업 소유자 한 명을 요구한다. `availability=AUGMENT`인 타워는 직업 소유자 조건을 두지 않고 `augmentId`가 필수다. 현재 설계한 방벽, 박동 중계기, 방벽 핵심은 모든 빌더가 해당 증강을 골랐을 때 쓰는 중립 타워이므로 `builderOrigin`은 `null`로 내보낸다. 나중에 빌더 전용 증강 타워를 만들 때만 실제 빌더 ID를 넣는다.

웹 카탈로그는 증강 타워를 가짜 공용 빌더 아래에 넣지 않고 `AUGMENT` 그룹으로 내보낸다. 플레이어별 런타임 카탈로그와 전용 GUI는 만들지 않는다.

### 10.6 거래, 중복 처리와 재접속

- 같은 카드의 제안·설정 초안을 다시 열면 대상·모드와 버전을 유지한다. 다른 카드로 바꾸거나 실제 입력을 바꿨을 때만 초안과 버전을 갱신한다. 미확정 제안의 초안·리롤·건너뛰기·대상·모드 요청은 요청에 담긴 `offerRevision`을 현재 제안과 비교한다. 확정 카드의 설정 요청은 선택 기록 칸으로 카드를 찾고 `configurationRevision`과 카드별 `lastConfiguredRound`를 검사한다. 카드마다 준비 단계에 한 번만 설정을 확정할 수 있으며, 처음 카드를 확정하면서 대상이나 모드를 정한 경우도 현재 라운드를 `lastConfiguredRound`에 기록한다. 준비 단계가 끝나면 `startWavePhase`가 단계 변경 전에 미확정 제안을 `SKIPPED`로 바꾸고 사유를 `TIMEOUT`으로 기록하며, 미확정 설정 초안도 지운다.
- 정기 지급은 `EconomyService.payRoundIncome(currentRound, ...)` 한 메서드가 지급액 계산, 부채·배율 적용, 다이아 지급과 `lastSettledRound` 갱신을 함께 처리한다. `tickPayout`에서 별도로 같은 보정을 적용하지 않는다.
- 승급권, 인컴 토글처럼 거래 금액이나 결과를 바꾸는 효과는 성공 뒤에 덧붙이지 않는다. 기존 서비스 안에서 `검증·금액 계산 → 변경 내용을 담은 불변 계획 생성 → 기존 거래 실행 → 성공 시 이용권·토글·원장 소비` 순서로 처리한다. 거래가 실패하면 아무 상태도 소비하지 않는다.
- 제안·설정 초안 생성, 리롤, 카드·설정 확정과 건너뛰기처럼 상태를 바꾸는 일회성 버튼에는 서버가 발급한 `requestId`를 넣는다. 플레이어를 확인한 직후 `(requestId, 작업 종류, 인자 지문)`을 조회하고, 같은 요청을 이미 처리했다면 상태를 다시 바꾸지 않는다. 대상·모드는 성공할 때마다 해당 초안 버전을 올려 반복된 이전 요청을 거절한다. 서버 거래 ID는 성공한 거래에 한 번 만들고 결과 개체와 텔레메트리까지 전달한다.
- `명예 퇴역`과 전용 퇴역 거래 API는 이번 범위에서 제외한다. 일반 판매 경로는 보존한다.
- 거래는 서버 거래 ID, 웨이브 정산은 `lastSettledRound`로 중복 적용을 막는다. 무료 호출과 메아리는 정상 구매 경로를 재호출하지 않는다.
- 재접속은 `SemionGameManager.handlePlayerJoin`에서 배치를 복원한 직후 5.4절의 상태를 읽는다. 선택 기한은 남은 시간이 아니라 배타적 절대 게임 틱 `deadlineTickExclusive`로 저장하고 `currentTick < deadlineTickExclusive`일 때만 입력을 받는다. 미확정 제안은 같은 `offerRevision`과 대상 선택 초안으로 다시 연다.
- 경기 종료 전 증강 결과를 `MatchParticipantResult`에 복사해 기존 결과 저장·수집 경로로 보낸다. 런타임 상태를 닫은 뒤 읽지 않는다.

### 11.3 카드 공개 질문

아래 질문에 모두 `예`라고 답한 카드만 무작위 풀에 넣는다.

1. 플레이어가 목표를 동사 한 문장으로 설명할 수 있는가?
2. 선택이 선호하는 편성이나 운영을 강화하거나 새로운 선택을 여는가? 범용 카드에 매 웨이브 조작을 억지로 붙이지 않는다.
3. 보상과 손실을 확정 전에 계산해 보여 줄 수 있는가?
4. 실패 이유를 전투 화면에서 확인할 수 있는가?
5. 무료 획득, 판매, 복제와 재접속으로 대가를 피할 수 없는가?
6. 기존 빌더와 함께 조합할 이유가 있는가? 카드 하나만으로 기존 타워 구성이 무의미해지지 않는가?
7. 대가형은 같은 등급의 안전 카드보다 강해지는 상황이 있는가? 되돌릴 수 없는 손실에 맞는 보상이 보이는가?

### 11.4 텔레메트리

모든 카드가 아래 공통 값을 기록한다.

- `augment_version`, `catalog_version`, 빌더, 라운드, 희귀도, 카테고리
- 최초 제안, 리롤 전후 제안, 선택, `SKIPPED`, 시간 초과와 부적격 사유
- 발동 횟수, 실제 피해·감소·회복·지원·인컴 증가와 지불한 대가
- 선택 뒤 3웨이브의 생존, 완막, 누수, 타워 파괴, 전투 시간과 경제 변화

전용 타워는 배치 시점, 생존 시간, 흡수량과 사용 슬롯을 추가로 기록한다. 확장 후보는 아래 값을 더 기록한다.

| 카드 | 추가 지표 |
|---|---|
| 쌍둥이 편대 | 적격 묶음 수, 적용 슬롯 비율, 총피해 |
| 전장 숙련 | 조건 피해율, 성공·실패 이유, 스택, 제거로 잃은 스택 |
| 편향 장갑 | 선택 유형, 유형별 직접 피해 비중, 감소량과 증가량 |
| 현금 결제 | 포기한 다이아 인컴 증가량, 즉시 지급 다이아, 이후 실제 정기 지급 횟수 |

선택률의 분모는 카드가 적격 상태로 제시된 횟수다. 적격 제시 100회는 공개 관찰의 수집 목표이지 통계적 신뢰를 보장하는 선이 아니다. 반복 참가자·경기·제안 조합의 영향을 함께 본다. 표본이 적어도 재현되는 손익 역전, 중복 지급, 이해 실패는 고칠 수 있다. 선택군 간 차이만으로 카드의 인과 효과를 단정하지 않는다.

| 선택률 65% 초과 | 지배 카드 여부 조사 |
| 선택률 15% 미만 | 함정 카드 또는 설명 실패 조사 |
| 조작형 카드의 선택 후 능동 사용률 30% 미만 | 조작 비용·필요 상황·UI 조사. 범용 자동 효과에는 적용하지 않음 |
| 시간 초과율 2% 초과 | 무작위 공개 중단 후 문구와 선택 단계 축소 |
| 비공격 전용 타워가 의도하지 않은 직접 피해를 만듦 | 공개 중단. 중계기 추가 피해는 연결된 공격 타워에 귀속 |
| 대가 없는 발동, 무료 소환 재귀, 중복 지급 발생 | 즉시 공개 중단. 허용치 0 |

### 11.6 재미 검증: 빠른 선택과 좋은 선택을 구분한다

대표 빌더의 같은 예산 보드를 준비하고, 같은 희귀도의 대안 두 장을 번갈아 시험한다. 자연 웨이브와 상대 인컴을 고정하고 실행 순서를 바꾼다. 손익 계산은 불가능한 안을 걸러낼 뿐 재미를 증명하지 않는다.

| 관찰 질문 | 통과시키지 말아야 할 신호 |
|---|---|
| 왜 다른 카드 대신 이것을 골랐는가? | 숫자가 크다는 말 외에 편성이나 선호를 설명하지 못함 |
| 다음 웨이브나 보드를 바꾸면 선택도 달라지는가? | 조건이 바뀌어도 같은 모드·같은 구매만 정답 |
| 효과가 났거나 실패한 장면을 알아봤는가? | HUD 숫자는 올랐지만 무엇이 좋아졌는지 모름 |
| 다음 경기에서 무엇을 다시 시도하고 싶은가? | 선택 전에는 기대했으나 실제로는 반복 클릭·대기만 늘어남 |

자동 효과를 편하게 쓰는 것도 유효한 재미다. 모든 카드에서 잦은 설정 변경을 요구하지 않는다. 반대로 프리즘과 대가형은 강해진 순간이나 운영이 바뀐 순간을 플레이어가 짚을 수 있어야 한다. 첫 시험에서는 선택 이유, 실제 장면, 다음 시도를 짧은 관찰 메모로 남긴다. 새 설문·분석 시스템은 만들지 않는다.

`명예 퇴역`은 유지한 보드와 환급을 재투자한 보드를, `과밀 허가`는 동일 총예산의 기존 만석 보드와 증축 보드를 비교한다. `지원 실적`은 회복·보호막 선택이 달라지는 상황을, `전장 숙련`은 완성 전 생존 부담까지 확인한다. 답이 없는 카드는 카드 수를 채우기 위해 공개하지 않는다.

### 11.7 구현과 활성화 순서

1. `AugmentCatalog`, `PlayerAugmentState`, 제안·리롤·건너뛰기, 재접속, 관리자 강제 제안과 텔레메트리를 구현한다.
2. 기존 공용 경계만 쓰는 전술 지명, 삼각 진형, 교전 계획, 비상 융자, 과열 코어를 카드별로 검증한다. 과열 코어는 웨이브 종료 정산까지 포함하고, 쌍둥이 편대는 별도 카탈로그에서 뒤이어 검증한다.
3. 소환 출처, 거래 ID, 인컴 실결제 에메랄드를 추가한 뒤 추가 적재, 지원 실적, 저압 고수익과 현금 결제를 각각 검증한다.
4. 예약 소환 경로를 분리한 뒤 예고 공세를 연다.
5. 공통 최대 체력, 한도, 피격 경계를 만든 뒤 전열 분업, 금지된 설계도, 과밀 허가, 전장 숙련과 편향 장갑을 각각 검증한다.
6. 정적 카탈로그와 웹 스키마를 바꾼 뒤 접이식 방벽 하나를 연다. 통과하면 박동 중계기와 방벽 핵심을 차례로 연다.
7. 명예 퇴역은 대상 조건, 정상 판매 경로와 빌더별 판매 예외를 검증한 뒤 마지막에 연다.

각 단계는 새 `catalog_version`을 사용한다. 한 `catalog_version`에서는 새 구현 경계를 쓰는 카드를 한 장씩만 검증한다. 재설계 보류 카드는 구현 순서에 적혀 있어도 공개 승인 전에는 무작위 제안에 넣지 않는다.

## 12. 설계 기준

### 12.1 MDA와 학습 가능한 규칙

[MDA](https://cdn.aaai.org/Workshops/2004/WS-04-04/WS04-04-001.pdf)는 규칙, 플레이 중 행동, 경험을 오가며 검토하는 틀로 사용한다. 먼저 조합 발견·성장 애착·승부수의 긴장처럼 원하는 경험을 정하고, 이를 만들 규칙을 제안한 뒤 실제 전투에서 반증한다. 아래는 목표 경험이지 검증 결과가 아니다.

| 카드 | 규칙 | 플레이 중 생기는 행동 | 목표 경험 |
|---|---|---|---|
| 삼각 진형 | 가까운 타워 세 기 강화 | 화력 밀집과 광역 피해 위험 계산 | 배치 문제를 푸는 유능감 |
| 과열 코어 | 한 웨이브 화력과 영구 열화 교환 | 과열 대상과 사용 시점 관리 | 누적되는 긴장 |
| 명예 퇴역 | 성장 타워와 슬롯을 편성 강화로 전환 | 핵심 타워를 버리는 피벗 | 손실을 감수한 자기표현 |
| 쌍둥이 편대 | 같은 타워를 정확히 두 기 유지 | 수량과 동시 승급 관리 | 조합 완성의 만족감 |

Raph Koster의 [A Theory of Fun for Game Design](https://www.oreilly.com/library/view/theory-of-fun/9781449363208/)이 다루는 학습의 관점을 참고한다. 세미온의 실무 기준으로 카드 하나의 핵심 패턴을 한 문장으로 설명하게 한다. 실패한 다음 웨이브에 바꿀 행동이 보여야 한다.

GUI의 `목표·규칙·피드백`은 이 프로젝트의 세 가지 점검 항목이다. 게임의 유일한 정의나 보편적으로 합의된 세 요소라고 주장하지 않는다. [자기결정성이론](https://selfdeterminationtheory.org/the-theory/)의 자율성과 유능감은 선택 이유와 결과 이해를 묻는 데 참고한다. 건너뛰기 버튼이나 선택지 세 개만으로 이를 충족했다고 보지 않는다.

### 12.2 TFT에서 참고한 원칙

TFT 카드의 이름과 수치를 복사하지 않는다. Riot의 [Augments, Augmented](https://teamfighttactics.leagueoflegends.com/en-us/news/game-updates/augments-augmented/)와 [Into the Arcane 회고](https://teamfighttactics.leagueoflegends.com/en-us/news/dev/dev-tft-into-the-arcane-learnings/)를 참고해 아래 적용 가설을 세웠다. 오른쪽의 제한은 Riot의 공통 규칙이 아니라 세미온 H0의 선택이다.

| TFT에서 참고한 원칙 | 세미온 적용 |
|---|---|
| 같은 유닛의 수량처럼 편성 모습이 달라지는 카드가 기억에 남는다. | 삼각 진형, 쌍둥이 편대, 전열 분업 |
| 큰 보상에는 기다림이나 전력 손실이 필요하다. | 비상 융자, 예고 공세, 명예 퇴역 |
| 단순한 안전 카드와 복잡한 변칙을 같은 제안에 섞는다. | 전술 지명 계보와 제안당 `SAFE` 카드 1장 |
| 익숙한 유닛의 역할을 증강으로 바꾸면 새로운 조합을 시험할 수 있다. | 첫 전용 타워는 비공격 지원으로 범위를 제한한다. 공용 공격 타워가 언제나 재미없다는 뜻은 아니다. |
