검증일: 2026-09-22~23

후속 수정: 9월 23일 증강 효과 425개와 특성 수치 32개에 `NEXT_MATCH` 편집을 연결했다. 기존 증강 확률 8개를 포함한 증강 편집 항목은 433개다. 사용자 승인 후 10:34 KST 운영 JAR을 교체하고 재시작했다. 운영 API에서 증강 433개·특성 32개의 편집 허용과 기존 수치 유지를 확인했다. 아래 초기 검증 수치는 최초 배포본의 기록이다.

게임 `s3-release`, 웹 `codex/s3-release`에서 작업했다. 초기 로컬 검증 이후의 운영 반영은 [배포 기록](2026-09-23-live-balance-dashboard-deployment.ko.md)에 구분해 남겼다. 커밋과 푸시는 하지 않았다.

## 구현 범위

- `/admin/balance`: 서버 선택, 검색·필터, 수치 편집, 일괄 계산, 초안 저장, 검사·확인·적용, 예약 취소, 변경 이력과 수치 복원.
- GitHub 숫자 계정 ID 허용 목록, 암호화 세션, CSRF·출처 검사. 운영 쓰기에는 계정의 2단계 인증 활성화 확인을 요구한다.
- 웹과 AI가 같은 관리 API를 사용한다. AI 토큰은 서버·영역·시점·항목 수·변경률·만료 시간을 제한하며 폐기할 수 있다.
- 게임은 루프백 API, 요청 서명, 버전 충돌 검사, 중복 요청 방지, 불변 설정 버전과 처리 이력을 사용한다.
- 경기 시작 버전과 경기 중 변경 이벤트를 저장한다. 웹은 혼합 버전 경기와 패치별 통계 필터를 구분한다.

사용 순서는 [웹 안내](../../../semion-web/docs/balance-dashboard.ko.md), 요청 형식은 [OpenAPI](../../../semion-web/docs/balance-api.openapi.yaml)에 있다.

### 증강·특성 편집 확대 검증

최초 구현은 특성의 기존 `TraitBalanceRuntime` 적용 경로를 연결하고도 관리 필드 허용 목록에는 `mobilization_grant.startingDiamond`만 등록했다. 증강도 효과 파라미터 8개만 등록해 나머지를 읽기 전용으로 표시했다.

- 증강의 기존 값 검증 규칙을 필드 범위·정수 조건과 공유한다. 타워별 능력 엔진이나 새 적용 경로는 추가하지 않았다.
- 특성의 설정 키와 카탈로그 ID에서 네임스페이스를 맞춰 한글 이름·설명을 표시한다.
- 기본 설정의 편집 가능 항목은 4,721개, 읽기 전용은 3,571개다. 증강 활성화·공개 후보 설정과 알 수 없는 필드는 열지 않았다.
- 457개 효과 파라미터를 한 패치로 검사했다. 전 항목의 단위·편집 가능 여부·다음 경기 제한을 확인했고, 음수·0틱·범위 밖 비율·초 단위 오버플로를 차단했다. 정수 항목의 반올림과 소수 비율 유지도 검사했다.
- GameTest에서 예약 중 기존 특성·선택 증강의 효과를 유지하고 다음 경기에서 특성 피해, 공통 증강 피해, 직업 증강 지연 시간을 반영하는지 확인했다. 새 경기의 시작 버전도 검사했다.
- Java 21 `rtk ./gradlew test runGameTest remapJar --console=plain --no-daemon`: 43초, `BUILD SUCCESSFUL`, 필수 GameTest 676개 통과.
- JUnit 1,336개 중 1,334개 통과·2개 건너뜀, 실패 0개. 빌드 JAR SHA-256: `d04bb52aef09f6616f0c4afbd139ba590ce955f9cf3a12e9204f1f29d07c1213`.

이번 수정에서는 밸런스 수치 자체를 바꾸지 않았다. 운영 게임 JAR 교체·재시작 후 API의 편집 가능 여부와 수치·버전 유지를 확인했다. 브라우저 로그인 후 관리자 화면과 게임 클라이언트 화면은 다시 확인하지 않았다. 웹·DB·동기화 컨테이너는 교체하지 않았다.

## 브라우저 검증

실제 Next.js HTTPS 화면과 관리 API를 사용했다. 인증은 격리 QA 계정의 암호화 세션으로 주입했다. 실제 GitHub 동의 화면·콜백·운영자 계정 로그인 검증과는 구분한다.

게임 응답을 대체한 시험에서는 편집·저장·새로 고침, 검사 후 수정 시 재검사, 예약값과 실제값 분리, 복원, 25틱의 10% 증가를 28틱으로 반올림, 응답 유실 후 같은 요청 ID 확인, 오프라인 잠금, 390px 화면의 가로 넘침 방지를 확인했다.

9월 23일 실제 게임에 연결해 돼지 공격력 `6 → 5`를 복원했다. 요청 `5b49c912-7965-430d-ae34-bde348e5a00e`가 적용 완료로 바뀌고 실제 버전이 원래 해시로 돌아왔다.

최종 검수에서 다음 두 문제를 수정했다.

- 미확인 요청 중 401·403을 받으면 원래 요청 ID를 보존하고 자동 재시도를 중지한다. 인증 회복 후 같은 키로 확인한다.
- 데스크톱의 변경 패널이 화면보다 높으면 내부 스크롤을 사용한다. 1280×633에서 적용 버튼 전체가 화면 안으로 들어오는 것을 실제 화면에서 확인했다. 별도 레이아웃 검사에서도 1280×1000, 800×633, 390×633의 버튼을 클릭했다.

검수 중 브라우저 JavaScript 오류는 없었다. 로컬 화면 자료는 웹 `outputs/balance-qa/`에 보관하며 인증 상태·토큰 자료를 공개하거나 커밋하지 않는다.

## 실제 Minecraft와 AI API

Copper Golem Fabric 1.21.8 클라이언트로 로컬 NORMAL 경기의 돼지 타워를 확인했다. API 적용 전후 서버 엔티티를 읽어 다음 값을 대조했다.

| 항목 | 복원 전 | 복원 후 |
|---|---:|---:|
| 기본 공격력 | 6 | 5 |
| 현재 체력 / 최대 체력 | 80 / 80 | 80 / 80 |
| 엔티티 UUID | 같은 타워 | 유지 |

클라이언트 화면에서 타워가 남아 있는 것을 확인했다. 이 화면 검수로 타격별 피해량까지 눈으로 대조한 것은 아니다. 전투·상태 경로는 GameTest 결과로 구분한다.

이전 실행에서 적용한 공격력 6과 요청 이력이 서버 재시작 후 유지됐고, 다시 5로 복원했다. 마지막 상태의 대기 요청과 쓰기 차단은 모두 없었으며, 활성 버전은 최초 값 `51f427d0b3826731265944ad022f847ee3dd78718240ffd53328f690818b2294`였다.

AI 경로는 웹에서 테스트 서버·타워 영역만 허용하는 5분 토큰을 발급해 실제 게임 API까지 실행했다. 같은 요청을 두 번 보내도 원래 요청 ID를 반환했다.

| 요청 | 결과 | 요청 ID |
|---|---|---|
| 공격력 5 → 6, 즉시 | 적용 완료 | `ea0ec7b0-7be2-4a81-be77-3f3cfd588e2a` |
| 공격력 6 → 5, 즉시 | 적용 완료 | `74fd0478-f1a2-42fb-ab9c-b68c0bd8a94a` |
| 공격력 5 → 6, 다음 경기 | 예약 후 취소 | `d4f6cd68-810f-4b83-a5b1-3aad6a96956a` |

발급한 QA 토큰은 검수 직후 폐기했으며, 같은 토큰의 다음 조회가 401로 거절되는 것을 확인했다. 운영 토큰은 발급하지 않았다.

## 일괄 변경 측정

로컬 20 TPS 서버에서 동물 타워 16종의 공격력을 10% 올리고 한 묶음으로 복원했다. 실제 클라이언트 1개와 QA 가상 플레이어 3개를 사용했으며, 배치된 타워 수가 적은 시험이다.

| 측정 | 증가 | 복원 |
|---|---:|---:|
| 게임 API 검사 응답 | 35ms | 33ms |
| 요청부터 적용 완료 조회까지 | 160ms | 160ms |

`tick query`의 100틱 표본은 변경 전 평균 2.5ms·P99 3.8ms, 변경 후 평균 2.1ms·P99 3.4ms였다. 표본 구간의 평균이며 패치 틱 하나의 최대 정지 시간이나 운영 부하를 증명하지 않는다. 웹 AI API의 단일 변경·복원은 1 TPS로 늦춘 검수 환경에서 각각 695ms·955ms였으므로 운영 지연 목표로 사용하지 않는다. 30명 접속 시험은 요청대로 제외했다.

## 배포 전 남은 확인

1. 실제 GitHub OAuth 앱과 운영자 계정으로 로그인·거절·2단계 인증 조회를 확인한다.
2. 웹 컨테이너에서 게임 루프백 API로 연결할 비공개 경로, HTTPS와 접근 제한을 준비한다.
3. 운영 DB 마이그레이션, 기존 설정의 첫 버전 등록과 전체 저장소 백업을 별도 승인 후 진행한다.
4. 공개 카탈로그 동기화를 켠 환경에서 반영 지연과 실패 복구를 확인한다. 이번 실제 게임 QA는 공개 연동을 꺼 두어 상태가 `DISABLED`였다.
5. `npm audit --omit=dev`의 의존성 경고 5건(critical 1, high 3, moderate 1)을 검토하고 업데이트·회귀 검사한다. 기존 Next.js 16.2.12를 이번 기능 작업에서 올리지는 않았다. 경고 자체가 현재 배포의 악용 가능성을 입증하지는 않지만 운영 공개 전에 해결 여부를 판단해야 한다.

검수용 게임·클라이언트·웹 프로세스와 가상 플레이어는 종료했다. 격리 DB 컨테이너도 종료했으며 임시 DB는 자동 삭제됐다. 원본 QA 로그와 인증 상태는 로컬 생성물로 남기며 운영 자료와 섞지 않는다.
