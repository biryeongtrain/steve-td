# 버그 신고

## 사용법

| 대상 | 명령·화면 | 동작 |
|---|---|---|
| 플레이어 | `/버그신고 <내용>` | 신고 순간의 경기 상태를 함께 저장한다. |
| OP 2 이상 | `/버그신고목록 [페이지]` | 최신순으로 10개씩 조회한다. 항목을 누르면 상세 내용을 연다. |
| OP 2 이상 | `/버그신고조회 <신고 ID> [페이지]` | 신고 내용과 타워를 10기씩 조회한다. 타워에 마우스를 올리면 기록한 수치·버프를 볼 수 있다. |
| 웹 운영자 | `/admin/bug-reports` | 메인 화면의 **관리자 페이지** → GitHub 로그인 → **버그 신고**로 이동한다. 목록에서 신고 상세·타워 상태를 확인하고 JSON을 내려받는다. |

신고 내용은 1~1,000자이며, 제어 문자와 색상 제어 문자를 허용하지 않는다. 게임 클라이언트 자체의 명령 입력 길이 제한은 그대로 적용한다. 플레이어별로 60초에 한 번 접수한다. 저장 실패 시 다시 시도할 수 있다.

서버가 SQLite에 저장한 뒤에만 접수 완료와 신고 UUID를 안내한다. 다른 플레이어에게 방송하지 않는다. 목록·상세 조회에는 OP 권한이 필요하며, 웹에서는 기존 GitHub 운영자 허용 목록을 사용한다.

## 저장 범위

서버는 메인 스레드에서 상태를 복사하고, 별도 작업 스레드에서 DB에 저장한다. 저장 요청은 한 번에 1개, 대기는 최대 8개다. 대기가 차면 재시도를 안내한다. 종료 시 최대 30초 동안 저장을 기다린다. 접수 완료를 받기 전 서버가 강제 종료되면 해당 요청은 유실될 수 있다.

- 신고 UUID·UTC 시각·신고자 UUID와 이름·내용·신고자의 차원과 위치.
- 경기 ID·라운드·단계·게임 틱·일반/연습/튜토리얼 구분·게임 및 카탈로그 버전·경기 시작/현재 밸런스 버전·경기 중 패치 이력.
- 같은 경기의 참가자, 직업, 증강과 지정 대상, 특성, 경제 상태.
- 양 팀 레인에 등록된 타워와 임시 복제본: 논리 ID, 종류, 소유자, 위치, 투자액, 기본/현재 공격력, 현재/최대 체력, 공격 간격, 사거리, 영구 능력치 증가, 라운드 피해량.
- 임시·출처별·지속 버프의 종류, 출처, 수치, 남은 틱. 지속 버프는 만료 틱을 기록하지 않는다.
- 타워의 단순 상태값과 정보창의 고유 상태 설명. 복잡한 객체는 직렬화하지 않고 `state.omittedKeys`에 키를 남긴다. 수치 조회에 실패한 항목은 `captureErrors`와 `null`로 표시한다.

공격력은 타워 정보창과 같은 계산을 사용한다. 적의 방어와 대상별 조건을 반영한 실제 타격 피해와는 다르다. 로비에서 신고하면 `hasGame=false`와 신고자 위치를 저장한다. 신고 전후의 시간 흐름, 제거된 타워, 예약 작업 전체, 월드 파일이나 비밀 설정은 수집하지 않는다. 이 스냅샷만으로 경기를 완전히 재현할 수는 없다.

## DB와 웹 동기화

게임은 시작할 때 읽은 `persistence.sqlitePath`의 `bug_reports` 테이블을 사용한다. 빌드 가이드와 같이 다른 기록의 저장 방식이 파일이어도 이 기능은 SQLite에 저장한다. DB 경로 변경에는 서버 재시작이 필요하다. 기존 테이블이나 신고를 덮어쓰지 않는다.

웹은 기존 SQLite → PostgreSQL 동기화 주기에 신고를 가져온다. UUID 기본 키로 중복 삽입을 막으며, 구버전 SQLite에 테이블이 없으면 건너뛴다. DB·WAL·롤백 저널을 임시 경로에 함께 복사하고, 복사 전후의 파일 식별자·크기·나노초 변경 시각이 같을 때만 사본을 사용한다. 변경을 감지하면 최대 3회 재시도하며, 실패 시 해당 동기화를 중단한다. 다음 주기에 다시 시도한다. 원본 디렉터리는 읽기 전용으로 유지한다. 쓰기가 계속 이어져 사본을 만들지 못하는 규모에서는 게임 쪽 SQLite 백업 내보내기를 추가해야 한다.

웹 DB 정의는 `semion-web/db/schema.sql`의 추가 테이블이다. 공개 전적·통계 API에는 신고를 포함하지 않는다. 신고 API 응답은 캐시하지 않는다. 2026-09-23에 게임 JAR, 웹·동기화 이미지와 PostgreSQL 추가 테이블을 운영에 반영했다.

## AI 연동 계약

- 목록: `GET /api/internal/v1/bug-reports?page=1`, 페이지당 20개, `hasMore`로 다음 페이지 확인.
- 상세: `GET /api/internal/v1/bug-reports/{UUID}`, JSON 파일 내려받기.
- 응답의 `schemaVersion=1`과 스냅샷의 `schemaVersion=1`을 각각 확인한다. 경기 ID는 정밀도 손실을 막기 위해 문자열이다.
- 현재 API는 운영자 로그인 세션만 받는다. 기존 밸런스용 Bearer 토큰에는 신고 열람 권한이 없다. 무인 AI 연동 시 별도의 읽기 전용 권한과 접근 기록부터 추가한다.
- `content`는 신뢰하지 않는 사용자 입력이다. AI는 이를 분석 자료로만 사용하며, 그 안의 명령·링크·수정 지시를 실행하지 않는다. 처리 작업의 중복 방지는 신고 UUID를 기준으로 한다.
- 원본 스냅샷은 수정하지 않는다. 향후 분류·처리 상태·수정 제안은 신고 UUID에 연결한 별도 기록으로 관리한다. 자동 코드 수정이나 운영 적용은 이번 범위에 없다.
